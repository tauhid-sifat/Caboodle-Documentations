## Description

In Data Upload Reporting → SPINS → **Item Ranking Report**, when using the **Monthly Report** filter panel, applying/interacting with the **Date filter** fails. The underlying API call to `/spins/items-ranking-filter-data` returns a **400 Bad Request** error, blocking users from generating or viewing the report.

**Problem**

* The Date filter action triggers a request to `/spins/items-ranking-filter-data` that fails with a 400 status, indicating the request payload/params sent by the frontend are invalid, malformed, or missing required fields expected by the backend.
* This is a hard failure (not a UX/cosmetic issue) — users are fully blocked from using the Date filter in this flow.

**Impact**

* Users cannot filter the Item Ranking Report by date in the Monthly Report context, making the report unusable for date-based analysis.
* Complete blocker for this specific workflow (SPINS → Item Ranking Report → Monthly Report → Date filter).

**Steps to Reproduce**

1. Navigate to **Data Upload Reporting**.
2. Go to **SPINS**.
3. Select **Item Ranking Report**.
4. Open/apply the **Monthly Report** filter panel.
5. Interact with the **Date filter**.
6. Observe API call to `/spins/items-ranking-filter-data` returns **400 error**.
7. Check browser console/network tab — filter fails to load or apply as a result.

**Expected Behavior**

* Selecting/applying the Date filter should return a successful (200) response with valid filter data, allowing the report to update accordingly.

**Actual Behavior**

* API call to `/spins/items-ranking-filter-data` fails with a 400 error, and the Date filter does not function.
