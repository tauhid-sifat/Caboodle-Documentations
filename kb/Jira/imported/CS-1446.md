## Description

Improve the filtering experience by maintaining independent filters for the List and Calendar views and ensuring filter options always reflect the current data visible to the user.

#### Acceptance Criteria

1. **Separate Filters*** The List view and Calendar view must maintain separate filter states.
* Applying or changing filters in one view must not affect the filters in the other view.
2. **Filter Values*** Filter options should display only the values that exist in the current user's visible log set.
* Users should not see filter values that have no associated logs they can access.
3. **Empty State*** If a selected filter returns zero matching logs, display an appropriate empty state (e.g., "No logs found") instead of an error message.
4. **Consistent Behavior*** Filter functionality and behavior must be identical for both **Broker** and **Brand** users.
5. **Real-Time Filter Updates*** If a user deletes a log from either the List view or Calendar view, the filter options should update immediately to reflect the remaining available data.
* Any filter value that no longer has associated logs should be removed from the filter options without requiring a page refresh.
