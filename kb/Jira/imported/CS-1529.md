## Description

During **Product Upload via CSV**, the **UPC** field currently accepts/processes values in **scientific notation** format (e.g., `6.28177E+11`) instead of the correct full numeric UPC value. This typically happens when Excel auto-formats long numeric strings as scientific notation when the CSV is opened/edited/saved, and the system does not validate or reject this incorrect format before processing.

**Impact**

* Products may be uploaded with incorrect/corrupted UPC values, breaking downstream matching, lookups, or integrations that rely on exact UPC values.
* Users may not notice the issue until much later (e.g., failed product matching, incorrect reporting), since the upload itself doesn't fail or warn them.
* Common and easy-to-hit user error (simply opening/saving a CSV in Excel can trigger this), so likely to recur frequently without validation.

**Steps to Reproduce**

1. Prepare a CSV file for Product Upload with a UPC column.
2. Open the CSV file in Excel.
3. Enter a long numeric UPC value (e.g., `628177000000`) in a cell that is **not** pre-formatted as Text.
4. Save the file — Excel auto-converts the value to scientific notation (e.g., `6.28177E+11`).
5. Upload this CSV file via **Product Upload**.
6. Observe that the system accepts/processes the row without flagging the UPC as invalid.
7. Check the uploaded product record — the UPC field shows the incorrect scientific notation value (or a corrupted/rounded number) instead of the correct full UPC.

**Expected Behavior**

* The system should detect scientific notation format in the UPC field during CSV upload and reject/flag it as invalid, rather than silently accepting it.

**Actual Behavior**

* Scientific notation UPC values are accepted and processed without validation, resulting in incorrect/corrupted UPC data.
