## Description

In **Admin – Data Mapping – Mapped Data**, the filters need to be updated so that they **correctly correspond to the actual column names** in the table, and the filters should be made **dynamic** (consistent with the dynamic filter behavior requested app-wide in earlier tickets).

**Current Behavior:**

* Filters in Mapped Data do not align properly with the table's column names
* Filters are **static**  = selecting one filter does not dynamically update the available options in other related filters, nor are options limited to values actually present in the table.

**Expected Behavior:**

1. **Filter–Column Alignment:*** Each filter should clearly and accurately correspond to its respective **column name** in the Mapped Data table.
* Filter labels should match (or clearly map to) the actual column headers to avoid confusion.
2. **Dynamic Filters:*** Selecting a filter option should update the available options in other dependent filters based on current data (consistent with the app-wide dynamic filter requirement).
* Other filters should be **disabled while the BE API call is in progress** to fetch updated options, then re-enabled once loaded — per the earlier raised ticket on dynamic filter loading states.
* Filter option lists should only show values **actually present** in the Mapped Data table — no stale/unused options (per the earlier raised ticket on this pattern, applied here too).
