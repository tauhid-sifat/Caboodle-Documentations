## Description

For the same Brand/Category Review, once a notification mail has already been sent to a user, sending mail again should not resend the same notification to that user a second time. However, currently the user is receiving the mail again. This appears to be because the system is calling the **Re-Notify** API instead of the correct **Notify** API in this flow.

**Steps to Reproduce:**

1. Go to Category Review section.
2. Select a Brand/Category and send mail to a user.
3. User receives the notification mail (1st time — expected).
4. Trigger the send mail action again for the **same** Brand/Category Review, targeting the same user.
5. Observe that the user receives the mail a **2nd time**, which should not happen.

**Expected Behavior:**
Once a mail has been sent to a user for a specific Brand/Category Review, sending mail again for that same review should **not** re-send the notification to that same user (since they've already been notified). The correct **Notify API** should be called here — not the Re-Notify API — to respect this "already notified" state.

**Actual Behavior:**
User receives the mail again for the same Brand/Category Review, indicating the Re-Notify API is being incorrectly invoked instead of Notify.
