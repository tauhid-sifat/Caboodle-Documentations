## Description

**Description:**
When any data within a promotion version is updated in the Sandbox, the **"Push to Approved"** button correctly becomes active/enabled, indicating there are pending changes to push. However, the **"Set as reporting"** button for that same version remains disabled and does not reflect the updated state.

**Steps to Reproduce:**

1. Navigate to Promotional Planning → Trade Spend Sandbox.
2. Open a promo and make any update to the promotion (e.g., edit an event, fee, or date) under a specific version.
3. Open the "Versions" panel.
4. Observe that "Push to Approved" is now active for that version.
5. Check the "Set as reporting" button for the same version.

**Expected Result:**
When a version has updated/unsaved changes, both "Push to Approved" and "Set as reporting" should reflect the current state consistently — if "Push to Approved" becomes active because of the changes, "Set as reporting" should also be enabled (assuming it isn't already the reporting version) so the user can mark the updated version as reporting without needing to push first.

**Actual Result:**
"Push to Approved" becomes active after an update, but "Set as reporting" stays disabled for that version, preventing the user from setting the updated version as reporting.
