## Description

When a bulk upload has failed or skipped rows, the backend (BE) already returns an S3 link pointing to an error file. Currently the frontend (FE) does not consume or display this link anywhere, so users have no visibility into which rows failed or why.

**Current Behavior**

* BE returns an S3 link containing the error details in the upload API response.
* FE ignores this field entirely.
* User sees only a generic success message, even when rows failed silently.

**Required Behavior**

* FE must read the S3 link from the upload response payload.
* FE must surface this to the user, e.g.:* A visible message such as "Some rows failed to upload — [Download error report]"
  * A clickable/downloadable link that opens or downloads the S3 file
* This should trigger whenever the response indicates partial or full failure (not just on total success).
