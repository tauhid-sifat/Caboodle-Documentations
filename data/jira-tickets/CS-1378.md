## Description

Currently, a single brand can have only one owner user.

During the *Invite User* flow, brands are shown as disabled only when an invited user has already accepted the invitation and become associated with the brand.

Because of this behavior, multiple pending invitations can be sent for the same brand if the first invited user has not yet accepted the invitation.

As a result:

* Admin can invite multiple users for the same brand owner role
* The first user who accepts the invitation gets registered successfully
* Subsequent users encounter an error during registration/signup because the brand already has an owner

This creates a confusing and inconsistent user experience.

h3. Possible Solutions

h4. Option 1 (Recommended)

When an invitation is created for a brand owner:

* Mark the selected brand as *reserved*
* Disable that brand for future owner invitations until:
** the invitation expires
** invitation is cancelled
** invitation is rejected
** or the invited user completes registration

This prevents duplicate pending invitations at the source.

h4. Option 2

Allow multiple invitations but validate during resend/signup flow:

* Before registration completion, check whether the brand already has:
** an active owner
** or another accepted invitation
* Show a proper message such as:

{quote}“This brand already has an assigned owner. Your invitation is no longer valid.”{quote}

This improves UX but still allows conflicting pending invites.
