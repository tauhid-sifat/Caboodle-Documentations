## Description

Two related issues in the file upload error-handling flow:

1. **Wrong modal on failure:** When a file upload fails, the **Success** modal is still shown to the user (along with the error file), instead of a Failure/Error modal. This misleads the user into thinking the upload succeeded when it didn't.
2. **Wrong modal triggered on error file download:** From the error/error-file modal, when the user clicks to download the error file, instead of simply downloading the file, the modal switches to the **File Upload** modal — an unexpected navigation change.

**Steps to Reproduce (Issue 1):**

1. Upload a file that will fail/error
2. Observe the modal shown — it displays as "Success" even though the upload failed, with an error file attached

**Steps to Reproduce (Issue 2):**

1. Trigger a failed upload with an error file available
2. From the error modal, click to download the error file
3. Observe: instead of downloading, the modal changes to the File Upload modal

**Expected Behavior:**

1. Failed uploads should show a Failure/Error modal (not Success), clearly indicating the upload did not complete, with the error file available for download.
2. Clicking "download error file" should simply download the file and keep the user on the same modal/screen — it should not navigate to or open the File Upload modal.

**Actual Behavior:**

1. Success modal displays even on failure.
2. Download action incorrectly triggers a modal switch instead of a file download.
