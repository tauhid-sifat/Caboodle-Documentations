## Description

Introduce the Organization itself and everything needed to run one: creating it, giving it brands, setting approved email domains, and inviting people into it.

The Primary Owner sets an Organization up and decides which brands it can work on. The customer's Admin then builds out their own team by inviting colleagues, without coming to us for every new starter — the main thing this ticket unlocks.

Approved email domains stop an Organization inviting people who don't work there; invitations to any other address are refused.

This ticket also settles who counts as your colleague — one shared definition, used everywhere, which is what makes tickets 2–10 small, safe switches that can be done in any order rather than a rewrite.

Every existing brokerage customer is placed into an Organization automatically. At this stage the product still behaves exactly as today — this builds the structure but nothing switches over to using it yet.

*Release note:* Existing Brokers are not promoted to Admin. They keep the Broker role, and lose invite/grant-access ability as soon as this ships. Schedule the Admin-appointment pass alongside the release, not after.

*Acceptance Criteria:*

_Setting up an Organization_

* Primary Owner can create an Organization with a name, ≥1 approved email domain, and optionally a set of brands.
* Cannot create an Organization without at least one approved email domain.
* Primary Owner can add/remove brands on an Organization at any time.
* Admin can see which brands their Organization holds, but cannot change the list.
* Brokers and Broker Sub Users never see the Organization's brand list — only brands given to them personally.
* Primary Owner can add/remove approved email domains.
* Removing a brand from an Organization immediately removes it from everyone in it. Existing work on that brand is kept, not deleted — re-adding the brand restores the previous position.

_Inviting people_

* Primary Owner and Admins can invite people as Admin, Broker, or Broker Sub User.
* Brokers and Broker Sub Users cannot invite anyone.
* An invite to an address outside approved domains is refused with a clear message.
* An invite can include the brands the new person should get — only brands the Organization holds are selectable.
* On accepting, the person joins with the brands chosen at invite time.
* An invitation is tied to the address it was sent to.

_Managing members_

* Primary Owner and Admins can give/take brands from any member of their Organization.
* Brokers and Broker Sub Users cannot give brands to anyone, including themselves.
* Primary Owner and Admins can remove a member — loses all brand access, can no longer sign in.
* An Organization can be deleted only once it has no members; otherwise shows which members remain.
* An Organization is allowed to have no Admin — it keeps working, managed by the Primary Owner.

_One consistent definition of "my Organization"_

* One definition of Organization membership, used product-wide.
* No visible change for any user — screens show exactly what they showed before.
* Users who previously hit errors on file screens no longer do.
* Definition returns the same answer as current arrangement — verified against real data before release.

_Existing customers_

* Every existing brokerage user is placed into an Organization automatically.
* Existing teams stay together.
* Anyone unmatched to a team gets their own single-person Organization; no manual follow-up needed.
* Approved email domains for existing Organizations are set up automatically from members' current addresses.
* Existing Brokers keep the Broker role — nobody promoted automatically.
* No existing user loses access to any brand or data as a result of this ticket.
