#### Acceptance Criteria

Scenario 1: Failed record reason is specific and actionable
Given I upload a CSV to Monthly Report Import Actuals
When a record fails validation
Then the error reason clearly identifies:

* Which column/field caused the failure (e.g., "UPC", "Sales $", "Date")
* What value was rejected
* Why it was rejected (e.g., "UPC 012345678905 not found in system", "Sales value exceeds allowed range", "Date format must be MM/DD/YYYY")
  And no error says "Error processing row" or similarly generic messages

Scenario 2: Row number from source file is included
Given I view the failed records list after an import
Then each failed record shows the original CSV row number
So I can locate and correct the error in my source file

Scenario 3: Multiple failures per row are reported
Given a single row has multiple validation errors
Then all errors for that row are listed, not just the first one found

Scenario 4: Successful records are clearly marked
Given I import a file with mixed success and failure
Then successfully imported records show "Imported" or "Success" status
And they are excluded from the failed records section
