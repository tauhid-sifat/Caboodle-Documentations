## Description

## Summary

When a user deletes the report or version that is currently open on screen, they are **not redirected** to another existing version afterwards. The user stays on the deleted item's view.

## Environment

Staging · Versioning (report versions)

## Steps to reproduce

1. Open a report that has **two or more** versions.
2. Select a version so it is open on screen.
3. Delete that version.

## Actual result

* The version is deleted, but the screen does not switch to another existing version.
* The user stays on the deleted version's view, which may be stale, empty or broken.

## Expected result

* After deleting, the user is automatically redirected to another existing version. Suggested order:1. the version set as **reporting**, if there is one;
  2. otherwise the latest remaining version;
  3. otherwise the previous version in the list.
* The version list/selector updates and no longer shows the deleted version.
* A success message confirms the deletion.
* If it was the **last** version, the user is taken to the report's default or empty state, or back to the list, with no errors.

## Also check

* Deleting a version that is **not** the one on screen: the current view is unchanged and the list updates.
* Deleting the version set as reporting: confirm which version becomes reporting, if any.
* Browser back button and page refresh after deleting: no error, and the deleted version is not reachable.
