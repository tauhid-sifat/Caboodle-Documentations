## Description

Two related filter behavior requirements across the platform:

1. **Dynamic filter options based on existing data:** Filter dropdowns should only show options that actually exist in the current dataset/list — not static/all possible values. If an option has no corresponding entries in the list, it shouldn't appear in the filter.
2. **Cascading/dependent filters:** When multiple filters exist together (e.g., Filter A, B, C), selecting a value in one filter should narrow down the available options in the next filter(s), based on what actually exists for that combination.

**Example (as described):**

* Filter A, B, C exist together
* User selects **Option 1** in Filter A → Filter B should only show options that exist **for Option 1** (not all B options)
* User then selects **Option 3** in Filter B → Filter C should only show options that exist for the combination **Filter A = Option 1 AND Filter B = Option 3**

**Steps to Reproduce:**

1. Go to any module with multiple filters (e.g., Distributor APL: Region, Brand, etc.)
2. Select a value in the first filter
3. Check the second filter's available options — currently shows all possible options, not just those relevant to the first filter's selection
4. Select a value in the second filter
5. Check the third filter — same issue, not narrowed based on prior selections

**Expected Behavior:**

* Each filter should only display options that exist within the current filtered dataset.
* Selecting a value in one filter should dynamically update the available options in subsequent filters to reflect only valid combinations.

**Actual Behavior:** Filters are static/independent — all options show regardless of what's actually in the data or what's already selected in other filters.

**Impact:** Users can select filter combinations that return zero results, or see irrelevant options that don't apply — confusing and inefficient, especially as data grows across brokers, brands, and regions.
