## Description

## Description:

We need to implement the backend propagation and visibility logic for the **Category Review List** based on who performs the upload or addition. The goal is to ensure proper data distribution from Brokers down to Brands, while keeping Brand-specific uploads isolated—unless they are explicitly committed to a shared calendar.

### Core User Stories:

1. **As a Broker**, when I upload/add a Category Review list, I want it to automatically propagate to all Brand environments associated with my account, saving me from manual duplication.
2. **As a Brand**, when I upload/add a Category Review list, I want it to remain private to my environment so it does not clutter the Broker's dashboard or other brands' views.
3. **As a Brand**, when I assign an item from my review list to my **Category Review Calendar**, I want that specific calendar event to push up to the **Broker Master Category Review Calendar** (once created).

## Technical Functional Requirements

### 1. Broker-Level Uploads (Top-Down Propagation)

* **Trigger:** A user with a `Broker` role uploads or adds a Category Review list.
* **Behavior:** The system must identify all `Brand` IDs/environments associated with that Broker's account and instantly propagate/copy the list to those environments.
* **Visibility:** Visible in the Broker Dashboard and all associated Brand Dashboards.

### 2. Brand-Level Uploads (Isolated Environment)

* **Trigger:** A user with a `Brand` role uploads or adds a Category Review list.
* **Behavior:** The data must remain strictly within that specific Brand's database schema/environment.
* **Visibility:** Visible **only** to that Brand. It must **not** propagate to the Broker Dashboard or any sister brands.

### 3. Brand Calendar Event Promotion (Bottom-Up Exception)

* **Trigger:** A Brand user takes an item from their local category review list and adds it to their local **Category Review Calendar**.
* **Behavior:*** The list item itself remains isolated to the brand.
  * *However*, the calendar assignment must trigger an event pipeline to propagate this specific date/category combo up to the upcoming **Broker Master Category Review Calendar** feature space.
  * *Dev Note:* Ensure the data structure for local brand calendars is ready to feed a master broker view once the master calendar UI is officially built.

## Acceptance Criteria

```
Scenario: A Broker uploads a category list
  Given a Broker is logged into the Broker Dashboard
  When the Broker uploads a new Category Review list
  Then the list should be visible to the Broker
  And the list must be immediately propagated and visible in all associated Brand environments

Scenario: A Brand uploads a category list
  Given a Brand user is logged into their dashboard
  When the Brand user uploads a new Category Review list
  Then the list should only be visible within that specific Brand's environment
  And the list must NOT be visible on the Broker Dashboard or any other Brand Dashboards

Scenario: A Brand adds a list item to their Calendar
  Given a Brand has a localized Category Review list
  When the Brand maps a list item to their Category Review Calendar
  Then that calendar entry must be flagged/staged to sync with the Broker Master Category Review Calendar pipeline

```

## UX/UI Notes:

* **Broker view:** Needs a visual indicator or column showing that an item was "Propagated to All Brands."
* **Brand view:** Should clearly differentiate between list items that were pushed down by their Broker (read-only or editable depending on current permissions) vs. items they added locally themselves.
