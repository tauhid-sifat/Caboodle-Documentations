## Description

## Summary

The Simple Promotion details API returns `"perUnitPrice": null` for products that **do have a per-unit price** in the price list. Because every costed field is derived from `perUnitPrice`, the whole CALCULATED section is empty. The header shows "Not costed: 3 events — product has no price", and the footnotes tell the user to "Add a price", even though a price already exists.

## Environment

Staging, brand **Apple Jacks**
Promotion: **"EDLP = Y two months"** (id `197b50de-0e6d-4652-b258-77e3a9…`), Plan year 2026
Endpoint: `POST tradespends/simple/{id}` (details)

## Steps to reproduce

1. Make sure the product **All Natural Food Dye - 12 Pack Case (12X5X8 OZ)** has a per-unit price in the Price List for distributor **KeHE DELIVERED**.
2. Create a Simple Promotion with events on that product (ABSCO / ABSCO National), with OI%, Scan, TPR $ and Ad/TPR filled in.
3. Open the promotion details.

## Actual result

Event response (example):

```json
"distributorName": "KeHE DELIVERED",
"casePack": 12,
"perUnitPrice": null,
"distributorMarkup": 5,
"promotedCaseAllowanceOI": 6,
"promotedUnitScanAllowance": 0.07,
"unitSRP": 7.9,
"lumpSumProposed": 500,
"caseCost": null,
"caseCostMarkup": null,
"totalCaseAllowance": null,
"retailerNetCase": null,
"netUnitRetailerCost": null,
"retailerProfit": null
```

* Case cost, + Markup, Allowance, Net case, Net unit and Profit are all blank for all 3 events.
* "Not costed" = **3**, even though the product is priced.

## Expected result

* `perUnitPrice` resolves from the price list for the product, distributor and banner.
* With the values above, the full costed chain is calculated as in QA guide §5.1: case cost = case pack × per-unit price → markup → allowance → net case → net unit → profit.
* "Not costed" counts only products that genuinely have no price.

## Notes for dev

* `casePack` (12) and `distributorMarkup` (5) resolve correctly. Only the price lookup fails.
* Possible cause: the price lookup filters on **Valid From / effective date** against the event dates. For example, a price valid from 2026-09-02 would not match a Jan–Feb 2026 event. It could also be matching on the wrong distributor or banner key. Please check the detail query's price join. The QA guide §14 notes these joins have not been run against a real DB before.
* Rows 2 and 3 show UPC `6.28177E+11`. Please make sure the product lookup is not relying on the UPC string. See CS-1743.
* Related: CS-1742 (unpriced product blocks submission) and CS-1745 (Add Price modal fails).
