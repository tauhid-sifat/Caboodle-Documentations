## Description

h2. Hi Keya, Can you please test this? 

h2. Context

When a user adds multiple SKUs to existing promotions using the "Add a SKU" option and applies them to all existing promotions, promo cases and promo revenue data is not appearing for the first few promotions of affected items. This appears to be a data calculation or aggregation issue that occurs during the SKU addition process.

This was noted in Brand>Zucchini Beanie Demo Brand>Promotion >*WHOLE FOODS NATIONAL 2026*

h2. Problem / Goal

h3. Steps to Reproduce

# In the Promotional Planning module, select an existing promotion with multiple items
# Click "Add a SKU" option
# Select approximately 10 items to add to the promotions
# Apply the selected items to every existing promotion
# Review the promotion data for the newly added items
# Observe: Promo cases and promo revenue are missing for early promotions

h3. Impact

*Blueberry Lavender item:*

* No promoted cases showing for the first 2 promotions
* No promoted revenue showing for the first 2 promotions
* Subsequent 3 promotions likely showing data correctly

*Chocolate Chip item:*

* No promoted cases showing for the first promotion
* No promoted revenue showing for the first promotion
* Subsequent promotions likely showing data correctly

This causes incomplete promotional reporting and inaccurate trade spend analysis for newly added SKUs.

h2. Implementation Notes

* Verify data calculation when bulk-adding SKUs to existing promotions
* Check if promo cases/revenue calculation is skipping the first promotion(s) for newly added SKUs
* Likely issue: Indexing error or off-by-one logic when iterating through promotions
* Test with various item counts (5, 10, 15+) to identify pattern
* Confirm data is correct when adding single SKU vs. bulk adding multiple SKUs
* Check if issue occurs for all items added or only affects certain items
* Review timestamp/date logic — may be related to promotion start date handling
