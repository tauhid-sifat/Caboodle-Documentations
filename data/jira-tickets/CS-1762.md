## Description

## Summary

Update the **Trade Spend Roll Up** report so every promo row shows the **original (family) name in bold**, with the **version label beside it**, using the same pattern as CS-1729 (e.g. **Test Promo** v2 · Summer Plan). This applies to both the **Brand Approved** and **Sandbox** sections.

## Current behaviour

* **Brand Approved section:** always shows the original promo name, even when a later version was pushed. The figures are correct, but the name does not show which version they belong to.
* **Sandbox section:** shows only the version name, not the original name.

## Required FE change

* Use the new fields from the BE sub-task (CS-1758): `originalName`, `versionName` and `versionNumber`.
* Display format in both sections:* **Bold:** `originalName`
  * **Beside it, not bold:** `v{versionNumber} · {versionName}`
* Match the style used on the Sandbox and Brand Approved promo headers (CS-1729).

## Acceptance criteria

* **Brand Approved:** shows the original name in bold and the **pushed** version's label beside it.
* **Sandbox:** shows the original name in bold and the reporting version's label beside it.
* The format is identical in both sections and matches CS-1729.
* After a version is renamed or a different version is pushed, the report shows the updated label once it refreshes.
* Promos with a single version show `v1 · <name>`. Confirm with the PO whether the label should be hidden when there is only one version.
* Long names wrap or are truncated with a tooltip, and the table layout does not break.
* Roll Up **export** (if FE-generated) uses the same name and version format.
* No regression in sorting, search or filters that use the promo name.

## Dependency

Blocked by **CS-1758** (BE fields).
