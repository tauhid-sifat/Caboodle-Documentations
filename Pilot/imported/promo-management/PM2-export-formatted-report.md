# Promotional Management | Export to Formatted Report

**CS-1614** | New Requirement | User Story | Priority: High | Status: New

---

## User Story

**As a** Broker user,  
**I want** to export promotional management data as a formatted report,  
**So that** I can share it with stakeholders without manually formatting the raw export.

---

## Description

Current export endpoints (`GET Brokers/export-events`, `GET Brokers/export-promotional-management-events`) output raw CSV only. Users then spend time formatting columns, adding headers, and styling before sharing with brands or retailers. The existing export also has known bugs (CS-1367: export data doesn't match filters — resolution blocks this story).

This story adds a "Formatted Report" export option that outputs a presentation-ready document with proper column widths, headers, date formatting, and branding.

---

## Acceptance Criteria

### Scenario 1: Formatted Report Option
- **Given** I am on the Promotional Management page
- **When** I open the export menu
- **Then** I see "Export as Formatted Report" as an additional option
- **And** the existing raw CSV export options remain available

### Scenario 2: Report Contents
- **Given** I choose formatted export
- **Then** the report includes:
  - Report title, date range, broker name, brand name header
  - Events grouped by **retailer** (primary grouping) then by **month** (sub-grouping)
  - Columns: Month, Retailer, Banner, Distributor, Product, Status, Dates
  - Bold column headers, proper alignment, borders
  - Subtotal rows per retailer (event count) and a grand total row
  - Timestamp and "Generated by Caboodle" footer

### Scenario 3: Empty Data
- **Given** there are no promotional events matching the current filters
- **When** I choose formatted export
- **Then** a clear message is shown: "No events to export"
- **And** no file is generated

### Scenario 4: Large Dataset (>500 events)
- **Given** the filtered dataset exceeds 500 events
- **When** I choose formatted export
- **Then** a loading indicator is shown during generation
- **And** the export is processed asynchronously (Hangfire job) with status polling
- **And** auto-fit column widths are skipped in favor of fixed preset widths

### Scenario 5: Generation Failure
- **Given** the export generation fails (timeout, server error, data integrity issue)
- **When** the process completes
- **Then** I see a descriptive error message: "Report generation failed. Please try again or contact support."
- **And** the system logs the failure with timestamp, user ID, and filter context

### Scenario 6: File Format
- **Given** the export is complete
- **Then** the file is downloaded with format determined by user selection:
  - **Option A (.xlsx):** Styled Excel with bold headers, background color, borders, alternating row colors, summary/title row
  - **Option C (.pdf):** Print-ready PDF with pagination, header/footer on each page (if implemented)

---

## Design Notes

### Recommended Approach: Option A (Server-side .xlsx)
Use EPPlus or ClosedXML on the backend for styled Excel generation. Keeps formatting logic centralized and avoids client-side memory overhead for large datasets.

### Integration with Existing Endpoints
Add a new endpoint rather than modifying the existing CSV exports:
- **New:** `GET Brokers/export-formatted-report?format=xlsx&groupBy=retailer`
- Existing `export-events` and `export-promotional-management-events` remain unchanged

### Performance
- Fixed column widths for >500 rows (skip auto-fit to prevent OOM on single-instance EC2)
- Background job via Hangfire for datasets exceeding 500 events
- Memory budget: must not exceed 256MB additional allocation per export

### Dependencies
- **Blocked by:** CS-1367 (export data mismatch bug) — must be resolved first
- **Related:** Promotional Management export infrastructure

### Future Considerations
- Preview option before download (separate story)
- Broker logo/branding header on report (confirm with CW)
- PDF template engine (Option C) as a follow-up if PDF is required
