## Description

On the Brand Report grid, if a Broker sets a value in the **Next Action Due Date** column for a row, and then attempts to set or cancel a value in any of the other editable columns (Submission Status, Brand Response, Waiting On, Next Action, Review Result) for that same row, the update fails and the following error is shown:

> **Not saved**
> The request field is required. The JSON value could not be converted to System.Nullable`1[System.DateTime]. Path: $.nextActionDueDate | LineNumber: 0 | BytePositionInLine: 387. The previous value was restored. Other fields on this row were not validated.

**Steps to Reproduce:**

1. Log in as a Broker and navigate to Category Review → Brand Report.
2. On any row, set a value in the **Next Action Due Date** column.
3. On the same row, try to change or cancel a value in **Submission Status**, **Brand Response**, **Waiting On**, **Next Action**, or **Review Result**.
4. Observe the error toast.

**Expected Result:**
Setting the Next Action Due Date should not interfere with editing other columns on the same row. Each field should validate and save independently.

**Actual Result:**
Attempting to update any other column after setting Next Action Due Date throws a "Not saved" error — the `nextActionDueDate` field is being incorrectly re-sent/re-validated as part of the request for unrelated column updates, and fails JSON-to-DateTime conversion (likely because it's being sent as an empty string or invalid format instead of `null` or a valid date).

**Root Cause (suspected):**
The API request payload for updating a different column appears to be including the `nextActionDueDate` field with an value, causing deserialization to fail on the backend.
