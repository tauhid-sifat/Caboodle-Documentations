## Description

## Summary

On the Simple Promotion create grid, an event's Start and End dates must fall inside the month column it's entered in. A promotion that runs across a month boundary has to be entered as two separate events, e.g. **Jan 15 – Jan 31** in the Jan column and **Feb 1 – Feb 15** in the Feb column. This doubles the data entry and shows as two events instead of one.

## Requested change

Allow a single event to run across months. The user enters **Jan 15 – Feb 15** once, and it's saved as one event.

## Examples

| Column | Start | End | Today | Expected |
| Jan | 01/15 | 02/15 | Validation error (End Date outside Jan) | Saved as 1 event |
| Jan | 01/15 | 03/10 | Validation error | Saved as 1 event |
| Jan | 01/15 | 01/31 | Saved | Saved (no change) |
| Jan | 02/01 | 02/15 | Validation error | Validation error (Start Date must be in Jan) |
| Dec | 12/15 | 01/15 (next year) | Validation error | Validation error (dates must be within the plan year) |

## Expected behavior

* The event is entered in the column of its **start month**. Jan 15 – Feb 15 goes in the Jan column.
* The End Date can fall in any later month, as long as both dates are within the **plan year** (Jan 1 – Dec 31). An event cannot cross into the next year.
* The Start Date must still fall within the column's month.
* Start ≤ End still applies.
* **Overlap rule:** events on the same line cannot have overlapping dates.* Jan 15 – Feb 15 (Jan column) + Feb 20 – Feb 28 (Feb column), same line → **allowed**
  * Jan 15 – Feb 15 (Jan column) + Feb 10 – Feb 20 (Feb column), same line → **blocked**, with a message naming the row and months
  * EDLP (all-year) events are excluded from this check, as today.
* **Details screen:** shows the full date range. The event is counted once in the Events header card and totals.
* **Brand and Broker Promotional Calendars:** show it as one continuous event across every month it covers.
* **Month filter:** the event appears when filtering by any month it covers (e.g. both Jan and Feb).
* **Copy events to other months:** both dates shift by the same number of months and the span is kept. For example, Jan 15 – Feb 15 copied to Mar becomes Mar 15 – Apr 15. The last-day rule from CS-1760 applies to both dates. If the shifted dates would go past Dec 31 of the plan year, or would overlap another event on that line, the copy for that row is blocked with a clear message. Dates are never silently cut short.
* **Import / Export:** cross-month dates are accepted on import, using the same rules, and exported as the full range.
* **Edit (CS-1754):** the same date rules apply when editing an event's dates.

## Acceptance criteria

* A user can enter Jan 15 – Feb 15 in the Jan column and submit. 2 events are created.
* An event can span any number of months within the plan year (e.g. Jan 15 – Mar 10).
* An event that crosses into the next year is blocked with a clear message.
* A Start Date outside the column's month is still blocked with a clear message.
* A Start Date after the End Date is still blocked.
* Two events on the same line with overlapping dates are blocked, and the message names the row and months.
* Non-overlapping events on the same line are allowed, even when one of them spans into the other's month.
* The event shows once on the details screen and is counted once in the totals.
* Brand and Broker calendars show the event across every month it covers.
* Filtering by any covered month includes the event.
* Copy to other months keeps the span and follows the plan-year and overlap rules.
* Import accepts cross-month rows, and export shows the full dates.
* Single-month events and EDLP events behave exactly as before.
