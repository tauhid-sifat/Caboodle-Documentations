## Description

# Summary

When a user updates a product's **case pack** (the number of units per case) in the **Product Specifications** section, the **Distributor Sales Reports** continue showing outdated case counts. This causes confusion when reviewing sales performance and making business decisions.

## Expected Behavior

After updating a product's case pack, all historical distributor sales records for that product should automatically recalculate to reflect the new case pack. The updated case counts should appear correctly in all Distributor Sales Reports (Sales by Product, Sales by Chain, Sales by Store, etc.).

## Actual Behavior

After updating a product's case pack, the Distributor Sales Reports continue displaying the old case counts based on the previous case pack value. Users must manually re-upload historical distributor files to see correct numbers, which is time-consuming and error-prone.

## Steps to Reproduce

1. Navigate to **Product Specifications**.
2. Select a product that has distributor sales data.
3. Note the current case pack value (e.g., **8 units per case**).
4. Navigate to **Distributor Sales Reports → Sales by Product**.
5. Filter by the product and note the total **Cases Shipped** value.
6. Return to **Product Specifications** and update the case pack to a new value (e.g., **9 units per case**).
7. Return to **Distributor Sales Reports → Sales by Product**.
8. Observe that the **Cases Shipped** value has not changed or has changed incorrectly.

## Impact

* Sales and broker teams cannot trust case count metrics after correcting product specifications.
* Historical reports show inconsistent data, making trend analysis unreliable.
* Users must manually track which products had case pack changes and mentally adjust numbers.

## Acceptance Criteria

* When a product's case pack is updated, all distributor sales records for that product are automatically recalculated.
* The recalculation uses the following formula:* Round the result to **2 decimal places**.
* Only records with known unit counts are recalculated.
* Records without unit counts remain unchanged.
* All Distributor Sales Reports display the updated case counts, including:* Sales by Product
  * Sales by Chain
  * Sales by Store
  * Sales by City
  * Sales by State
  * Sales Details
  * Velocity
  * DC Report
  * Warehouse Report
* The recalculation happens automatically in the background without requiring any user action.
* The total **Cases Shipped** in reports reflects the sum of all recalculated values.

## Example

### Before Fix

* **Product:** Bubbies Mochi Ice Cream - Alphonso Mango
* **Original Case Pack:** 8 units per case
* **Cases Shipped (Report):** 7,776

### After Updating Case Pack to 9

* **New Case Pack:** 9 units per case
* **Recalculated Cases Shipped:** ~7,422.66
* The report displays the updated case count based on the new case pack.

## Notes

* This fix ensures data consistency between **Product Specifications** and historical sales reports.
* The recalculation preserves the original unit counts and only adjusts the case count based on the updated case pack.
* Records where unit counts were not captured during import remain unchanged to avoid data loss.
