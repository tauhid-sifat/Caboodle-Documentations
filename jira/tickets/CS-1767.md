## Description

**Environment:** Brand view (Bubbies Ice Cream) → Promotional Planning → Promotional Calendar

## Steps to Reproduce

1. Log in as a Brand user (Bubbies Ice Cream).
2. Go to **Promotional Planning → Promotional Calendar**.
3. Find the **Adams Hometown Market** banner row.
4. Click the **EDLP** event chip, which shows a count badge of **6** (e.g. in December).

## Actual Result

* The **Promo Events** modal opens, but the table (Event Name, Month, Start Date, End Date, SKU, UPC, Item Status, Event Status) is **empty**.
* The modal header reads **"EDLP · Adams Hometown Market · February · Retailer Approved"**, even though the chip was clicked in a different month column.

## Expected Result

* The modal lists all **6** events that the chip's count badge shows.
* The header shows the **month of the chip that was clicked**.
* The chip count and the number of rows in the modal always match.

## Additional Notes

* The same EDLP chip with a count of 6 appears in several months for Adams Hometown Market. Check whether the problem affects every month or only some.
* Check the other banners with event counts too (e.g. Alvesta Glass / Lohilo with 18, Associated Food Stores with 10), to see whether this is specific to EDLP events or affects all event types.
* **Possible cause:** the count and the modal list may use different queries or filters, such as month, status, or event type. EDLP events may also span several months and not be matched to the clicked month.
* **Possibly related:** CS-1746 (EDLP event saved/returned with an empty event name) and CS-1436 (EDLP reporting only populating January).
