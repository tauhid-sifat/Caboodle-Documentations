## Description

**Summary**

Add an admin-only read API endpoint to verify read access to a given external database connection.

Context

We need a way to confirm that Caboodle can establish a connection and read from an external SQL Server database before wiring up any downstream ingestion/mapping work. This endpoint acts as a connectivity and read-access smoke test.

Target Database (Bubbies)

* Host: 20.245.139.43
* Port: 1433
* Database: BUBBI
* Table: dbo.ForecastData
* Credentials: Stored in secrets manager under <KEY_NAME>. Do not hardcode or commit.

**Requirements**

* Add a new admin-only endpoint (RBAC: admin role required).
* Endpoint attempts to connect to the configured SQL Server instance using stored credentials.
* Perform a lightweight read against dbo.ForecastData (e.g. SELECT TOP 1 or row count) to confirm read access.
* Return a structured result: connection status, read status, row count or sample metadata on success, sanitized error message on failure.
* Handle failure cases gracefully: unreachable host, auth failure, missing table, timeout.
* Apply a sensible connection/query timeout.

**Acceptance Criteria**

* Endpoint exists and is protected behind admin RBAC.
* Successful call against BUBBI / dbo.ForecastData returns a success response with read confirmation.
* Auth failure, unreachable host, and missing-table cases return clear, sanitized error responses.
* Credentials are read from configuration/secrets, not hardcoded.
* No credentials or connection strings appear in logs or API responses.

**Notes**

* Connection details verified manually before implementation.
* Scope is read-only verification — no writes, no schema changes.
