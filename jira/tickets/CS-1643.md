## Description

## Summary

Update the Broker/Brand filter panels (Brand Report list, Category Review list, and the Category Review calendar) to call the reworked filter-options APIs, which now return smarter, cascading results based on what the user has already selected — and pick up several new filter fields (month/year/date-range breakdowns) that had never been exposed before.

## Background

Today, each filter panel's dropdown options are fetched independently and don't account for what else the user has already filtered by — a user can select a retailer and still see categories/brands that have no reviews under that retailer, leading to empty results after applying filters. The filter-options endpoints have been reworked to solve this: they now narrow every dropdown's options based on the user's current selections elsewhere in the panel, so users only ever see choices that will actually return data.

Alongside this, a couple of related, smaller items are bundled into this ticket:

* The Category Review filter and calendar filter panels can now offer additional breakdowns (review month, reset month/year, submission-due date range) that weren't previously available.
* The calendar filter's "Brands" list needs a small field-name update to match the format used everywhere else.
* Re-notify no longer logs an automatic internal note — any UI that expected to see that note should stop expecting it.

## Details & Required Changes

### 1. Cascading filter behavior (all three panels)

* Each filter panel's options call must now send along whatever the user has already selected elsewhere in that same panel, so the returned lists reflect only choices that are actually reachable given the current selections.
* A field being actively edited should always show its **full** set of choices (ignoring its own current selection) — only the *other* fields narrow. This prevents a multi-select dropdown from shrinking to just what's already picked and becoming impossible to expand.
* Panels that currently fetch each dropdown's options with a separate call may instead fetch all options in one call, then re-fetch just the field the user is actively interacting with as they change other selections — this is an optional efficiency improvement, not a requirement.

### 2. Brand Report filter panel

* Functionally unchanged for the end user — same filters, same options — but results are now narrowed by current selections as described above.
* No new UI is required here.

### 3. Category Review filter panel

* New optional filters are now available: review month, reset month, reset year, and submission-due date range.
* Decide with design/product whether to expose these as new filter controls now or in a follow-up — not required for this ticket to be considered functionally complete, but flag if there's user demand to include them now.

### 4. Category Review calendar filter panel

* Same new optional filters as above are available here too.
* **Required fix:** the "Brands" options list changes its field names — anywhere the UI reads a brand's id/name from this specific panel's options needs to be updated to the new field names. Verify the brand filter dropdown on the calendar view still populates and filters correctly after this change.
* Confirm there is no "year" input expected anywhere in this specific filter panel — it never existed as an actual filter here.

### 5. Re-notify internal note removal

* After a re-notify, the Brand Report's internal notes list will no longer show an automatically generated "Notified via Notify Brand" entry.
* If any screen relies on that note appearing (e.g. as a way to confirm a re-notify happened), switch it to reference the report's audit log instead, which still records every re-notify event.
