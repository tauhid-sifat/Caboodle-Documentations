## Description

The same feature is currently labeled inconsistently across the product:

| Location | Current Name |
| Brand Retail Reports section | Feature name: `Retail Report`
Exported CSV file name: `APL Report` |
| Broker section | Feature name: `Retail APL` |

This inconsistency can confuse users who interact with the feature in one section and then encounter a differently named artifact (or vice versa) in another, making it unclear that they're the same thing.

**Problem**

* Users moving between the Brand Retail Reports and Broker sections may not realize `Retail Report` and `Retail APL` refer to the same underlying feature/data.
* Increases cognitive load and potential support/help-desk questions ("Is this the same report as...?").
* Inconsistent naming undermines trust in the product's polish and information architecture.

**Proposed Solution**

Adopt a single, consistent name for this feature and apply it everywhere it appears, including:

* Feature/menu labels (Broker section)
* Exported file names (Brand Retail Reports section)
* Any related tooltips, help text, emails, or documentation

*Suggested unified name: *`Retail APL Report`* (combines both existing terms — pending final decision by design/product).*

**Acceptance Criteria**

* Final naming convention agreed upon and documented (e.g., in a style guide or naming glossary)
* Feature label updated in Broker section
* Exported CSV file name updated in Brand Retail Reports section
* Any other UI references (tooltips, dropdowns, help docs, filters, email notifications) audited and updated
* QA verification across both sections confirms consistent naming
* No broken references (e.g., saved filters, bookmarks, automation scripts relying on old file name) — consider backward-compatibility or a deprecation note if needed
