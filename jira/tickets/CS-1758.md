## Description

## Summary

In the **Trade Spend Roll Up** report, the promo name is shown inconsistently between sections. The report needs to show the **original (family) name** plus the **version name**, using the same pattern as CS-1729. The BE must return both values.

## Current behaviour

* **Brand Approved section:** always shows the **original** promo name, whichever version was pushed. The figures are correct and come from the pushed version, but the name does not say which version it is.
* **Sandbox section:** shows the **version name** of the version pushed from Sandbox, not the original name.

## Required BE change

For every promo row in the Trade Spend Roll Up API response, for both the **Brand Approved** and **Sandbox** sections, return:

* `originalName`: the family or original promo name (stable across versions)
* `versionName`: the name of the version whose figures are shown (the pushed or reporting version)
* `versionNumber`, e.g. `2` for "v2", so the FE can build the label `v2 · <versionName>`

## Acceptance criteria

* Both sections return `originalName`, `versionName` and `versionNumber` for every row.
* **Brand Approved:** the values match the version that is currently live in Brand Approved.
* **Sandbox:** the values match the version whose figures are used in the report (the reporting version).
* After a version is renamed, the next report load returns the new `versionName`, and `originalName` stays the same.
* After a different version is pushed, the report returns that version's name and number.
* Promos with only one version still return all three fields, with no nulls.
* Existing fields are unchanged, so the current consumers do not break.
