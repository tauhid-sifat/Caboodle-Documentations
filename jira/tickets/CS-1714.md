## Description

When a user adds a new row in a Promotional Management custom tab table and enters data into it (e.g., "Retailer" = "test z"), the entered value does not appear in the row the user just added on the currently visible page (Page 1). It looks as if the data was not saved or was lost. In reality, the new row's data **is saved correctly**, but it gets appended to the **end of the dataset**, which lands on a **different page (Page 2)** — the UI does not auto-navigate to or indicate this.

**Steps to Reproduce:**

1. Go to Promotional Management → a custom tab (e.g., "New Tab 2").
2. Click **"+ Row"** to add a new row.
3. Click into the "Retailer" cell of the newly added row and type a value (e.g., "test z").
4. Click elsewhere / navigate away to another tab (e.g., "New Tab 3") and then return to the original tab ("New Tab 2").
5. Observe Page 1 — the row where the value was typed now appears empty ("–").
6. Navigate to **Page 2** of the same table.
7. Observe that the entered value ("test z") is actually present there, in the last row.

**Actual Behavior:**

* After entering data into a newly added row, the value disappears from view on Page 1 (looks like data loss).
* The entered data is actually saved but pushed to the last page of the paginated table with no visual indication or auto-navigation.

**Expected Behavior:**

* After adding a row and entering data, the UI should:* Add new rows to the **top** of the list / current page instead of appending to the very end
* The user should never perceive their just-entered data as lost.
