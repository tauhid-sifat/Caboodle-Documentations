# Price Module Impact Checklist (Cross-Module Validation)

## 🔹 Core Rule

> When a **new price is added (new active from date)** → it must reflect correctly across **all related modules and event types**

---

# 1️⃣ Price Module Validation

* New price added with correct **Active From Date**
* No overlapping active dates
* Future date price behaves correctly (not applied before date)
* Price history maintained correctly

---

# 2️⃣ Trade Spend Sandbox (TSS) – General

* Updated price reflects in:* Product Summary
  * Event details
* No need for manual refresh (or clearly defined if needed)
* Editing event date updates price dynamically
* Resume draft picks correct price based on date

### Date-Based Validation

* If event date **before new price date** → old price used
* If event date **after new price date** → new price used

---

# 3️⃣ Non-Promo Event Period

* Same validation as promo:* Date-based price application works
* Calculation updates correctly:* Spend
  * Revenue
* No mismatch between UI and backend calculation

---

# 5️⃣ EDLP Event

EDLP runs across **full year**

Checklist:

* If price changes mid-year:* System should:* Split calculation internally
* Verify:* Yearly calculation uses correct price for each period
  * No flat price applied incorrectly across entire year
* Summary reflects correct blended/updated price

---

# 6️⃣ Date Change Impact (Critical)

* Change event start date → price updates
* Change event end date → price recalculates
* Back & forth date change does not break price
* No caching issue (old price showing)

---

# 7️⃣ Bulk & Multi-SKU Behavior

* Multiple products → each product uses its own correct price
* Bulk edit does not override price incorrectly
* Different SKUs with different price dates behave correctly

---

# 8️⃣ Historical Data Integrity

* Old promos (past dates) should NOT change unexpectedly
* Reports reflect correct historical price
* Editing old promo should not apply future price incorrectly

---

# 🔟 UI & UX Validation

* Price clearly visible (no blank/null)
* No “pricing not set” if valid price exists
* Price updates without needing hard refresh (or clearly defined)

---

# 1️⃣1️⃣ Edge Cases

* Price active from today (boundary case)
* Multiple price updates in same month
* Missing price for a date → proper message
* Deleted price handling
* Timezone issue (date mismatch)
* Decimal rounding differences
* Price = 0 case
* Same product - Different banner - Different price
