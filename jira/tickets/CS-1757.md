## Description

## Summary

When a Standard promo is created from **Trade Spend Sandbox**, the user is not asked which year the promo is for. In the **Events** step, the Start/End date pickers always open on the current month (e.g. September 2026). Planning a promo for another year, such as 2027, means clicking month by month through the calendar.

## Current behaviour

1. Trade Spend Sandbox → **Create a Promo Plan** modal asks only for **Promo Title**.
2. Stepper: Retailers and Banners → Products → **Events** → Metrics.
3. In Events, the Start date / End date calendar opens on today's month and year, and there is no quick way to jump to the planning year.

## Expected behaviour

**1. Plan year selector in the Create a Promo Plan modal**

* Add a **Plan year** dropdown next to or below Promo Title. Mark it required, or default it to the current year.
* Use the same year range and style as the Simple Promotion Plan year (see CS-1744 for the range discussion).

**2. Events step opens on the selected year**

* When the user reaches the Events step, the **Start date** and **End date** pickers open on **January of the selected plan year** (or the current month, if the plan year is the current year).
* Applies to every event row, including events added with **+ Add Event**.
* For the **EDLP Promo** toggle, the default range is 01 Jan – 31 Dec of the selected plan year.

**3. Year can be changed later**

* Show the plan year in the header next to the promo title, and let the user edit it with the same pencil/edit pattern as the title.
* If the year changes after events already exist, warn the user, or ask whether to shift the event dates.

## Acceptance criteria

* The Create a Promo Plan modal has a Plan year selector.
* The Events step date pickers open on the selected year.
* EDLP defaults to the selected year's full range.
* The selected year is saved with the promo and shown in the Sandbox list (Year column) and in Brand Approved after the push.
* Existing drafts without a year default to the current year, with no errors.
* Validation: event dates should fall within the selected plan year. Confirm with PO whether this is a hard block or a warning.
