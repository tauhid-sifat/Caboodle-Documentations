## Description

Provide the backend to support the admin Sent Emails feature: a paginated list of all emails sent from the system, plus endpoints to resend one or multiple emails.

Emails are logged at send time (recipient, subject, type/category, body/template reference, timestamp, status). Resend re-dispatches using the stored email content and original recipient.

**Acceptance Criteria:**

* Sent emails are persisted with: recipient, subject, email type/category, body or template reference, sent timestamp, and status (Sent / Failed).
* `GET`-equivalent list endpoint returns sent emails, paginated, newest first. Follow the existing POST-list + filter-options pattern used elsewhere in admin.
* List response includes all fields needed for the FE table (recipient, subject, type, sent date/time, status).
* Resend endpoint accepts a single email log ID and re-dispatches using stored content/recipient.
* Bulk resend endpoint accepts an array of email log IDs and re-dispatches each; returns a per-item result (success/failure) rather than failing the whole batch on one error.
* Resend creates a new sent-email log entry (or updates status) so history stays accurate — grooming to confirm which.
* Clean architecture: separate controller / service / repository; no business logic in controller.

**Open questions:**

* Resend as new log row vs. status update on original?
* Bulk batch size cap / async job (poll pattern) vs. synchronous?
* Filters exposed on list (recipient, date range, status, type)?
