## Description

Filters are now **dynamic/dependent** — selecting one filter option triggers a **BE API call** to fetch and update the available options for other related filter attributes. However, currently, the **other filter fields remain clickable/enabled** while this API call is in progress. Users can interact with them **before the updated options are loaded**, which can lead to incorrect selections, stale data, or inconsistent filter state.

**Current Behavior:**

* User selects a filter option (e.g., Filter A).
* BE API call is triggered to fetch updated/dependent options for other filters (e.g., Filter B, Filter C).
* While this API call is **in progress**, other filter fields remain **enabled/clickable**.
* User can select an option in another filter **before** the updated data has loaded — leading to potential stale selections or inconsistent filter results.

**Expected Behavior:**

* When a filter option is selected and the dependent BE API call is triggered:* **All other dependent filter fields should be disabled** (not clickable) while the API call is in progress.
  * Once the API call **completes successfully** and updated options are loaded, the dependent filters should be **re-enabled** with the refreshed options.
* Recommend showing a **loading indicator** (e.g., spinner or skeleton state) on the affected filter(s) during this period, so users understand why the field is temporarily disabled.

**Steps to Reproduce:**

1. Go to any section with dynamic/dependent filters (e.g., Category Review, Promotional Management, etc. — specify which sections apply).
2. Select an option in one filter.
3. Immediately try clicking/selecting an option in another dependent filter **before the API call finishes**.

**Actual Behavior:**

* Other filter remains clickable and allows selection during the loading state.
