## Description

Duplicate store records are currently being created in the **Store List** module under the Admin section. This results in multiple records representing the same store and can cause inconsistencies across modules that depend on store data.

## Requirements

* Investigate the root cause of duplicate store creation.
* Identify the fields/criteria that should be used to determine whether a store already exists.
* Prevent creation of a new store when an equivalent store record already exists.
* Review existing duplicate records and determine whether they need to be cleaned up/merged.
* Ensure the duplicate prevention logic works consistently across all store creation/import flows.
* Verify that preventing duplicates does not affect legitimate stores that have similar names or other overlapping information.

## Acceptance Criteria

* The same store cannot be created multiple times based on the defined uniqueness criteria.
* Existing duplicate records are identified and handled appropriately.
* All relevant Store creation/import flows use the same duplicate validation logic.
* Legitimate stores with similar information can still be created when they are genuinely different.
* No duplicate Store records are created after the fix is deployed.
