## Description

In SPINS → **Banner Weekly Unit Sales**, applying the **Period Ending** fails. The API call to `/api/v1/spins/stores-insight-filter-data` returns a **504 Gateway Timeout** error, blocking users from filtering the report by date.

**Problem**

* A 504 Gateway Timeout indicates the request is not failing due to bad input (unlike the 400 errors seen in other SPINS tickets) — instead, the upstream server/service is taking too long to respond or is unreachable within the gateway's timeout window.
* This typically points to a **performance issue** (slow query, large dataset processing, inefficient filter logic) or a **backend/infrastructure issue** (service overload, downstream dependency failure, network/connectivity issue between gateway and service).

**Impact**

* Users are completely blocked from applying the Date filter in Banner Weekly Unit Sales, making the report unusable for date-based analysis.
* If this is a performance/timeout issue tied to data volume, it may worsen over time as data grows, or may intermittently fail depending on server load.
* Full workflow blocker for this report.

**Steps to Reproduce**

1. Navigate to SPINS → **Banner Weekly Unit Sales**.
2. Apply/interact with the **Period Ending**.
3. Observe API call to `/api/v1/spins/stores-insight-filter-data`.
4. Note the request returns a **504 Gateway Timeout** error.
5. Filter fails to load/apply as a result.

**Expected Behavior**

* Applying the Date filter should return a successful response within an acceptable time window, with filter data loading correctly.

**Actual Behavior**

* API call times out at the gateway level (504), and the Date filter fails to function.
