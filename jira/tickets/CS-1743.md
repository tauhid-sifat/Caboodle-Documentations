## Description

## Summary

The Simple Promotion screen has a **"Fill this in Excel"** section with **Export** and **Import** buttons. Its helper text reads "Export the grid, fill it in, then import it back." No template file is shared for import, and the flow is not consistent with the other import features in the system.

## Environment

Staging, brand **Apple Jacks**, Promotional Planning → Simple Promotion

## Current behaviour

* There is no downloadable template for Import. The user has to rely on Export of the current grid.
* There is no guidance on the expected columns, format, or rules.
* The flow looks and behaves differently from the other import features in Caboodle.

## Expected behaviour

The flow should be user friendly and aligned with the existing system import pattern:

1. **Download Template** option with a sample, clearly named file. Column headers per CS-1708 are Promotion Title, Banner, UPC, Event Name, Start Date, End Date, and Fee or Notes, or the finalised grid columns.
2. **Instructions and format hints** covering required fields, date format, EDLP (Y/N), one event per month per line, and a price not being required.
3. **Same UI/UX as other imports**: upload modal, file-type check, progress, and success/failure summary.
4. **Row-level validation feedback**: valid rows imported, invalid rows reported with a reason per row (downloadable error file), as in CS-1708 Scenario 9.
5. **UPC preserved as text** in Export/Import, never converted to scientific notation. The grid currently shows values like `6.28E+11`.

## Notes

* The QA guide (§12) lists Excel Export/Import on the grid as "No backend, out of scope by decision". CS-1708 lists file upload with a template as **in scope** (Scenarios 5, 6, 9). Please confirm the backend scope with the PO/BE (Bijoy) before implementation.
