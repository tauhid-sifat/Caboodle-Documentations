## Description

During **Product Upload**, when some products in the batch fail to upload successfully, the system correctly shows an **error file download modal** (allowing users to download details of failed items). However, the **success modal** is also shown at the same time — even though the upload was only partially successful.

**Problem**

* Two conflicting modals (partial-failure error + full success) appear together for the same upload action, giving contradictory feedback to the user.
* Showing a success modal when some products failed misrepresents the actual outcome of the upload — it implies everything succeeded when it didn't.
* This follows the same pattern as the earlier **Force Delete** bug (error + success modal shown together), suggesting a shared/systemic issue in how partial-failure states are handled across modals in Product Specs.

**Impact**

* Users may believe the entire upload succeeded and not realize some products failed, potentially missing the error file entirely (since success modal may overshadow or compete with it).
* Risk of data gaps going unnoticed — failed products may never get corrected/re-uploaded if the user assumes full success.
* Reduces trust in upload confirmation flows.

**Steps to Reproduce**

1. Navigate to **Product Specs → Product Upload**.
2. Upload a batch/file containing a mix of valid and invalid products (so that some succeed and some fail).
3. Observe the **error file download modal** appears (correct behavior for partial failure).
4. Observe the **success modal** also appears at the same time (incorrect).

**Expected Behavior**

* When some products fail to upload, only the **error file download modal** (or a combined partial-success/partial-failure modal) should be shown — clearly indicating that not all products succeeded, with the option to download the error file.
* The success modal should only appear when **all** products in the batch upload successfully.
* Consider a distinct **"Partial Success"** modal/state (e.g., "X of Y products uploaded successfully — download error file for details") for clearer communication, rather than reusing the pure success modal.

**Actual Behavior**

* Both the error file download modal and the success modal are shown together, regardless of partial failure.
