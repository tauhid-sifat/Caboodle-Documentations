## Description

In User Management → Users → Action → Assign Role, admins can assign roles to users. However, if a user already has an assigned role, the system shows an error message indicating that the existing role must be removed first before assigning a new one.

Currently, there is no option within the same modal to remove the existing role, unlike the brand assignment flow where remove functionality is available.

**Steps to Reproduce:**

1. Go to User Management → Users
2. Click Action → Assign Role for a user with an existing role
3. Try assigning a new role

**Actual Result:**

* System shows an error stating the existing role must be removed first
* No remove role option is available in the modal

**Expected Result:**
Either:

* Add a remove role option within the same modal so admins can directly remove and reassign roles
  **OR**
* Disable the Assign Role option for already assigned users with a proper tooltip/message explaining the restriction

**Impact:**
The current flow is incomplete and confusing, requiring additional/manual steps without providing users a clear way to proceed.

## Comments

### Kazi Towfiq Tasmin Ornov (2026-07-09T10:51:41.422+0600)

Instead of implementing a separate "remove role" option or disabling the assignment button as originally suggested, we overhauled the backend architecture to support **seamless, atomic role transitions**. The `AssignRoleAsync` endpoint has been refactored to natively handle users who already have an active role by performing a complete "handover" process in a single transaction. When an admin assigns a new role to an existing user, the system now automatically:

1. Validates the transition and ensures a designated "Replacement User" is provided if the user is vacating a critical role (like `BrandOwner` or `Broker`).
2. Safely transfers all existing assets (such as assigned Brands and child users in the hierarchy) to the replacement user to prevent orphaned records.
3. Cleans up any outdated role context (e.g., removing old sub-user connections).
4. Swaps the Identity roles and provisions the new role's context (linking new brands and hierarchy positions).
5. Invalidates active sessions for both users so new security permissions take effect instantly.

This approach completely eliminates the friction of requiring a manual "remove role" step. It turns role assignment into an intelligent, one-click promotion/demotion workflow that guarantees strict data integrity and a much smoother user experience.
