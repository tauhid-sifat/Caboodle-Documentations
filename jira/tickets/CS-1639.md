## Description

Currently, timestamps sent from the backend do not consistently include timezone information (Z/UTC suffix). This makes it impossible for the frontend to reliably convert and display times based on the user's local timezone. All datetime fields in API responses should include the zone designator (e.g., ISO 8601 format with `Z` for UTC) so the frontend can accurately convert and render times per the logged-in user's zone.

**Acceptance Criteria:**

* All API responses containing date/time fields return values in a timezone-aware format (e.g., `2026-08-30T14:32:00Z`).
* Frontend receives UTC-based timestamps consistently across all endpoints/modules.
* Frontend converts and displays the time based on the user's local timezone rather than server/raw time.
* No endpoints return "naive" datetime strings (without zone info).

**Impact:**

* Without zone info, users in different regions may see incorrect or ambiguous times (e.g., created dates, send logs, notes timestamps, calendar entries).
* Affects any feature relying on timestamps: notes, send logs, category reports, calendar indicators, etc.
