## Description

**Problem**

The "Copy File URL" button in the File Repository copies a presigned S3 URL that expires after 6 hours. Any link a user shares — in an email, a document, a chat message — silently stops working the next day, which reads as a product defect.

The same URL also discloses more than it should. It contains the S3 bucket name, the tenant's full folder path including the customer's brand name, the region, and the AWS access key ID. Anyone the link is forwarded to can read all of it. There is currently no way to revoke a link once shared.

**Solution**

Replace the presigned URL with an opaque, revocable **share token**. The button copies a permanent link of the form `{apiHost}/share/{token}`, which reveals nothing about the bucket, tenant, or file path. Opening it redirects to a freshly signed, short-lived S3 URL generated per request.

**Scope**

* `POST api/v1/files/share` — mint a share link (reuses the existing one on repeat calls)
* `GET /share/{token}` — anonymous; 302-redirects to a 15-minute presigned URL. Unversioned by design, so permanent links don't carry an API version that could be retired
* `DELETE api/v1/files/share/{token}` — revoke
* New `FileRepository.FileShareLinks` table; new `UserFiles.Key` column so S3 keys stop being reverse-engineered out of stored URLs
* Optional expiry (1–3650 days); default is no expiry

---

## Acceptance criteria

* A copied link still resolves after 24+ hours
* The link contains no bucket name, tenant ID, brand name, file path, or AWS key ID
* Revoking a link stops it working immediately
* Files marked **Private** cannot be shared; the API returns 400
* A public file switched to Private invalidates links already issued
* Unknown, revoked, expired, and deleted tokens all return the same 404 (no token probing)
* Repeat "Copy URL" clicks on the same file return the same link
* The existing Download button is unchanged
* ≥90% test coverage on the touched Application project

---

## Technical notes

* Migration `FileShareLinksAndUserFileKeyAdded` must be applied before the endpoints work. Requires `--context MainDbContext` — the bare `dotnet ef` command fails, as the solution has two DbContexts
* The `Key` backfill deliberately skips URLs containing a query string or percent-encoding; writing an encoded key would point at a non-existent S3 object. Those rows use the runtime fallback
* `AppUrls:ApiBaseUrl` added per environment (Staging `caboodle-service-stg…`, Production `api.caboodleservices.com`)
* Frontend guide: `docs/FileRepository-Share-Link-FE.md`

**Out of scope:** frontend integration; switching `ProductSpec.ImageURL` to share links; CDN work.
