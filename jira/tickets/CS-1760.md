## Description

## Summary

On the Simple Promotion create grid, **"Copy events to other months"** keeps the same day number when it shifts dates to the target month. If the source End Date is a day that doesn't exist in the target month (29, 30 or 31), the **End Date is left empty** after copying.

## Example

* Source (Jan): Start **01/01**, End **01/31**
* Copied to Feb: Start **02/01**, End **(empty)**, because 02/31 doesn't exist
* The same happens when copying to Apr, Jun, Sep or Nov (30-day months), and to Feb in both leap and non-leap years.

## Improvement

When the source day doesn't exist in the target month, fill the date with the **last day of the target month**.

| Source End Date | Target month | Expected End Date |
| 01/31 | Feb 2026 | 02/28 |
| 01/31 | Feb 2028 (leap year) | 02/29 |
| 01/30 | Feb 2026 | 02/28 |
| 01/31 | Apr | 04/30 |
| 03/31 | Jun, Sep, Nov | last day (30) |
| 04/30 | May | 05/30 (day exists, keep as is) |

## Acceptance criteria

* End Date is never left empty after a Copy. If the day doesn't exist, it is set to the last day of the target month.
* The same rule applies to **Start Date**. For example, 01/30–01/31 copied to Feb gives 02/28–02/28, and Start is never later than End.
* Days that exist in the target month are copied unchanged.
* Leap years are handled based on the selected Plan year.
* Works when copying to several months at once, and for many rows.
* Works together with the Copy-with-filter fix (CS-1753).
* No validation error after the copy for a valid source event.
