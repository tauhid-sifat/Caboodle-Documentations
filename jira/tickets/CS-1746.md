## Description

## Summary

After a Simple Promotion is created with an **EDLP** event, the details API returns the EDLP event with an **empty event name** (`"eventName": ""`). The Event column on the details screen shows only the date range (01 Jan – 31 Dec) and no name.

## Environment

Staging, brand **Apple Jacks**
Promotion: **"EDLP Event test Name"** (id `43b8e8f1-8c0e-4ce0-99f2-3ebf4d040a92`), Plan year 2027
Endpoint: `POST tradespends/simple/{id}` (details)

## Steps to reproduce

1. Open Promotional Planning → Simple Promotion → create.
2. On one line (ABSCO / ABSCO National / All Natural Food Dye - 12 Pack Case), set EDLP = **Y**, add an everyday allowance, and enter an event name.
3. Submit, then open the created promotion's details.

## Actual result

Details response for the EDLP event:

```json
{
  "id": "5a9376cd-9b65-4ab1-b977-185307ea0ea…",
  "month": 0,
  "eventName": "",
  "startDate": "2027-01-01T00:00:00",
  "endDate": "2027-12-31T00:00:00",
  "promotionType": 2,
  ...
}
```

* `eventName` is empty.
* The UI Event column shows only "01 Jan – 31 Dec".
* Month, dates and promotion type are correct.

## Expected result

* The EDLP event is saved with the event name entered in the grid, and the details API returns it.
* The name appears on the details screen and on the promotional calendars.

## Notes for dev

* Please check the create request payload. Confirm whether the FE sends the EDLP event name, and under which field, or whether the BE drops or does not map it for `month: 0` events.
* The grid has no dedicated EDLP event-name column (only Y/N and Everyday Allowance). If the name is taken from another column, such as Jan Event Name, the mapping needs to be defined clearly between FE and BE.
* Also check the edit, add and calendar paths for EDLP events, which may have the same issue.
* Minor, separate: the UPC is returned as `"upcNumber": "6.28E+11"` (scientific notation). See CS-1743.
