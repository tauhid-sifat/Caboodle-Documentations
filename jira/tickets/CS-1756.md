## Description

## Summary

On the Trade Spend Sandbox **Versions** panel, the **"Push to Approved"** button stays enabled on a version that is already **"Live in Brand Approved"**. Pushing the same, unchanged version again has no purpose and can confuse users. The button should reflect whether a push is actually needed.

## Current behaviour

* v1 "Test prom" shows the **Live in Brand Approved** tag, and the banner reads "Brokers see Test prom · pushed Sep 29, 2026 5:46 AM".
* The **Push to Approved** button on that same version is still enabled.

## Expected behaviour

**1. Live and unchanged → disabled**

* If a version has the **Live in Brand Approved** tag and nothing has changed since it was pushed, its **Push to Approved** button is **disabled**.
* Show a tooltip on the disabled button, e.g. "This version is already live in Brand Approved."

**2. Live but edited after the push → re-push enabled**

* If anything in the live version changes after it was pushed (events, values, dates, products, name), the button becomes **enabled** again.
* Suggested label: **"Re-push to Approved"**, optionally with an "Unpublished changes" hint, so the user knows Brand Approved is out of date.
* After a re-push, the button goes back to disabled and the banner's "pushed" timestamp updates.

**3. Another version pushed → buttons swap**

* When the user pushes a **different** version to Brand Approved:* the new version gets the **Live in Brand Approved** tag and its button becomes **disabled**;
  * the previous version loses the tag and its **Push to Approved** button becomes **enabled** again.
* Only one version can be live at a time.

## Acceptance criteria

* A live, unchanged version has its button disabled, with a tooltip.
* Editing the live version enables Re-push.
* Re-pushing disables the button again and updates the timestamp.
* Pushing another version moves the tag and swaps the enabled/disabled state.
* The state is correct after a page refresh, so it is based on saved data and not only the UI state.
* Works alongside "Set as reporting" and Delete (see CS-1755).
