## Description

## Summary

Today, a promo can only be removed from Brand Approved by opening it and clicking **Remove** on its details screen. Add a **Remove** option directly on the **Brand Approved list page**, so users can remove **one or several promos** without opening each one. The same pattern already exists in the Trade Spend Sandbox list (Select All + Delete).

## Current remove logic (keep as is)

* **Normal (Standard) promo:** removed from Brand Approved, and from the Trade Spend Roll Up and the Monthly Report approved section. The promo **stays in Sandbox** and can be pushed to Approved again later.
* **Simple Promotion:** removed from Brand Approved and from the **Brand and Broker calendars**. There is no Sandbox copy, so this removal is **final** and can't be undone or re-pushed.

## Expected behaviour

**1. Single remove from the list**

* Each row in the Brand Approved list has a Remove action, either a row action or an icon.

**2. Bulk remove**

* Each row has a checkbox, and there is a **Select All** option, as in the Sandbox list.
* A **Remove** button at the top of the list is enabled only when at least one promo is selected, and shows the count, e.g. "Remove (3)".

**3. Confirmation dialog**

* It lists or counts the selected promos and explains the result by type:* Standard: "Will be removed from Approved and reports. It stays in Sandbox and can be pushed again."
  * Simple: "Will be permanently removed, including from the Brand and Broker calendars. This can't be undone."
* If the selection mixes Standard and Simple promos, show both messages, with the Simple promos clearly marked as permanent.

**4. After removal**

* The list refreshes, a success message shows the count removed, and the selection is cleared.
* Removed promos disappear from the Roll Up, the Monthly Report approved section and the calendars, following the same logic as removing from the details screen.

## Acceptance criteria

* Single remove from the list gives the same result as Remove on the details screen, for both promo types.
* Bulk remove works for Standard-only, Simple-only and mixed selections.
* Standard promos are still in Sandbox after removal and can be pushed again.
* Simple promos are permanently removed and gone from both calendars.
* Select All respects the current search and filter (only the visible promos are selected), and paging is handled clearly.
* If some promos fail to remove, the user sees which ones, and the rest still succeed. Alternatively all-or-nothing, but the approach must be defined.
* Permissions are the same as for the existing Remove.
* No regression on Remove from the details screen (CS-1748).

## Notes for dev

* Check whether the BE supports **bulk remove** from Approved in a single call. If not, a BE sub-task is needed, or the FE calls the single remove per promo.
* Reuse the Sandbox list's checkbox and bulk-action UI for consistency.
