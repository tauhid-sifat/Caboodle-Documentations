## Description

In **Product Specs → Product**, when performing a **Force Delete** on any product, the frontend displays **both an error modal and a success modal** at the same time — even though the product is actually deleted successfully. Since the deletion succeeds, showing the error modal serves no purpose and only confuses/alarms the user.

**Problem**

* Two conflicting modals (error + success) appear together for the same action, creating a contradictory and confusing user experience.
* Since the underlying deletion is successful, the error modal is misleading — it implies failure when there is none.
* Likely caused by the frontend handling a secondary/non-critical response (e.g., a warning, partial response, or an unrelated failed sub-call) as a hard error, while still correctly processing the main success response.

**Impact**

* Users may think the deletion failed and could retry unnecessarily, potentially causing confusion or duplicate actions.
* Undermines trust in the reliability of delete confirmations across the platform.
* Creates a jarring, unpolished UX moment (two modals stacked/overlapping).

**Steps to Reproduce**

1. Navigate to **Product Specs → Product**.
2. Select any product and choose **Force Delete**.
3. Confirm the deletion.
4. Observe both an **error modal** and a **success modal** appear.
5. Verify in the product list that the product was, in fact, deleted successfully.

**Expected Behavior**

* Only the **success modal** should be shown when a force delete completes successfully.
* No error modal should appear unless the deletion actually fails.

**Actual Behavior**

* Both error and success modals are shown simultaneously, despite the deletion succeeding.
