## Description

When uploading a file in **Distributor APL**, the system simultaneously shows a **green "Success" toast** and an **"Upload" modal with an error message** stating "Some data were not uploaded. Click Here to see the corrupted data." These two messages contradict each other — one indicates the upload fully succeeded, the other indicates partial failure — leaving the user unsure whether the upload actually succeeded or not.

**Steps to Reproduce:**

1. Go to Distributor APL.
2. Click **Upload** and select a file that contains some invalid/corrupted rows (mixed valid + invalid data).
3. Observe the messages shown after upload completes.

**Actual Behavior:**

* A **"Success"** toast notification appears (top right), implying the upload was fully successful.
* At the same time, the **Upload modal** displays: *"Some data were not uploaded. Click Here to see the corrupted data"* — indicating partial failure.
* Both messages are shown together, which is contradictory and confusing.

**Expected Behavior:**

* The system should show a **single, accurate status** reflecting the actual outcome:* If the upload is **fully successful** → show only "Success."
  * If the upload is **partially successful** (some rows failed) → show a **"Partially Done"** (or similar) message — not "Success" — along with the corrupted data link, consistent with the earlier raised ticket on correct status messaging (Success / Partially Done / Failed based on row-level pass/fail).
  * If **all rows fail** → show "Failed" (per the same earlier ticket's logic).
* The "Success" toast should not fire when there is any corrupted/failed data in the same upload.
