## Description

**Improvement 1: Add Info (i) Button for "How these tools report back"**

**Current Behavior:**

* No explanation is provided on how these tools report back their results.

**Expected Behavior:**

* Add an **"i" (info) icon** beside the **"Store List Tools"** header.
* On hover/click, it should display information explaining **how these tools report back** (results/output behavior).

---

**Improvement 2: Add Clear Button in Merge Store**

**Current Behavior:**

* No option to clear/reset selections or entered values in the Merge Store tool.

**Expected Behavior:**

* Add a **Clear** button in the **Merge Store** section to reset the form/selections back to default.

---

**Improvement 3: Incorrect Navigation After Running Merge Store**

**Current Behavior:**

* When a user executes **Run** in Merge Store, after completion, the user is redirected to the **"Data Cleanup"** page.

**Expected Behavior:**

* After successfully running Merge Store, the user should stay in same page

---

**Improvement 4: Change Search Icon in Find Nearby Stores**

**Current Behavior:**

* The current search icon in **Find Nearby Stores** is *not matched with search theme*

**Expected Behavior:**

* Replace the search icon with the correct/appropriate icon

---

**Improvement 5: "Radius (meters)" Field Value Shared Between "Near a Store" and "Near an Address"**

**Current Behavior:**

* The **"Radius (meters)"** field appears in both **"Near a Store"** and **"Near an Address"** sections.
* Entering a value in **either one** of the two sections causes the value to reflect in **both** — even though they are meant to be independent inputs.

**Expected Behavior:**

* Each section ("Near a Store" and "Near an Address") should have its **own independent "Radius (meters)" value**, not shared/synced with the other.

**Suspected Cause (for engineering to verify):**

* Both radius fields are likely bound to the **same state variable** instead of separate independent states.
