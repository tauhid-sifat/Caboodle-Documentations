# Module 2.5 — Product Specifications (code-verified)

Source of truth: `docs/feature-context.md` §2.5. Self-sufficient reproduction (condensed to verified facts).

## Purpose
Owns a brand's product master data: categories, product specifications (SKU attributes, UPCs, pack and pallet data, distributor item codes) and the price list (per-unit price per product, distributor or delivery method, and start date). Products and prices feed trade promotions, banner SKUs, reports and data-ingestion matching.

## Key paths
- Backend controllers: `Hosts/API/Controllers/Modules/ProductSpecs/CategoriesController.cs`, `PriceListsController.cs`, `ProductSpecsController.cs`; admin bulk routes in `Hosts/API/Controllers/Modules/DataUpload/MasterDataUploadController.cs` (`categories`, `price-list`, `productspecs` actions); `Hosts/API/Controllers/Admin/AdminController.cs` (`SyncPerUnitPriceAsync`).
- Backend module: `Modules/ProductSpec/Modules.ProductSpecs.Application/` (`Categories/`, `ProductSpecifications/`, `PriceList/`, `ExportImport/`, `Specifications/`, `Helpers/QueryHelper.cs`, `Helpers/ProductSpecModules.cs`, `DTOs/`), `Modules/ProductSpec/Modules.ProductSpecs.Domain/` (`Category`, `ProductSpecification`, `PriceList`).
- Shared services used: `SharedDataService` (`UpdatePromoEventsPerUnitPrice`, `SyncPerUnitPriceAsync`, `CreateBannerSkusAsync`), `SharedDataHubService` (`PropagateProductNameChangeByUpcAsync`, `PropagateCasePackChangeByUpcAsync`), `BackgroundJobDispatcher`, `MasterDataUploadService` (admin imports/exports), `DataUpload/.../ProductSpec/` (admin import/export requests).
- Web: routes `caboodle.web/src/app/(brand)/[brandID]/(product-specs)/` (`categories`, `categories/[categoryID]`, `products`, `products/add`, `products/[productID]`, `products/[productID]/edit`, `pricing`, shared `ProductSpecsLayout.tsx`, `ProductListing.tsx`); services `category.service.ts`, `product.service.ts`, `priceList.service.ts`, `sampleFile.service.ts`; hooks `product-spec/{category,product,priceList}.ts`, `sampleFilesHook.ts`; components `components/productSpecs/` (only `AddPricingList.tsx` live); models `category.interface.ts`, `priceList.interface.ts`; sort keys `sort-keys/product-specs.ts`.
- Admin: routes `category`, `price-lists`, `product-spec`; components `Tables/{CategoryTable,PriceListsTable,ProductSpecTable}.tsx`, `Category/AddCategory.tsx`, `PriceList/AddPriceList.tsx`, `ProductSpec/AddProductSpec.tsx`; services/hooks; header helper `crmDataUpload.helper.ts` (`brandSupportHeaders`).

## Shared data models
- `ProductSpecs.Categories` (`Category`): `ID`, `BrandID`, `Name`, `ImageURL`, audit and soft-delete. Name unique per brand by handler check only (index on `Name`, not unique).
- `ProductSpecs.ProductSpecifications` (`ProductSpecification`): `ID`, `BrandID`, `CategoryID?`, `Name`, `BrandCode`, `Description`, `CaseUPC` (long), `UPCNumber` (string), `Size`, `UOM`, `CasePack`, `MasterPack`, item and case dimensions, `PalletTie`, `PalletHigh`, `PalletCount`, `GrossWeight`, `NetWeight`, `KeHECode`, `UNFICode`, `UNFIEastCode`, `UNFIWestCode`, `Miscellaneous`, `ImageURL`.
- `ProductSpecs.PriceList` (`PriceList`): `ID`, `BrandID`, `ProductID`, `Name` (product name copy), `DistributorID?` (leaf distributor or delivery method, `CRM.Distributors`), `CategoryID?`, `CasePrice?`, `PerUnitPrice?`, `ValidFrom?`. Several rows per product and distributor form price history by `ValidFrom`.
- Read from other modules: `CRM.Distributors` (parent hierarchy), `CRM.DistributorBrands` (brand to distributor link), `CRM.BannerSKUs`, `CRM.Banners`, `TradeSpend.TradeSpendPromoEvents`, `TradeSpendSandbox.PromotionalEvents`, `Brand.Brands`.

## Shared services

- `ProductSpecModules` (`Helpers/ProductSpecModules.cs`): slug sets `ProductAndCategoryLookup` (`categories-products-pricing`, `approved-promotions`, `trade-spend-sandbox`, `retail-reports`), `PriceCreation` (first three), `BrokerPromotionPlanning` (`approved-promotions`, `trade-spend-sandbox`), `BannerProducts` (`distributors`, `retailers`), `SampleFileModules`.
- `QueryHelper` (`Helpers/QueryHelper.cs`): sort-key allow lists (`ProductSpecColumns`, `PriceListColumns`, `PriceListGroupedByDistributorColumns`, `CategoryColumns`), search-condition builders, `BrandSoftDeleteQuery`.
- `FileExportHelper.GetRecords` / `ConvertToCsvFile` for CSV in/out; `IBulkRepository`; `IMainDbTransaction`; `IJobService` (Hangfire).
- Web `ActionButtons`: add, delete, upload, export, template buttons; `useModuleAccess().can("categories-products-pricing", action)` decides which render.

## Cross-module dependencies
- 2.2 Organizations & Access: module slug `categories-products-pricing` and access engine decide every brand endpoint; admin calls use support access (`OrganizationID` = brand ID).
- 2.4 CRM: price rows point at `CRM.Distributors` linked to brand through `CRM.DistributorBrands`; product create inserts `CRM.BannerSKUs` for every banner; product delete blocked by banner SKUs; CRM banner screens use `GET /productspecs/for-bannerSku/{bannerID}`.
- 2.6 Trade Promotion Planning: product and category lookups feed promo creation; price writes reprice `TradeSpendPromoEvents` and sandbox `PromotionalEvents`; promo product step creates prices (`PricingAddOrEdit`); Simple Entries "Set price" uses `AddPricingList`; force delete removes promo events.
- 2.9 Market Overview & APL: force delete removes `Broker.MarketOverviews` and `Broker.DistributorAPLs` rows; Retail Reports filter uses product and category lookups.
- Data ingestion (KeHE, UNFI, Distributor Sales): product name and case pack changes pushed into `DataUpload` tables by UPC.

## Feature inventory (summary; full detail in source §2.5)

### 2.5.1 Categories [Active]
- Brand groups products into named categories with optional image. Brand users and brokerages with `categories-products-pricing` manage on `/{brandID}/categories`; other modules read category list as lookup (promo creation, Retail Reports filter, trade spend detail).
- User flow: `/{brandID}/categories` (tab "Categories" in `ProductSpecsLayout`) loads `GET /api/v1/categories` with `pageSize`, `currentPage`, `sortingOrder`, `sortKey` (`Name` or `NumberOfProducts`) and optional `searchKeyword`; grid or table view, select-all, pagination. Initial paging, sort, view mode read from URL search params. Add opens `CategoryAddOrEdit` (name, image URL) posts `POST /api/v1/categories`; Edit (row menu, only with update) posts same with `id`. Delete (with delete) sends `DELETE /api/v1/categories` `{ iDs }`. Categories with prices or products skipped; partial delete returns 400 naming how many deleted. Clicking category opens `/{brandID}/categories/{categoryID}`: header with name, image, product count (`GET /api/v1/categories/{id}`), edit pencil (with update), `ProductListing` filtered to category, where "Link Product" and "Remove" manage membership (2.5.1.2). Upload (with import) posts CSV to `POST /api/v1/categories/import` (2.5.1.1). Export hidden on this page (`showExport={false}`).
- APIs: `GET /api/v1/categories`, `GET /api/v1/categories/{id}`, `POST /api/v1/categories`, `DELETE /api/v1/categories`, `GET /api/v1/categories/export`.
- Business rules: controller attribute on `POST /categories` checks only `View`; handler then requires `Create` (no `ID`) or `Update` (with `ID`). Same pattern for price list upsert and product upsert. Names compare case-insensitively within brand; duplicate returns 404 with key `Name` "Category with same name already exists!" (admin service notes unusual status). Delete: categories referenced by non-deleted price row or product not deleted; if none can be deleted, 400 "Selected Categories can not be deleted. They are linked to item(s)."; if some, 400 "{n} category(s) deleted successfully. Others couldn't be deleted ...". Deletion brand-scoped soft delete (`QueryHelper.BrandSoftDeleteQuery`). Sort keys and sort order validated against allow lists before SQL.
- Gotchas: upsert and import load every category in table (`ListAsync`) and filter in memory. Web `useGetCategories` keys on `[getCategories, params]` without `brandId`, so after brand switch previous brand's list can show until refetch (`keepPreviousData: true`). Category export exists on backend but no UI calls it; admin uses `POST /masterdataupload/categories/export` instead.

#### 2.5.1.1 Category import and template [Active]
- Upload CSV of category names and image URLs for selected brand; existing names update image URL, new names create categories.
- User flow: Upload button opens shared bulk uploader posting to `POST /api/v1/categories/import`; template link calls `GET /api/v1/productspecs/export-sample-file?fileCategory=` (`FileCategory.Category`). Failed rows return as CSV.
- API: `POST /api/v1/categories/import` (`RequireModule(categories-products-pricing, null, Import)`), multipart `file` (`CategoryImportDTO`: `[*] Category Name`, `ImageURL`) / `FileUploadResponseMetaDTO` (declared as `ResponseMetaDTO` on action).
- Business rules: blank name failed row "Name is required"; empty file 400 "No records found to upload!". Duplicate names in one file keep last row. Writes bulk insert and bulk update.
- Gotchas: handler class named `ImportProductSpecRequestHandler` although imports categories.

#### 2.5.1.2 Link and unlink products [Active]
- On category detail page, attach uncategorised products to category or remove products from it.
- User flow: "Link Product" opens `ProductLink`, loads every brand product (`POST /productspecs`, `pageSize=-1`) and shows each product's current category; submit calls `PATCH /api/v1/categories/{id}/link-product` with `{ productIDs }`. "Remove" in category's product list calls `PATCH /api/v1/categories/{id}/remove-product`.
- APIs: `PATCH /api/v1/categories/{id}/link-product`, `PATCH /api/v1/categories/{id}/remove-product` (both `RequireModule(categories-products-pricing, null, Update)`).
- Business rules: link only takes products of active brand with no category (`GetProductsByIDSpec`: `CategoryID == null`); if none qualify, 404 "Either product(s) not found, or they already belong to some Category(ies)!". Link writes `CategoryID` only; does not create price rows. Remove sets `CategoryID = null` on products and soft-deletes their price rows for that category (`GetPriceListsByCategoryAndProductsSpec`), so products lose prices.
- Gotchas: removing product from category deletes pricing without warning in UI copy. `ProductLink` lists products that already have category, but backend silently skips them.

### 2.5.2 Products (product specifications) [Active]
- Brand maintains product catalog: name, category, UPC, case UPC, pack sizes, dimensions, pallet data, KeHE/UNFI codes. Brand users and brokerages with `categories-products-pricing` manage on `/{brandID}/products`; product list also product picker for promotions, banner SKUs, Retail Reports (lookup gate covers `approved-promotions`, `trade-spend-sandbox`, `retail-reports`).
- User flow: `/{brandID}/products` renders `ProductListing`: search by name or UPC, filters by case pack and category from `GET /api/v1/productspecs/filters`, sort by `Name`, `UPCNumber`, `CategoryName`, `CasePack`; grid or table; list is `POST /api/v1/productspecs` with filters in body and paging in query. Add (with create) goes to `/{brandID}/products/add`; Edit (row menu or detail page, with update) goes to `/{brandID}/products/{productID}/edit`. Both render `ProductForm`, loads categories (`GET /categories`, `pageSize=-1`), submits `POST /api/v1/productspecs/upsert`, then navigates back. `/{brandID}/products/{productID}` (`GET /api/v1/productspecs/{productID}`) shows basic and other info, per-unit-price-by-distributor chart from `pricingDetails`, link to `/{brandID}/retail-report?productID=`. Delete and Force Delete (with delete), Upload (with import), Export (with export) in sub-features.
- APIs (prefix `/api/v1/productspecs`): `POST /`, `GET /filters`, `GET /{productID}`, `POST /upsert`.
- Business rules: required on upsert: `Name`, `CasePack`, `CategoryID`, `UPCNumber` (`CreateProductSpecRequestValidation`); category must belong to active brand. UPC must be unique within brand among non-deleted products (exact string match). On save UPC trimmed and `$`, `,`, `%`, `-` removed (`ValidateUPCNumber`). Text fields trimmed and blank values stored as empty strings.
- Gotchas: UPC duplicate check compares raw request value before normalisation, so `123-456` passes even when `123456` exists (`GetProductSpecificationAsync` runs before `MapProductSpecFromRequest`). Web `useGetProductFilters` keys on `[getProductFilters]` only, so brand switch can show previous brand's filter options until refetch. Dead web code: `components/productSpecs/{AddProduct,ProductTable,CategoryTable,AddCategory,PriceListTable}.tsx` no live importer; `ProductService.updateProduct` calls `PUT /api/v1/productspecs`, route that does not exist, used only by dead `AddProduct.tsx`.

#### 2.5.2.1 Product save side effects [Active]
- Saving a product also maintains price placeholders, banner SKUs and data-ingestion copies of product name and case pack.
- User flow: In one `IMainDbTransaction`: product inserted/updated; when product new or category changed, one blank `PriceList` row (no price, no date) inserted for each leaf distributor linked to brand that has no row yet for this product and category; on category change, all existing price rows of product under other categories soft-deleted. After commit: new product enqueues `CreateBannerSkus` (Hangfire), inserting `CRM.BannerSKUs` row with status `NotActive` for every non-deleted banner in platform. An update enqueues `PropagateProductNameChangeByUpcAsync` when name changed and `PropagateCasePackChangeByUpcAsync` when case pack changed.
- APIs: Hangfire jobs: `ISharedDataService.CreateBannerSkusAsync`, `ISharedDataHubService.PropagateProductNameChangeByUpcAsync`, `ISharedDataHubService.PropagateCasePackChangeByUpcAsync` (fire-and-forget via `IJobService.Enqueue`).
- Business rules: leaf distributors are those with a parent or with no child (`d.ParentID IS NOT NULL OR child.ParentID IS NULL`), non-deleted, linked by `CRM.DistributorBrands`. Jobs queued only after transaction commits.
- Gotchas: changing product's category soft-deletes all priced rows under old category and replaces with blank rows, so real prices lost; UI gives no warning. Name propagation updates KeHE, UNFI and Distributor Sales rows for that UPC across all brands (no brand filter in `PropagateProductNameChangeByUpcAsync`). Banner SKU creation inserts one row per platform banner for each new product, which is why ordinary product delete almost always blocked (2.5.2.2). In `GetDistributorsQuery` self join checks `d."Deleted"` instead of `child."Deleted"`, so deleted child distributors still make parent count as non-leaf.

#### 2.5.2.2 Delete and force delete [Active]
- Soft delete for products not used anywhere, permanent cascading delete for products already in use.
- User flow: Delete (`ActionButtons`) sends `DELETE /api/v1/productspecs` `{ iDs }`. Products with non-deleted `CRM.BannerSKUs` row skipped; response 400 when any skipped. Force Delete (separate `ActionButtons` with `confirmationTagKey="force-delete-products"`, only on products page, not category page) sends `DELETE /api/v1/productspecs/force-delete` `{ productIDs }` after confirmation.
- APIs: `DELETE /api/v1/productspecs`, `DELETE /api/v1/productspecs/force-delete` (both `RequireModule(categories-products-pricing, null, Delete)`).
- Business rules: force delete runs one transaction of hard `DELETE`s for brand's matching products: `Broker.DistributorAPLs` by UPC (only when no other brand has live product with that UPC), `Broker.MarketOverviews` by `SKUID`, `CRM.BannerSKUs`, `ProductSpecs.PriceList`, `TradeSpend.TradeSpendPromoEvents`, `TradeSpendSandbox.PromotionalEvents` by product id, then products. No product of brand found: 200 "No products found to delete."
- Gotchas: force delete irreversible and removes promotion events and market overview logs owned by other modules; writes no audit entry. `TradeSpendPromoEvents`/`PromotionalEvents`/`MarketOverviews` deletes not brand-filtered, but product ids brand-validated first.

#### 2.5.2.3 Product import, export and template [Active]
- CSV upsert of products keyed by UPC, CSV export of products with price rows, empty template.
- User flow: Upload posts to `POST /api/v1/productspecs/import`; template from `GET /api/v1/productspecs/export-sample-file?fileCategory=` (default `FileCategory.ProductSpec` in `ActionButtons`). Export calls `POST /api/v1/productspecs/export` with paging and sort in query and body `{}` (`ProductService.exportProducts`), so file ignores page's filters.
- APIs: `POST /api/v1/productspecs/import`, `POST /api/v1/productspecs/export`, `GET /api/v1/productspecs/export-sample-file`.
- Business rules: import requires UPC, product name (taken from `Product Name` column into both `Name` and `Description`), existing category name, case pack > 0; numeric columns type-checked. UPCs lose dashes and leading zeros before matching existing products. New products get blank price rows for each leaf distributor and `CreateBannerSkus` job; updated products bulk updated with no price-row or propagation side effects.
- Gotchas: UPC normalisation differs between import (dash and leading zeros removed) and form (dash, `$`, `,`, `%` removed, zeros kept), so same product can be stored/matched under two UPCs. Import validates case pack with cleaned string but then calls `int.Parse` on raw value, so value such as `1,200` passes validation and throws. Import does not map `UNFICode`. Export: `WHERE ... AND pl."BrandID" = @BrandID` turns price join into inner join, so products without price rows not exported; and `QueryHelper.GetSearchCondition` returns fragment ending in `AND` that export query appends after another condition without leading `AND`, yielding invalid SQL when any filter sent (web never sends filters). Template endpoint also serves `RetailerPromoRules` (owned by CRM promo rules).

#### 2.5.2.4 Products for a banner SKU picker [Active]
- For a banner, lists every product of brand with `ShouldBeDisabled = true` when it already has a banner SKU on that banner. Used by CRM banner SKU add dialog (web `BannerSKUAddOrEdit.tsx`, admin `AddBannerSku.tsx`).
- API: `GET /api/v1/productspecs/for-bannerSku/{bannerID}` (`Authorize`; handler `DemandAnyModuleAsync(BannerProducts = distributors, retailers, View)`), path `bannerID` / `ProductForBannerSKUDTO` (`Products[{ID, Name, ShouldBeDisabled}]`).
- Gotchas: web calls `.../for-bannersku/...` (lower case); routing case-insensitive.

### 2.5.3 Price lists (pricing) [Active]
- Stores per-unit price a brand charges each distributor or delivery method for each product, with start date (`ValidFrom`), keeps promotion events priced from it. Managed on `/{brandID}/pricing` with `categories-products-pricing`; prices also created from promo product step (`ProductRow` > `PricingAddOrEdit`) and Simple Entries "Set price" (`AddPricingList`), gated by `PriceCreation` / `BrokerPromotionPlanning` slugs.
- User flow: `/{brandID}/pricing` loads `POST /api/v1/pricelists` with filters in body (`searchKeyword`) and `pageSize` (default `-1`, all rows), `currentPage`, `sortingOrder`, `sortKey` in query. Columns include product, category, distributor, per-unit price, case cost (`CasePack x PerUnitPrice`), valid-from. Pagination commented out on this page. Add opens `PricingAddOrEdit` (distributor from `useLeafDistributors`, product, per-unit price, valid-from, all required in UI) posts `POST /api/v1/pricelists/create` with `{ distributorID, productIDs: [id], perUnitPrice, validFrom: "YYYY-MM-DD" }`. Edit posts `POST /api/v1/pricelists/upsert` with `id`. Delete (with delete) sends `DELETE /api/v1/pricelists` `{ iDs }`. Upload, template, export in 2.5.3.2. From promo product row with no price, `PricingAddOrEdit` opens pre-filled with that product and distributor; after successful create invalidates `[getPromoBannerSkus, brandID]` so row updates.
- APIs (prefix `/api/v1/pricelists`): `POST /`, `GET /{id}`, `POST /upsert`, `POST /create`, `DELETE /`, `POST /by-distributor` (Partial), `POST /import`, `POST /export`, `GET /export-sample-file`.
- Business rules: `PerUnitPrice` may be null but not negative. Product must belong to brand and distributor linked to brand (`CRM.DistributorBrands`), else 404. Uniqueness: one row per (product, distributor, `ValidFrom` date), with "no date" counted as a value. Create skips duplicates per product; if every product skipped, 400 "No new pricing has been added ..."; partial success message names how many created. Upsert with an `ID` whose `ValidFrom` date changed does not edit row: inserts new row (after duplicate check) and keeps old one, building price history. Upsert with same date edits price in place and keeps `ValidFrom`. `upsert` takes singular `productID`; `create` takes `productIDs` (array). A singular key sent to `create` ignored by model binding and answered 400 "Please select at least one product." (`CreatePriceListRequestValidator`). List filters: `DistributorIDs`, `ProductIDs`, keyword over product, category and distributor names; price range applies only when both min and max sent. `StartDate` and `CategoryIDs` accepted but not applied (controller does not pass `CategoryIDs`; no `StartDate` condition in `QueryHelper.GetSearchConditionForPriceList`).
- Gotchas: web form requires non-zero price (`!formData.perUnitPrice`), so price of 0 cannot be entered although API allows it (`PricingAddOrEdit.validateForm`). `CheckAlreadyExistsAsync`, `CreatePriceListRequestHandler` and import load every price row in DB and filter in memory. Deleting a price does not reprice events that used it.

#### 2.5.3.1 Event repricing on price change [Active]
- When a price is created or its value changes, approved promotion events (`TradeSpend.TradeSpendPromoEvents`) and sandbox events (`TradeSpendSandbox.PromotionalEvents`) of that brand, product and distributor that start on or after price's `ValidFrom` take the price in force at their start date.
- Code map: `SharedDataService.UpdatePromoEventsPerUnitPrice` (picks latest row with `ValidFrom <= event start`; falls back to new price for events on or after new start date; bulk updates changed events); `UpsertPriceListRequest.cs`, `CreatePriceListRequest.cs` (callers).
- Business rules: only rows with both `ValidFrom` and `PerUnitPrice` count; with no such row call does nothing. Upsert calls it after saving; row without `ValidFrom` passes `DateTime.MaxValue`, so no event touched.
- Gotchas: `CreatePriceListRequestHandler` calls repricing inside product loop before `BulkInsertAsync` writes new rows, so service reads price rows not yet including new price: events get older price when one exists, and nothing changes when none exists. Price import (brand and admin) never reprices events; admin sync below is catch-up.

#### 2.5.3.2 Price import, export and template [Active]
- CSV import of new price rows matched by product name and distributor name, CSV export of filtered list, empty template.
- User flow: Upload posts to `POST /api/v1/pricelists/import`; template via `GET /api/v1/pricelists/export-sample-file` (`useGetFileForPriceList`); Export (with export) calls `POST /api/v1/pricelists/export` with current filters in body (`PriceListService.exportPriceLists`, file name "Prices").
- APIs: `POST /api/v1/pricelists/import`, `POST /api/v1/pricelists/export`, `GET /api/v1/pricelists/export-sample-file`.
- Business rules: import only inserts; row matching existing (product, distributor, date) fails "Record with the same value already exists!". Price accepts leading `$`; dates accept `M/d/yyyy` and two-digit-year variants.
- Gotchas: distributor matching strips non-alphanumeric characters from stored names but not from CSV value, so name such as "KeHE Distributors, LLC" in file never matches (`GetSystemDistributorsAsync`). Imported rows get no `CategoryID` (computed but not assigned), so invisible to category-scoped logic such as category delete check and remove-from-category cleanup. Products matched by exact name (case-insensitive), not UPC.

#### 2.5.3.3 Prices grouped by distributor [Partial]
- Backend only; no caller in web or admin.
- API: `POST /api/v1/pricelists/by-distributor` (`RequireModule(categories-products-pricing, null, View)`), body `GetPriceListPayload`, query paging, `sortKey` (`DistributorName` or `ProductCount`) / `PagedData<PriceListGroupedByDistributorDTO>` (`DistributorID`, `DistributorName`, `ProductCount`).
- Gotchas: shared keyword condition references `ct."Name"`, but this query has no `ct` join, so any `searchKeyword` should make PostgreSQL reject the query (not executed during review).

#### 2.5.3.4 Admin event price sync [Partial]
- Backend only: no caller of `admin/data-cleanup/sync-per-unit-price` in admin or web; Platform Admin can call directly.
- What it does: reprices every non-deleted approved and sandbox promotion event from price list in one pass. Sandbox events find distributor through `CRM.DistributorBanners` (first distributor per brand and banner).
- API: `POST /api/v1/admin/data-cleanup/sync-per-unit-price` (`MustHavePermission(Clean, DataCleanup, Admin)`), none / `ResponseMetaDTO` "Pricing synchronization for events completed successfully." (`SyncPricingsOfEventsRequestHandler` calling `SharedDataService.SyncPerUnitPriceAsync`).
- Gotchas: loads all events and all price rows of platform into memory in a request thread.

### 2.5.4 Admin cross-brand product data [Active]
- Platform Admin browses categories, prices and products across all brands with faceted filters, creates/edits them for chosen brand, bulk imports/exports through Data Upload controller. Admin sidebar "CRM Data Upload" > Categories, Price Lists, Product Specs.
- User flow: `/category` (`CategoryTable`): `POST /api/v1/categories/for-admin` with brand ids, query, category and brand name filters; Add/Edit (`AddCategory`) calls `POST /api/v1/categories` with `BrandID` and `OrganizationID` headers set to chosen brand (`brandSupportHeaders`); Upload posts to `POST /api/v1/masterdataupload/categories`; Export posts `POST /api/v1/masterdataupload/categories/export`. `/price-lists` (`PriceListsTable`): `POST /api/v1/pricelists/for-admin` and `POST /api/v1/pricelists/filter-options`; Add (`AddPriceList`) loads brand's products (`POST /productspecs`) and leaf distributors and calls `POST /pricelists/create` (new) or `POST /pricelists/upsert` (edit) with support headers; Upload `POST /api/v1/masterdataupload/price-list`; Export `POST /api/v1/masterdataupload/price-list/export`. `/product-spec` (`ProductSpecTable`): `POST /api/v1/productspecs/for-admin` and `POST /api/v1/productspecs/filter-options`; Add (`AddProductSpec`) loads brand's categories (`GET /categories`) and calls `POST /productspecs/upsert`; Upload `POST /api/v1/masterdataupload/productspecs`; Export `GET /api/v1/masterdataupload/productspecs?brandID=` (only when exactly one brand filtered). Templates from `GET /api/v1/masterdataupload/sample-file?fileCategory=` (Data Upload module).
- APIs: `POST /api/v1/categories/for-admin`, `POST /api/v1/categories/filter-options`, `POST /api/v1/pricelists/for-admin`, `POST /api/v1/pricelists/filter-options`, `POST /api/v1/productspecs/for-admin`, `POST /api/v1/productspecs/filter-options`, `POST /api/v1/masterdataupload/categories`, `POST /api/v1/masterdataupload/categories/export`, `POST /api/v1/masterdataupload/price-list`, `POST /api/v1/masterdataupload/price-list/export`, `POST /api/v1/masterdataupload/productspecs`, `GET /api/v1/masterdataupload/productspecs`.
- Business rules: admin create/edit go through brand endpoints of 2.5.1-2.5.3 under support access: admin sends `OrganizationID` = brand ID, and brand's own module assignment applies (403 when `categories-products-pricing` off for that brand; `crmDataUpload.helper.ts`). Facet endpoints compute each facet ignoring its own selection. Admin product import matches brands by name and products by raw UPC, allows missing category, creates blank price rows but no banner SKUs.
- Gotchas: `ProductSpecSummaryDTO.Disabled` never selected by admin product query, so admin "Status" column always shows Active. `POST /categories/filter-options` has no admin caller; category brand filter uses `GET /brands` instead. Admin product export ignores multi-brand, category and search filters (legacy GET endpoint takes one `brandID`, per comment in `ProductSpecTable.handleExportProducts`). Products created by admin import get no banner SKUs, unlike brand-side create and import. `BrandPriceListImportRequest` / `BrandPriceListExportRequest` in `DataUpload/.../ProductSpec/` have no controller action.
