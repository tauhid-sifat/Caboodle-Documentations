# Module 2.7 — Promotional Calendars & Management (code-verified)

Source of truth: `docs/feature-context.md` §2.7. Self-sufficient reproduction (condensed to verified facts; full SQL/handler detail in source).

## Purpose
Read and bulk-update surfaces over Brand Approved promotion events (`TradeSpend.TradeSpendPromoEvents`). Brands get the "Promo at a glance" calendar (one row per banner, twelve month columns of event-name chips) plus a free-text notes grid. Brokers get "Promotional Management": the same calendar across every brand they can access (one row per brand x distributor x banner x category x promotion type), a read view of the brands' notes, and their own spreadsheet-like custom note tabs ("Promo Tabs"). All calendars support a chip drill-down, bulk event-status and submission-status writes, a synchronous chip CSV and an asynchronous whole-calendar CSV export job.

## Shared data models
- `TradeSpend.TradeSpendPromoEvents` (`TradeSpendPromoEvent`): `BrandID`, `TradeSpendPromoID`, `RetailerID`, `DistributorID`, `BannerID`, `ProductID`, `CategoryID`, `EventName`, `Month` (int, 0 for EDLP), `StartDate`, `EndDate`, `PromotionType?` (Regular = 1, EdlpOnly = 2), `Status` (`PromotionEventStatus`: 1 Active, 2 Cancelled, 3 Pending, 4 Did Not Run, 5 Declined, 6 Retailer Approved, 7 Completed), `IsSubmitted`, `CreatedBy`, money fields. Owned by 2.6; this module reads it and writes only `Status`, `IsSubmitted` and audit stamps.
- `TradeSpend.TradeSpendPromoNotes` (`TradeSpendPromoNote`): `BrandID`, `Year?`, `Title`, `January`..`December` (free text), `IsSubmitted`, `Meta`.
- `Broker.PromoTabs`, `Broker.PromoTabColumns`, `Broker.PromoTabRows`, `Broker.PromoTabCells` (see 2.7.5).
- `DataHub` `ExportJob` rows (ModuleType 35 broker, 38 brand), shared with other exports.

## Shared services
- `PromoEventVisibility.BuildCondition` (`Shared/.../Helper/PromoEventVisibility.cs`): EXISTS predicates requiring event's retailer, distributor-banner mapping, banner, banner SKU, product and category to be live for the event's own brand. Appended to every read, export and status write in this module.
- Brand filter SQL: `PromosAtAGlanceEventFilter` (`.../PromosAtAGlance/PromosAtAGlanceEventFilter.cs`). Broker filter SQL and group paging: `PromotionalManagementEventQuery` (`.../PromotionalManagement/PromotionalManagementEventQuery.cs`).

- Web: `useAsyncExportJob` + `asyncExportJob.helpers.ts`; `UpdateEventStatusControl` + `eventStatus.helper.ts`; drill-down grid `PromoEvents` (documented in 2.6).

## Feature inventory (summary; full detail in source §2.7)

### 2.7.1 Brand Promotional Calendar (Promos at a Glance) [Active]
- Brand-scoped calendar of Brand Approved promotion events for one year: one row per banner, twelve month columns, each cell a list of chips grouped by event name and event status, with count badge and green "submitted" tag. EDLP events (`Month = 0`) appear in every month column. Used by Brand organizations (module `promotional-calendar-view`, brand slug, broker slug `null`); Brokerage acting on connected brand route passes same brand slug (`AccessContext.ModuleRefusal`, `brokerageUsesBrandSlug: true`).
- User flow: Nav "Promotional Planning > Promotional Calendar" opens `/{brandID}/promotional-calendar` (gate `promotional-calendar-view`). Layout titled "Promo at a glance" shows two tabs: Promotional Calendar and Notes. Year starts at current calendar year and snaps back when cleared (`resolvePromoCalendarYear`); other filters in drawer (2.7.1.1). Filters debounced before querying. Grid loads `POST promos-at-a-glance` with paging on query string; `rowKey` is `bannerID`; `PaginationComponent` pages banners. Clicking chip opens drill-down modal (2.7.1.2) with status update (2.7.1.3) and chip CSV. Toolbar: Submit and Revoke (`update` action) open scope menu then confirmation (2.7.1.4); Export (`export` action) starts async job (2.7.1.5). Controls hidden while access loads and when action missing. Empty states: banner with no chips still renders as row (handler emits every banner on page).
- APIs: `POST /api/v1/tradespends/promos-at-a-glance` (plus filters, events, events/export, event-status, submission-status, export, export/{jobId}/status in sub-features).
- Business rules: brand from `IAccessContext.GetActiveBrandIdAsync` (BrandID header), never body. Only events with `Deleted = FALSE`, `PromotionType IS NOT NULL` and passing `PromoEventVisibility` count. Month filter always adds month 0 so EDLP events survive; EDLP chips copied into every month column month filter allows. `year` matches when event's start or end year equals it; omitted year merges all years into twelve columns (web always sends one). Distributor filter matches `COALESCE(parent.ID, d.ID)` (same value facet returns); category filter matches event's own `CategoryID`; region filter inner-joins `CRM.RetailerRegions` + `CRM.Regions`. Banner paging orders by banner name then id; final rows re-sorted by banner name.
- Gotchas: SQL fragments interpolate GUID and month lists into query string (`PromosAtAGlanceEventFilter.BuildCondition`); safe only because values typed `Guid`/`Month`. `PromotionalCalendarLayout.tsx` leaves `console.log(pathname...)` and shows both tabs regardless of module access; route guard enforces notes gate on navigation. Legacy region name "Promo At a Glace" (typo) in controller.

#### 2.7.1.1 Brand calendar filter facets [Active]
- Returns filter options still valid for current selection; each dimension narrowed by every other selected dimension but never by its own. Dimensions: Category, Retailer, Banner, Distributor, Region, Created By, Month, Year.
- API: `POST /api/v1/tradespends/promos-at-a-glance/filters` (`RequireModule(promotional-calendar-view, null, View)`, `BrandID` header) → `BrandPromotionalManagementFilterDTO`.
- Business rules: distributor facet returns parent distributor when one exists; Years collects both start and end years; options sorted by name.
- Gotchas: whole brand event set loaded into memory per call; cost grows with event count.

#### 2.7.1.2 Brand chip drill-down and chip CSV [Active]
- Clicking a chip lists every event behind it (SKU, retailer, dates, allowances, status) in shared `PromoEvents` AG Grid; "Export promo event" downloads same rows as CSV.
- APIs: `GET /api/v1/tradespends/promos-at-a-glance/events`, `GET /api/v1/tradespends/promos-at-a-glance/events/export`.
- Business rules: match on brand, event name, banner, and `Month = @Month OR PromotionType = EdlpOnly`; `year` and `eventStatus` applied only when sent (omitting either returns superset). Drill-down does not require `PromotionType IS NOT NULL` (returns `COALESCE(PromotionType, 0)`). Validators require banner, month and event name. CSV with no rows throws 400 "No promotional events found."; web shows as info "Nothing to export" (`isPromoCalendarNoEventsError`).
- Gotchas: drill-down subquery pages without `ORDER BY` (`GetEventsWithSameEventNameRequest.GetQuery`), so any page size other than -1 non-deterministic. `DistributorID`/`DistributorMarkup` come from `CRM.DistributorBanners` matched on banner + brand only, so with several distributors on one banner a `DISTINCT ON` picks one arbitrarily, not necessarily the event's own distributor (same pattern in CSV, which inner-joins `DistributorBanners` and uses product's category).

#### 2.7.1.3 Brand bulk event status update [Active]
- Sets `PromotionEventStatus` on drill-down rows user ticked. Picker options from enum; confirmation states count and target status; outcome reported as success, partial warning, or info on 404.
- API: `PATCH /api/v1/tradespends/promos-at-a-glance/event-status` (`RequireModule(promotional-calendar-view, null, Update)`, `BrandID` header) → `UpdateEventStatusResponseDTO` (`message`, `requestedCount`, `updatedCount`).
- Business rules: validator: non-empty ids, no empty GUID, status in enum. Ids outside brand or failing visibility skipped silently; `requestedCount` counts distinct ids. Bulk write bypasses EF audit interceptor, so `LastModifiedBy/On` stamped by hand. Web invalidates calendar and drill-down only on success.
- Gotchas: no transition rules server-side; any status can be set from any status.

#### 2.7.1.4 Brand submission status (Submit / Revoke) [Active]
- Sets `IsSubmitted` true (Submit) or false (Revoke) on every event matching chosen scope: All data (year only), Filtered data (current filters), Current page (current filters + `bannerIDs` of banners on screen).
- API: `PATCH /api/v1/tradespends/promos-at-a-glance/submission-status` (`RequireModule(promotional-calendar-view, null, Update)`, `BrandID` header) → `ResponseMetaDTO`.
- Business rules: matching ids from same `PromosAtAGlanceEventFilter` SQL and visibility rule; single `UPDATE` sets `IsSubmitted`, `LastModifiedBy`, `LastModifiedOn` scoped to header brand. "Current page" expressed as `bannerIDs` because brand row is exactly one banner. "All data" keeps selected year on purpose; year is context, not filter.
- Gotchas: response message same whether zero or all rows changed; web never patches optimistically and relies on invalidated calendar.

#### 2.7.1.5 Brand calendar async export (ModuleType 38) [Active]
- Queues background CSV of every event (one row per event) matching a scope; page polls status and offers download URL.
- User flow: Export menu (All data, Filtered data, Current page) calls `usePromoAtAGlanceExport().start`; job id stored in `sessionStorage` key `promo-at-a-glance-export-job` and polled every 2500 ms by `useAsyncExportJob`; `ExportStatusUI` shows progress, empty-result note or download link.
- APIs: `POST /api/v1/tradespends/promos-at-a-glance/export`, `GET /api/v1/tradespends/promos-at-a-glance/export/{jobId}/status`.
- Business rules: paging applied only when both `pageSize > 0` and `currentPage` sent (`BuildBannerPageCondition`); web omits both for All/Filtered (`buildPromoCalendarExportPaging`). Status lookup requires job's module type, active brand and creator to match caller, else 404 "Record not found." Zero matches completes with `Promotional_Events_Empty.csv`, no S3 key and no download URL (web `isAsyncExportEmptyResult`); exceptions mark job Failed with message. Web treats 404 (clears stored id) and 403 as terminal and resumes polling after reload only once session token exists.
- Gotchas: whole CSV built in `MemoryStream` before upload (memory grows with row count). Row projection inner-joins `CRM.DistributorBanners` on banner + brand only and takes category from product (`ct.ID = p.CategoryID`), unlike filters (event category) and broker export.

#### 2.7.1.6 Legacy promotion event filters [Deprecated]
- Gated to Platform Admin `UnusedEndpoints`; no web caller; replaced by 2.7.1.1. Returns banners, regions and all months for brand read from `ICurrentUser.GetBrandID()`.
- API: `GET /api/v1/tradespends/promos-at-a-glance/events/filters` (`MustHavePermission(Execute, UnusedEndpoints, Admin)`) → `PromotionEventsFilterDTO`.

### 2.7.2 Brand Promotional Notes [Active]
- Brand's free-text planning grid: each note has Title, Year, twelve month text cells and `IsSubmitted` flag. Brand users edit cells inline; same notes read cross-brand by brokers in 2.7.4. Module `promotional-calendar-notes` (brand slug only; actions View, Create, Update, Delete, Export).
- User flow: `/{brandID}/promotional-notes` (Notes tab of "Promo at a glance" layout; route gate `promotional-calendar-notes` in `BRAND_ROUTE_MODULES`). Grid loads `GET promos-at-a-glance/notes` sorted by Title ASC, page size `PAGE_SIZE`; year picker and filter drawer (`PromoNotesFilter.tsx`: title search, submitted, months) narrow it. "Add New Note" (Create) immediately POSTs empty note; editing a cell (Update) POSTs whole row with its `id`. "Delete" per row (Delete) asks Popconfirm, then DELETEs that id. Export (Export) downloads "Promo Notes.csv". Without Update grid renders read-only columns; without Delete Action column dropped.
- APIs: `GET /api/v1/tradespends/promos-at-a-glance/notes`, `POST /api/v1/tradespends/promos-at-a-glance/notes`, `DELETE /api/v1/tradespends/promos-at-a-glance/notes`.
- Business rules: upsert: Create demanded when `id` absent, Update when present (route attribute only checks View); id missing/deleted/belongs to another brand 404 "Promo note not found"; all text trimmed; `Year` defaults to server's current year (`DateTime.Now.Year`). List: `title` is `ILIKE %title%`; `months` returns only selected month columns and keeps notes with at least one non-blank; `years` is `Year IN (...)`; `sortingOrder` falls back to ASC; `sortKey` must name a `TradeSpendPromoNote` property (case-insensitive), else `Title`. Delete: soft delete (`Deleted`, `DeletedBy`, `DeletedOn`) limited to header brand; empty `iDs` 400 "Please select a record to delete from the list".
- Gotchas: upsert success messages swapped (update returns "Promotion Note created successfully", create "Promotion Note updated successfully"). `sortKey` validated case-insensitively but inserted verbatim into quoted identifier, so lower-case key such as `title` would reference non-existent column; web always sends capitalised keys. Delete reports success even when zero rows matched (only singular vs plural depends on count). "Add New Note" persists empty note before user types anything.

#### 2.7.2.1 Brand notes CSV export [Active]
- Downloads notes grid as "Promotion Notes" CSV (`BrandPromoNotesExportDTO`: Title, Year, month columns, BrandID, IsSubmitted).
- API: `GET /api/v1/tradespends/promos-at-a-glance/export-for-brand` (`RequireModule(promotional-calendar-notes, null, Export)`, `BrandID` header) → CSV stream (declared `PagedData<TradeSpendPromoAtaGlanceNoteDTO>`).
- Business rules: same filters and sort as list, handler applies `PagingHelper.GetDataRange(PageSize, CurrentPage)`.
- Gotchas: web (`PromoService.exportPromoAtAGlanceNotes`) sends grid's `filter` object through `new URLSearchParams(filter)`, which includes `pageSize`/`currentPage`, so file holds only current page; arrays become comma string (`months=1,2`) and cleared year becomes string `null`, which ASP.NET cannot bind to `IList<int>` (likely 400 from `ValidationErrorHelper`; not executed). List uses `getFilterParamString`, which repeats keys correctly.

### 2.7.3 Broker Promotional Management calendar [Active]
- Broker's cross-brand calendar of Brand Approved events. One row per (brand, distributor, banner, category, promotion type) group; columns Brand, Distributor, Banner, Category plus twelve month columns of chips (event name, event status dot, count, submitted tag). Scope is every brand on which caller holds `promotional-management-events` with needed action (`AccessContext.BrandsInScope`), optionally narrowed by `brandIDs`. Used by Brokerage organizations (broker slug `promotional-management-events`, `CrossBrand = true`).
- User flow: Nav "Strategy > Promotional Management" or broker dashboard tile opens `/promotional-management` (route and nav gate on parent slug `promotional-management`, `BROKER_ROUTE_MODULES` and `buildBrokerNavItems`). Page shows notes tab strip (2.7.4, 2.7.5) above calendar card. Filters start empty (no year, so all years share twelve columns) and debounced; while change waits for debounce grid shows loading state over previous rows. Toolbar: Submit, Revoke (shown when `anyBrandCan(promotional-management-events, "update")`), Export (when `export`), Filter drawer (`PromotionalMangementFilter.tsx`), status legend, `PaginationComponent`. Chip (antd `Tag` with `role="button"`, keyboard Enter/Space) opens "Promo Events" modal: `PromoEventChipSummary` header, status control and "Export promo event", then `PromoEvents` grid with `showPromotionType` and `viewBrandId` set to row's brand.
- APIs: `POST /api/v1/brokers/promotional-management-events` (plus filters, events-with-same-name, export-events, event-status, submission-status, export, export/{jobId}/status in sub-features).
- Business rules: brand set = `BrandsInScope(promotional-management-events, View)` intersected with `brandIDs` when sent; empty set returns empty page, never error. Groups are `GROUP BY BrandID, DistributorID, BannerID, CategoryID, PromotionType`, ordered by brand name then ids, paged with `PagingHelper`. Filter semantics match brand side (month 0 kept, year on start or end, distributor via `COALESCE(parent.ID, d.ID)`, category on event column, region via `RetailerRegions`), plus `PromotionType IS NOT NULL` and `PromoEventVisibility`. Regular groups take chips for their month; EDLP groups get all their chips in every month column month filter allows. Web row key composite of displayed identity (brand, distributor, banner, category, id or name fallback, blanks kept), with positional `row-N` key for repeats (`buildPromoGroupRowKeys`), so filter change replaces rows instead of appending.
- Gotchas: route gated on parent catalog slug `promotional-management`, while every endpoint checks child slugs; payload granting only children would hide page. Calendar section rendered for anyone reaching route; only action buttons gated. A user without events View gets server's 403 on list. Groups include `PromotionType`, but ordering keys do not, so two groups differing only by type have no stable relative order across pages. Default broker filters carry no year, unlike brand calendar which always sends one.

#### 2.7.3.1 Broker calendar filter facets [Active]
- Faceted options for Brand, Retailer, Banner, Distributor, Category, Region, Created By, Month, Year; each dimension ignores its own selection. Dimension whose options drop to zero renders disabled with "No data" unless it still holds a selection (`isPromoFilterDimensionDisabled`).

#### 2.7.3.2 Broker chip drill-down and chip CSV [Active]
- Lists events behind a chip and exports them as CSV ("{eventName} Promotional Management").
- APIs: `GET /api/v1/brokers/events-with-same-name`, `GET /api/v1/brokers/export-events`.
- Business rules: validators require brand, banner, category, distributor, valid month and non-blank event name (400 texts such as "Brand is required."). Brand must be in accessible set: list returns empty page, CSV throws 400 "No promotional management events found.". Match on four ids, event name, and `Month = @month OR (EDLP AND Month = 0)`; `year` and `eventStatus` only when sent. CSV reuses `PromotionalManagementExportQuery.BuildExportQueryForEventIds` so columns equal async export's. Web serialises both calls through one `toSameNameQuery` and omits absent `year`/`eventStatus`.
- Gotchas: drill-down key has no retailer or region, so chip can list events from other retailers/regions of same group. CSV projection joins `CRM.DistributorRetailers` on retailer + brand without distributor, so `DistributorMarkup` in file can differ from drill-down (which matches distributor). CSV fetched with raw `fetch` (`fetchWithMock`) and hand-built `authorization` header.

### 2.7.4 Promotional Management Notes, "Brand's Notes" tab [Active]
- Read-only, cross-brand view for brokers of notes brands write in 2.7.2. First, pinned tab of Notes tab strip on `/promotional-management` (tab key `BRAND_NOTES_TAB_KEY`, never renamed, deleted or reordered). Module `promotional-management-notes` with `CrossBrand = true` (brand scope = brands on which caller holds notes module).

#### 2.7.4.1 Brand's Notes facets [Active]
- Brands, years (descending) and months that still have notes for current Title, Submitted, Year and Month selection; each of Brand, Year, Month ignores its own selection. Only source for Brands dropdown.
- API: `POST /api/v1/brokers/promos-at-a-glance/notes/filters` (`RequireModule(null, promotional-management-notes, View, CrossBrand)`) → `BrokerPromoAtaGlanceNotesFilterDTO` (`brands`, `years`, `months`).
- Business rules: all accessible notes loaded, then title (case-insensitive contains) and submitted applied in memory before faceting; a month counts when its text non-blank.

#### 2.7.4.2 Brand's Notes CSV export [Active]
- CSV "Promotional Management Notes" (`PromoNotesExportDTO`), every matching note ordered by brand name, no paging.
- API: `GET /api/v1/brokers/promos-at-a-glance/notes/export` (`RequireModule(null, promotional-management-notes, Export, CrossBrand)`) → CSV stream (`FileExportDTO`).
- Business rules: brand set uses Export action; `sortingOrder` accepted but ignored (fixed `ORDER BY b."Name" ASC`). Web calls with raw `fetch` and `getFilterParamString` (`PromotionalManagementService.exportPromoNotes`).

### 2.7.5 Promo Tabs (broker custom notes tabs) [Active]
- Spreadsheet-like tabs owned by a brokerage organization, shown after "Brand's Notes" in Notes tab strip on `/promotional-management`. Each tab starts with twelve Text month columns; users add typed columns (Text, Number, Currency, Percent, Date, CustomList, Checkbox), add rows, edit cells inline, filter per column (value checklist + condition), sort, page and export to CSV. Module `promotional-management-notes` checked at organization level (`RequireModule(..., OrganizationLevel = true)`, brokerage's company access); actions View, Create, Update, Delete, Export. Brand org refused (`PromoTabOwnership.GetOwnerAsync` throws "This module is not available to your organization.").
- User flow: `PromoNotesTabs.tsx` reads `useAccess()`; tabs render only when company access grants `view` (`canUsePromoTabs`), and each control follows `resolvePromoTabPermissions` (`promoTabsPermissions.helper.ts`), denying everything while access loads. "New tab" (create) POSTs with no name; server names it "New Tab N" and new tab opens (created tab written into tabs cache before refetch). Tab kebab: Rename (update), Delete (delete) via modal outside dropdown; tabs drag to reorder (delete action, `PUT tabs/order`). Inside tab (`PromoTabGrid.tsx`): "+ Column" opens `PromoTabColumnModal.tsx` (type locked when editing; disabled at 20 columns); header menu sorts, filters (`PromoTabFilterPanel.tsx`), renames, inserts and deletes columns; headers drag to reorder (update). "Add row" (create) appends empty row to cached page; cells edit inline by type (`PromoTabCell.tsx`: Input, InputNumber, DatePicker, Select for CustomList, Checkbox); saving optimistic with rollback on error (`useSavePromoTabCell`). Row delete via Popconfirm (delete); Export (export) downloads `{tab name}-{yyyyMMdd-HHmm}.csv`. If open tab disappears (deleted here or by teammate), strip falls back to "Brand's Notes" once tabs refetch settles.
- Data: schema `Broker` (migration `20260911164320_PromoTabTablesAdded.cs`): `PromoTabs` (`BrokerID` brokerage org id, `Name`, `NameKey` normalized unique per broker among non-deleted, `DisplayOrder`); `PromoTabColumns` (`TabID`, `Name`, `NameKey` unique per tab, `ColumnType` PromoTabColumnType 5 Text, 10 Number, 15 Currency, 20 Percent, 25 Date, 30 CustomList, 35 Checkbox, `DisplayOrder`, `Options` list); `PromoTabRows` (`TabID` + audit; index on `TabID, CreatedOn`); `PromoTabCells` (`RowID`, `ColumnID` unique per row+column among non-deleted, `ValueText`, `ValueNumber` decimal, `ValueDate` date at midnight UTC, `ValueBool`; indexes per value column). All four soft-deleted (`AuditableEntity`). Enums in `PromoTabEnums.cs` (`PromoTabFilterMode` 5 None, 10 Include, 15 Exclude; `PromoTabFilterOperator` 5 Contains to 40 Before).
- APIs: 16 endpoints listed under 2.7.5.1–2.7.5.6 (all `RequireModule(null, promotional-management-notes, <action>, OrganizationLevel)`, no `BrandID`).
- Business rules: ownership: `BrokerID` is caller's `OrganizationId`; every tab/column/row/cell id outside it 404. Names: trimmed, max 100 chars, must contain letter or digit; duplicates compared on `NameKey` (`CategoryReviewTextHelper.NormalizeKey`). Body id keys carry uppercase `ID` suffix (`tabID`, `columnID`, `rowID`, `tabIDs`, `columnIDs`); row delete body key is `iDs`.
- Dependencies: IAM company access (`OrganizationLevel`), module setting "Columns per Promo Tab" (`ModuleSettingCatalogSeedData.cs`, number 12 to 100, default 20), Category Review text helper, `Identity.Users` for names.
- Gotchas: web caps columns at constant `PROMO_TAB_MAX_COLUMNS = 20` (`promoTabs.interface.ts`, `canAddPromoTabColumn`), while server reads brokerage setting (12 to 100). A brokerage set above 20 cannot add columns 21+ from UI; one set below 20 sees enabled button server rejects. Multi-step writes not transactional: tab insert then bulk insert of twelve columns (`CreatePromoTabRequestHandler`); column order shift then insert; delete-tab cascades as three separate UPDATEs. Existing tabs created before IAM stored broker owner's user id in `BrokerID`; still match because org backfill reuses broker user id as brokerage id (`backfill_broker_org` in `OrganizationBackfillSql.cs`), except for merged brokers (`MergeFrom`/`MergeInto`), whose tabs no longer match. `useGetPromoTabs` fires `GET tabs` for any signed-in user on page even when `canUsePromoTabs` false (expected 403 for users without module). On master same feature still uses `PromoTabAccessHelper` (broker user id, sub-users resolve to `ParentBrokerID`, owner-only destructive actions; CS-1791/CS-XXXX changed it there). Working branch replaced with `PromoTabOwnership` and module actions, so merging needs care.

#### 2.7.5.1 Tabs [Active]
- APIs: `GET/POST/PUT/DELETE /api/v1/brokers/promotional-management-notes/tabs` (and `PUT .../tabs/order`).
- Business rules: blank name generates next free "New Tab N", retrying up to 3 times on unique-index race; new tab gets `DisplayOrder = max + 1` and twelve Text month columns. Reorder needs exactly broker's full tab set (no duplicates, nothing missing or foreign). Delete soft-deletes tab, then its columns, cells and rows by set-based SQL. Reordering tabs needs Delete, unlike columns (Update). Duplicate name 400 "A tab with the same name already exists."; 3 failed name generations 400 "Could not create a tab right now. Please try again."

#### 2.7.5.2 Columns [Active]
- APIs: `POST .../tabs/{tabId}/columns`, `PUT .../tabs/{tabId}/columns/order`, `PUT .../columns/{columnId}`, `DELETE .../columns/{columnId}`.
- Business rules: column count limited by brokerage setting (fallback 20, includes month columns); `position` is 0-based insert index (out of range appends) and shifts later columns. CustomList needs 1 to 100 unique, non-blank options of at most 200 chars; options sent for other types dropped. Column type immutable (sending different `columnType` 400). Editing options never rewrites existing cells. Column order must list every column of tab exactly once. Delete refuses last column, soft-deletes its cells and renumbers rest.

#### 2.7.5.3 Rows and cells [Active]
- APIs: `POST .../tabs/{tabId}/rows/list`, `POST .../tabs/{tabId}/rows`, `PUT .../rows/{rowId}/cells/{columnId}`, `DELETE .../rows`.
- Business rules: default order newest row first; with `sortColumnID` blanks sort last in both directions, then creation order. `pageSize -1` returns all rows. Blank cell is absence of row in `PromoTabCells` (omitted from `cells`); null, empty string or unticked checkbox clears cell. Parsing per type: Text max 1000 chars; CustomList must match option (case-insensitive); numbers accept JSON numbers or invariant strings without symbols; dates accept `yyyy-MM-dd` or `M/d/yyyy`-style; checkbox accepts booleans or "true"/"false". Dates returned as `MM/dd/yyyy`. Saving cell always stamps row's `LastModifiedBy/On`. Row delete all-or-nothing: any unknown, deleted or foreign id returns 404 listing ids and nothing deleted.
- Gotchas: two concurrent first writes to same empty cell can both try to insert and hit unique index `IX_PromoTabCells_RowID_ColumnID` (unhandled `DbUpdateException`, not verified at runtime).

#### 2.7.5.4 Bulk cell save (paste) [Partial]
- Backend and `PromoTabsService.savePromoTabCells` exist; no hook or component calls it.
- API: `PUT /api/v1/brokers/promotional-management-notes/rows/{rowId}/cells` (`RequireModule(null, promotional-management-notes, Update, OrganizationLevel)`) → `PromoTabRowDTO`.
- Business rules: every value parsed before any write; one bad value or repeated/foreign column rejects batch; inserts, updates and soft deletes through `IBulkRepository`.

#### 2.7.5.5 Column filters and value checklist [Active]
- Per-column filter panel: checklist of distinct values (with counts, search, separate blank count) in Include or Exclude mode, plus optional condition (operator by type), applied to rows list, values and export alike.
- API: `POST .../tabs/{tabId}/columns/{columnId}/values` (`RequireModule(null, promotional-management-notes, View, OrganizationLevel)`) → `PromoTabColumnValuesDTO` (`data` of `value`, `displayValue`, `count`; `meta`; `blankCount`).
- Business rules: filters for different columns ANDed; within column checklist and condition ANDed and `includeBlanks` (default true) ORs in rows with no cell. `mode` must be 5, 10 or 15 or omitted; any other int 400 (guards against silently inverting to Exclude). Exclude uses `IS NULL OR <> ALL(...)`. Operators: Contains/DoesNotContain on text types, Equals on all, GreaterThan/LessThan on numeric, Between on numeric and date (start must not exceed end), After/Before on date. LIKE metacharacters escaped. Values query drops column's own filter so value can always be ticked back; search matches display form (date as `MM/DD/YYYY`, checkbox as Yes/No).
- Gotchas: `mode: Include` with empty `values` list degrades to "has any value"; web blocks Apply in that state (`isPromoTabFilterDraftEmptySelection`). Web offers no condition operators for Checkbox columns (only checklist).

#### 2.7.5.6 Tab CSV export [Active]
- API: `POST .../tabs/{tabId}/export` (`RequireModule(null, promotional-management-notes, Export, OrganizationLevel)`) → CSV stream (`FileExportDTO`).
- Business rules: synchronous; all rows (`pageSize -1`) with grid's filters and sort; headers are column names in tab order; checkbox Yes/No; CsvHelper `InjectionOptions.Escape` neutralises leading `= + - @`; file name sanitized tab name (max 60 chars, fallback "Promo Tab") plus UTC timestamp. Web names download itself (`buildPromoTabExportFilename`) with local timestamp.

### 2.7.6 Shared async export job lifecycle (calendar exports) [Active]
- One client hook and one server pattern for two calendar exports (2.7.1.5 brand ModuleType 38, 2.7.3.5 broker ModuleType 35): start returns job id, client polls status every 2500 ms, Done job carries pre-signed S3 download URL.
- User flow: `start(scope, thunk)` calls module's start endpoint, stores job id in `sessionStorage` under module's key and begins polling. On reload hook resumes polling stored job once session token exists (status call without token would 401 and interceptor would sign user out). Terminal states: Done (download link, or empty-result note when Done with no URL), Failed, Cancelled; HTTP 404 clears stored id; 403 (another user's job or other module's route) stops polling. Interval cleared on unmount.
- Code map: `useAsyncExportJob.ts` (lifecycle), `asyncExportJob.helpers.ts` (`ASYNC_EXPORT_STATUS` 5/10/15/20/25, `isAsyncExportTerminal`, `isAsyncExportEmptyResult`, `resolveAsyncExportProgress`), `ExportStatusUI.tsx`, `ExportJobService.cs` (`ExecuteExportAsync` dispatch by `ModuleType`; two promo cases page event ids with keyset cursor (`ID > @lastProcessedEventId`, batch 10000), widen each batch to CSV rows, update `RowsExported`, upload, `Complete` or `Fail`).
- Data: `DataHub` `ExportJob` (`BrandID`, `ModuleType`, `RequestJson`, `Status`, `TotalRows`, `RowsExported`, `FileName`, `FileSize`, `S3Key`, `ErrorMessage`, `StartedOn`, `CompletedOn`, `CreatedBy`).
- APIs: four start/status endpoints listed in 2.7.1.5 and 2.7.3.5. Background: Hangfire job `IExportJobService.ExecuteExportAsync`. S3 prefixes `exports/promos-at-a-glance/{brandId}/` and `exports/promotional-management/{userId}/`.
- Business rules: id cursor advances from id page, not from returned rows, so batch whose rows dropped by joins cannot end export early (`PromosAtAGlanceExportQuery` and `PromotionalManagementExportQuery` summaries). Filters frozen in `RequestJson` at start.
- Gotchas: both CSVs written into `MemoryStream` before upload; very large exports hold whole file in API memory. Background CsvWriters and `FileExportHelper.ConvertToCsvFile` (used by chip and notes CSVs) set no CsvHelper injection escaping, so free text (event names, comments, notes) starting with `=`, `+`, `-` or `@` reaches spreadsheet unescaped; only Promo Tab export (`PromoTabCsvBuilder`) escapes it. No cancel endpoint for either promo export; hook exposes none.
