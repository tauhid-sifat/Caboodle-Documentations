# Module 2.10 — Data Uploads (code-verified)

Source of truth: `docs/feature-context.md` §2.10. Self-sufficient reproduction (condensed to verified facts; full SQL/handler detail in source).

## Purpose
Ingests distributor sales files (KeHE, UNFI), syndicated SPINS files (Item Ranking, Stores Insight) and the combined Distributor Sales Report file per brand; serves brand-facing report screens built on them; runs the chunked async import engine and async CSV export jobs those screens use; exposes platform-admin master data bulk import/export (CRM and product spec CSVs) and the admin data mapping table.

- Backend module: `Modules/DataUpload/Modules.DataUpload.Application/` (`Requests/{KeHE,UNFI,SPINS,DistributorSalesRecords,Mapping,Report Sync,MonthlyReport}`, `CRM/`, `ProductSpec/`, `Brand/`, `SampleFile/`, `Helper/`, `DTOs/`, `Services/IImportJobService.cs`) and `Modules.DataUpload.Domain/`.

## Feature inventory (summary; full detail in source §2.10)

### 2.10.1 Chunked async import engine [Active]
- Uploads large CSV in pieces to S3 multipart storage, tracks as `ImportJob`, runs import in Hangfire background job, lets client poll progress, counts, outcome and error-file link. Used by KeHE (2.10.2), UNFI (2.10.3), SPINS Stores Insight (2.10.5) and Distributor Sales Report file (2.10.6); Monthly Report actuals, Store List and Category Review reuse same `ImportJobService` from other modules. Access is provider's module `Import` action.
- User flow: user opens upload modal, picks `.csv` (client rejects other extensions). Client slices file into 5 MB pieces (`DEFAULT_CHUNK_SIZE`) and posts chunk 1 with `fileName`, `chunkIndex=1`, `chunkMax`, `fileSize` (whole file, first piece only) and raw bytes as body. Server creates `ImportJob` (status 7 Uploading) on first piece and returns `jobId`, `uploadId`, `key`, `etags`; later pieces send them back. Each failed piece retried up to 3 times with 1s/2s backoff on network or 5xx. On last piece server completes S3 object, checks real size, sets status 5 Pending and (KeHE, UNFI, SPINS) enqueues `IImportJobService.ExecuteImportAsync`; DSR flow instead calls separate start endpoint (2.10.6.1). Client polls status endpoint every 2s (every 4s while status 10 Processing) until terminal (15, 17, 20, 25). On 15 or 17 hook raises green "Import completed" toast (unless `suppressCompletionNotification`) and calls `onCompleted` with result snapshot; on 20 or 25 raises error toast. Modal shows upload and processing bars, row counts, "Download error file" link when `errorFileUrl` present and `failedRows > 0`.
- APIs: common contract `POST /api/v1/{kehe,unfi}/import/chunk`, `/api/v1/spins/import-stores-insight/chunk`, `/api/v1/distributorsalesreports/import/chunk`; `GET .../import/{jobId}/status`. Background job `IImportJobService.ExecuteImportAsync(jobId, brandId, userId, moduleType)` via `IJobService.Enqueue`.
- Business rules: chunk validators (`.csv` extension, `chunkIndex >= 1`, `chunkMax >= 1`, `chunkIndex <= chunkMax`) do not run: validation is MVC auto-validation of bound parameters only (`AddFluentValidation()` in `Program.cs`, no MediatR validation behavior), controllers build these requests by hand. `DataUploadSizeGuard.ReadPieceAsync` re-checks `fileSize >= 0`. `.csv` rule enforced only by web client. New job starts only when `chunkIndex == 1` and no `jobId`; later piece must name a job of same brand and `ModuleType`, else 404; neither case is 400 "Invalid request". Outcome: `null` while Pending/Uploading/Processing/Cancelled; Failed if status 20 or 0 success with failures; Success if 0 failures (including 0/0); PartialSuccess otherwise. `ImportJob.Complete` sets 17 PartiallyDone whenever `failedRows > 0`, so 17 can mean "every row failed". `errorFileUrl` presigned URL only when `FailedRows > 0` and error file exists. Status endpoints 404 a job of another brand or module type. KeHE and UNFI runners fail job with `StoreCleanupSyncGuard.CleanupRunningMessage` when store clean-up running; SPINS does not check.
- Gotchas: `IImportJobService.GetImportJobStatusAsync` and `CancelImportJobAsync` have no caller; each provider has own copy of status mapping and no cancel endpoint. UNFI and SPINS status handlers do not copy `SkippedRows`. `ModuleType` names reuse "Export" for imports (`KeHEExport`, `UNFIExport`, `SPINSExport`). Four chunk handlers near copies; fix must be applied to each.

#### 2.10.1.1 Brand data upload size limit [Active]
- Enforces brand setting "Largest data upload" (`data-upload-reporting` / `max-file-size-mb`, default no limit, 1 to 2048 MB) on KeHE, UNFI, SPINS and Distributor Sales uploads.
- Business rules: checked three times (`DataUploadSizeGuard`): declared `fileSize` and first piece before any job/object exists; running total on `ImportJob.FileSize` per piece; real S3 object size on last piece (object deleted, job failed). Refusal 400 keyed `File` with "Each KeHE, UNFI, SPINS or Distributor Sales file can be up to N MB." (`DataUploadSizeLimit.Message`). With no limit set, pieces streamed without buffering. SPINS Item Ranking single-shot import checks `file.Length` via `DemandSizeAsync`.
- Gotchas: none noted beyond the general chunk-handler copy issue.

### 2.10.2 KeHE data and reports [Active]
- Lets brand upload KeHE monthly sales CSVs and view KPI cards, charts and nine report grids built from raw `KeHeRecords` table, filtered by DC, retailer, product, state, city, category, sub-category, store and date range. Brand route `/{brandID}/kehe`, module slug `kehe` (`View`, `Import`, `Delete`; `Export` through async export job). Brand companies and brokerages with module on that brand (brokerage falls back to brand slug).
- User flow: open Reports hub "Data Upload Reporting", KeHE (or `/{brandID}/kehe`); `ModuleRouteGuard` checks slug `kehe`. Page loads Total Sales Dollars / Total Cases cards, sales chart and DC chart, then sections: DC Cases Sold, Sales Report (by month), Sales by Product, Chain (retailer), Store, Details, State, City, Warehouse, Velocity, Store Void. Filter drawer: cascading multi-selects (`SelectFilterGroup` over `POST kehe/filter-data`, each facet excludes its own selection client-side) plus From/To date pickers; every report re-queries with filter. "Upload KeHE" opens chunked upload (2.10.2.1) with sample-file link (`GET kehe/format`). "Export KeHE" and per-section Export buttons start async export job (2.10.7); status strip shows progress and download link. "Remove" opens confirmation and deletes KeHE rows matching current filter (2.10.2.3), then invalidates all queries. Store Void report fetches only when at least one category selected.
- APIs (prefix `/api/v1/kehe`, all `BrandIDHeader`): chunk/status/format, root `POST` (legacy import, platform-admin), root `GET` (raw records), `GET /total-dollar-and-cases-shiped`, `GET /sales-by-product`, `/sales-by-retailer`, `/sales-by-store`, `/sales-by-state`, `/sales-by-city`, `/sales-details`, `/dc-report`, `/sales-report`, `/warehouse-report`, `/store-void-report`, `/velocity-report`, `/filter-criteria-data`, `POST /filter-data`, `DELETE /` (root), `GET /export`, `POST /export-report`.
- Business rules: brand is `IAccessContext.GetActiveBrandIdAsync` (BrandID header, must be accessible) for every `RequireModule` handler; legacy import and sync exports use `ICurrentUser.GetBrandID()` (raw header) instead. `filter-data` property allowlist (case-insensitive): `Dc`, `RetailerName`, `ProductDescription`, `CustomerStateCode`, `CustomerCity`, `ProductCategory`, `ProductSubCategory`, `CustomerName`; anything else 400 "Filter property name not found". Velocity divides per-store totals by week count summed over distinct month numbers in data (31-day months 4.43, 30-day 4.29, February 4). A filter value with single quote escaped by `ReplaceSingleQuote` before inlined into SQL; empty filter on DELETE deletes every KeHE row of brand.
- Gotchas: reports read raw `KeHeRecords`, not `KeHeMapped`; retailer/store names on screen raw text, while Distributor Sales Report shows mapped names for same upload. KeHE/UNFI/SPINS filters string-built SQL with quote escaping, unlike parameterized DSR filters. No action-level gating in web page: Upload/Export/Remove buttons render for anyone who can open route (`KeheComponent.tsx` no `useModuleAccess` call); server refuses missing actions. Many `console.log` calls in `KeheComponent.tsx`.

#### 2.10.2.1 KeHE chunked import [Active]
- `UploadChunkForKeHEImportRequest` stores file under `imports/kehe/{brandId}/` and enqueues `ExecuteImportAsync(..., ModuleType.KeHEExport)`; `ImportJobService.ExecuteKeHEImportAsync` parses `KeHEImportDTO` rows, groups by month, and per month creates a `DataSyncRun` (`Trigger = Manual`), deletes that brand-month's KeHE raw, mapped, unmapped and DSR rows (`SharedDataHubService.DeleteSyncDataAsync`), then inserts through `SaveKeHeWithUnmappedHandlingAsync`.
- Business rules: rows whose Current Year QTY blank, zero or negative (accounting `(5)` and `$0.00` read as numbers) skipped before type checks and counted in `SkippedRows`, never in error file (`KeHeQuantityRule.ShouldSkip`). Missing UPC fails row ("UPC not found"); type checks (`ValidateKeHERecord`): Current/Prior Year QTY Int32, YoY % Double, Current/Prior Year Cost Float, Month DateTime, Product Size Float; message format `[Row = n] Column: Invalid Type. Expected: T` (row = index + 2). Re-uploading a month replaces that month for brand (delete then insert). Row with unparseable month falls into sentinel month (`SentinelMonth`, year 2000) group. Fails immediately when store clean-up running.
- Tests: `ImportJobServiceKeHeSkipTests.cs`.

#### 2.10.2.2 KeHE legacy single-shot import [Partial]
- No web caller: web uses only chunk route; `dataUpload.service.ts` has no POST to `/kehe`.
- What it does: `POST /api/v1/kehe` (platform-admin permission) parses whole file and bulk-inserts valid rows into `KeHeRecords` only; returns failed rows as CSV in `FileUploadResponseMetaDTO`.
- Gotchas: inserts raw rows only, so no mapped, unmapped or DSR rows and no month replacement (`ImportKeHERequestHandler`); `SaveBannerSKUs` call commented out; `Message` is "KeHE Data uploaded successfully" only when there ARE invalid rows (inverted condition).

#### 2.10.2.3 KeHE delete [Active]
- "Remove" sends `DELETE /api/v1/kehe` with drawer filter as query string and body `{ iDs, isAllDelete }` (`DataUploadService.deleteKeheData`). Handler hard-deletes from `KeHeRecords` where `BrandID` matches and bound filters match.
- Business rules: only `dcs`, `retailers`, `products`, `cities`, `states`, `months`, `years` bound (`DeleteKeHeRecordsRequest`); body ignored.
- Gotchas: drawer's category, sub-category, store and date filters not part of delete, so Remove can delete more rows than screen shows; with only those filters set deletes every KeHE row of brand. Confirmation text says "remove all the items" (`DeleteComponent` with `allDelete`), but request carries filters. Only raw `KeHeRecords` deleted; `KeHeMapped`, unmapped and `DistributorSalesRecords` rows from same upload remain, so Distributor Sales Report still shows them.

#### 2.10.2.4 KeHE raw records list [Partial]
- Backend `GET /api/v1/kehe` works; web table `KeheRowTableData` commented out in `KeheComponent.tsx`.

#### 2.10.2.5 KeHE synchronous exports [Partial]
- Endpoints exist; `DataUploadService.exportKehe` and `exportKeheReport` no caller; screen uses async job (2.10.7). `GET /kehe/export` (raw rows CSV) and `POST /kehe/export-report` (one report as CSV by `KeHEReportType`) under platform-admin permission `MustHavePermission(Export, MasterDataUpload, DataUpload)`, so brand user 403.

"Upload" opens `<ChunkedImportUpload provider="spins-stores-insight">` with sample `GET spins/format/false`. Sync export route misspelled `export-stores-ingiht` and admin-only; `DataUploadService.exportSpinsStoreInsight` calls it but no caller. Legacy `POST /import-stores-insight` reads brand from raw header (`ICurrentUser.GetBrandID()`), no web caller. SPINS runner does not check store clean-up guard.

### 2.10.6 Distributor Sales Report [Active]
- Combined KeHE + UNFI sales reporting over mapped `DistributorSalesRecords` table (one row per mapped sale line, with Store List link `StoreListEntryId`). Brand uploads distributor file for chosen month, year and provider; screen shows totals, monthly chart, DC chart and ten report grids, each with own CSV export. Route `/{brandID}/distributor-sales-report`, slug `distributor-sales-report` (`View`, `Import`, `Export`).
- User flow: page opens with filter preset to rolling 12 months (`getRolling12MonthsRange`: first day 11 months back to end of current month). Cards (Total Sales Dollars Shipped, Total Cases Shipped), chart (`retail-sales-report` monthly totals + `dc-report`), then DC Cases Sold, Sales by Product, Chain, Store, Details, State, City, Warehouse, Velocity, Store Void. Filter drawer: Source (All, UNFI, KEHE) plus cascading facets from `DISTRIBUTOR_SALES_FILTER_PROPERTIES` (distribution center, retailer, banner, Stores by Store List ID, ...); each facet calls `POST distributorsalesreports/filter-data`. "Refresh" invalidates every query whose key starts with `get-distributor-sales-`. "Upload Distributor Report" opens import form (2.10.6.1). Each section's Export button posts `export-report` with its `reportType` (1 to 9), `pageSize=-1`, downloads `distributor-{label}-{YYYYMMDD}.csv` (`useExportDistributorSalesReport`). Store Void loads only after at least one category chosen.
- APIs (prefix `/api/v1/distributorsalesreports`, all `BrandIDHeader`): `/filter-data`, `/sales-by-product`, `/sales-by-chain`, `/sales-by-store`, `/sales-by-city`, `/sales-by-state`, `/sales-details`, `/total-dollar-and-cases`, `/velocity-per-store`, `/dc-report`, `/store-void-report`, `/warehouse-report`, `/retail-sales-report`, `/export-report`, `/velocity-per-store-for-promotion`, `/import/chunk`, `/import/start`, `/import/{jobId}/status`.
- Business rules: all filters parameterized `= ANY(@...)` fragments (`DistributorSalesRecordsQueryHelper.GetSearchCondition`); `storeIds` filters `StoreListEntryId`; dates compare `ReportDate` by day. Store identity (store counts, Sales by Store lines, void report stores) is Store List ID, else lower-cased trimmed customer name plus ZIP5; row with no name not a store (`StoreIdentitySql`). Store filter options (`propertyName = StoreListEntryId`) list only Store List stores brand's rows linked to, labelled store name then address, city and state, sorted by label; rows not linked have no option. `filter-data` allowlist: `Source`, `Banner`, `DistributionCenter`, `RetailerName`, `ProductDescription`, `City`, `State`, `Category`, `SubCategory`, `CustomerName`, `StoreListEntryId`, `Region`; facet SQL includes facet's own selection (web drops it client-side via `excludeProperty`). Velocity per store divides by total weeks summed over distinct month numbers (same rule as KeHE).
- Gotchas: `DistributorSalesReportsController.ExportReportsAsync` copies `payload.Stores` but not `payload.StoreIds` into `ExportDistributorSalesReportByTypeRequest`, and web sends only `storeIds` (`buildPayload`), so every CSV export ignores Stores filter while grid above applies it. Store-ID filtering and store counts (commit `3b3eb92c` CS-1718) exist on working branch only; origin/master `PayloadHelper.cs` has no `StoreIds`. No delete for DSR rows from this screen; KeHE/UNFI raw deletes (2.10.2.3, 2.10.3.2) leave DSR rows behind. Week count uses distinct month numbers, so 12 months spanning two calendar years with repeated months count those weeks once. `useExportDistributorSalesReport.onError` reads `json.error.messages[0]`, but `messages` object keyed by field, so server text not shown (falls back to "Failed to export report"). Store Void returns every matching row with no paging.

#### 2.10.6.1 Distributor report file upload [Active]
- Upload of KeHE "Full POD Vendor Report" or UNFI "Sales Details" file for one month: chunk upload (`imports/distributor-report/{brandId}/`, `ModuleType.DistributorReportFileUpload`, not auto-queued), then `POST import/start` with month, year and provider queues `IImportJobService.ExecuteDistributorReportFileUploadAsync`.
- User flow: pick Provider (UNFI or KEHE), Month and Year (1900-2100; current year preselected), choose CSV, upload; when last chunk completes hook calls `startDistributorReportImport` (`onUploadComplete`), then polls status. Tab warns on page leave while active (`beforeunload`). On completion invalidates `get-distributor-sales-` queries. No sample file offered.
- Business rules: start validator: `importJobId` required, year 1900-2100, provider KEHE or UNFI (`StartDistributorReportFileImportRequestValidator`); start refuses job of another brand (403), wrong module type, still Uploading, not Pending, or without `S3Key` (400). Runner computes SHA-256 of file, creates `DataSyncRun` (`Trigger = FileUpload`, source file URL and hash), deletes brand-month for that provider (raw, mapped, unmapped, DSR) and inserts through `SharedDataHubService` (`ExecuteDistributorReportKeHEFileAsync`/`ExecuteDistributorReportUNFIFileAsync`). KeHE rows: zero-quantity rule, "UPC not found", type checks; UNFI rows: "Product/UPC is required" plus type checks. `ExecuteImportAsync` refuses this module type ("must be started through the start-import API").
- Gotchas: `ExecuteDistributorReportFileUploadAsync` returns without failing job when provider neither KEHE nor UNFI (unreachable through validator); start call sets status 10 before queuing.

#### 2.10.6.2 Velocity per store for promotion [Active]
- Supplies per-UPC units and dollars per store per week for one banner to promotion product stepper (`BannerSKUs.tsx` via `useGetVelocityPerStoreForPromotion`).
- Business rules: resolves banner's distributor through `CRM.DistributorBanners` for brand (parent distributor name when present); source is KEHE if name contains "kehe", UNFI if "unfi", otherwise empty result; excludes rows whose customer name contains "confidential"; `PercentageOfSalesQuantity` is UPC's share of banner total. Access: approved-promotions or trade-spend-sandbox `View` (not DSR module).
- Tests: `GetVelocityPerStoreReportForPromotionRequestTests.cs`.

#### 2.10.6.3 Full DSR rebuild and product name sync [Active]
- `SyncDistributorSalesRecordsRequest` deletes every `DistributorSalesRecords` row (all brands) and rebuilds from `KeHeMappedRecords` and `UNFIMappedRecords`, keeping only UPCs present in brand's product specs and computing cases from product `CasePack` (fallback UNFI feed `Pack`). `SyncMappedProductNameAndCategoryRequest` refreshes mapped product names and categories. Both live in this module (`Requests/Report Sync/`) but exposed as `POST /api/v1/datahub/report-sync/distributor-sales-records` and `POST /api/v1/datahub/report-sync/product-name-category` with `MustHavePermission(Upsert, EntityResolution, DataHub)` (`DataHubController.cs`), owned by 2.14.
- Gotchas: loads all mapped rows of all brands into memory (`ListAsync`) and uses first record's brand for CasePack lookup (`brandId` from `keHeRecords.FirstOrDefault()`), so CasePack resolution correct only for that one brand. Rounds cases to whole numbers, while upload path (`SaveKeHeWithUnmappedHandlingAsync`) rounds to 2 decimals, so rebuild changes `CasesShipped` values.

### 2.10.7 Async export jobs for data uploads [Active]
- Queues background CSV export of brand's raw rows (KeHE 19, UNFI 20, SPINS 21, Distributor Sales 27; Monthly Report 26 shares endpoint, see 2.11), stores file on S3 and returns presigned download link through polling. Used by KeHE, UNFI and SPINS pages' Export buttons. Access: module's `Export` action for active brand.
- User flow: user clicks Export; page builds filter object (`buildKeheExportFilters`/`buildUnfiExportFilters`/`buildSpinsExportFilters`) and calls `useExportJob.start(moduleType, filtersJson)`. `POST /api/v1/export/start` returns `jobId`; hook polls `GET /api/v1/export/{jobId}/status` every 2.5s until 15, 20 or 25. `ExportStatusUI` shows progress (`rowsExported`/`totalRows`), then download link (`downloadUrl`) or error; Export buttons disabled while job runs (`isRunning`).
- APIs: `POST /api/v1/export/start`, `GET /api/v1/export/{jobId}/status`.
- Business rules: unsupported module types 400 listing supported types; status 404s job of another brand or type not in `BrandExportModules`; export reads raw `KeHeRecords`, `UnfiRecords`, `SPINSStoresInsight` or `DistributorSalesRecords` with filter DTO.
- Gotchas: KeHE and UNFI per-section Export buttons send `reportType`, `sortKey`, `pageSize`, `currentPage` (`handleExportReport`), but `KeHEExportFilterDto`/`UNFIExportFilterDto` have none, so every section downloads same raw-rows CSV, not section's report. SPINS Item Ranking export returns Stores Insight data (2.10.4). `buildDistributorSalesExportFilters` (module 27) no caller; DSR exports use synchronous `export-report` (2.10.6). `useExportJob` no unmount cleanup for `setInterval` (no `useEffect`). Whole CSV built in `MemoryStream` before upload, memory grows with export size.

### 2.10.8 Master data bulk import and export (admin) [Active]
- Platform admins import CRM and product spec reference data from CSV (create or update by name/ID, failed rows returned as CSV) and export same entities as CSV from admin CRM screens. All routes require platform-admin permissions `Import Data`/`Export Data` (`MustHavePermission(Import|Export, MasterDataUpload, DataUpload)`), which only admin permission set contains (`CaboodlePermissions.Admin`; `Broker`/`SubBroker` sets include only `Broker` module permissions). No BrandID header; data spans all brands.
- User flow: Admin opens CRM screen (e.g. `/banners`), uses Upload (admin `UploadComponent` posting multipart `file` to `/api/v1/masterdataupload/{entity}`), optionally downloads sample (`GET masterdataupload/sample-file?fileCategory=`). Response lists failures; failed-rows CSV offered. Export posts/gets export route with grid's filters and saves CSV (`helper.ts` shared CSV export helper).
- APIs: 33 active routes (import + export per entity) + 2 commented out, listed in source §2.10.8 table. Import rows `MustHavePermission(Import, MasterDataUpload, DataUpload)`, Export rows `MustHavePermission(Export, MasterDataUpload, DataUpload)`.
- Business rules: (examples verified in `MasterDataUploadService`) banners: Retailer Name must match existing retailer `CorporateName` (case-insensitive), Banner Name and Door Count required; product specs: UPC Number and Brand Name required, brand matched by name; stores: Region ID and Retailer ID required. Master KeHE/UNFI imports all-or-nothing (any row error throws `ValidatorException` with every message, nothing inserted: `KeHeRecordsImport`, `UnfiRecordsImport`). Per-row errors use `[Row = n] message` with n = index + 2.
- Gotchas: `caboodle.admin/src/services/users.service.ts` `exportUser` calls `GET /api/v1/masterdataupload/users`, route that does not exist; `exportUser` no caller. `MasterDataUploadService` injects `IRepository<DataMapping>` but never uses it. Dead requests in module: `BrandsImportRequst` and `BrandPriceList{Import,Export}Request` no endpoint; `BrandsExportRequest` exposed by `BrandsController` `GET /api/v1/brands/export` (owned by Brand module). Master KeHE/UNFI imports bypass mapping and month replacement (raw insert only), unlike chunked brand import. Admin has no Jest tests for these callers.

### 2.10.9 Data mappings (admin) [Active]
- Platform admins keep table of external entity names (as written in provider file) and Caboodle entity each maps to (`EntityID` within a `FileCategory`, optional `Provider`). Admin screen lists mapped and unmapped names, edits unmapped name's target, removes rows, imports/exports mappings as CSV. Permission `Data Mapping` (`MustHavePermission(Create, DataUpload, DataUpload)`), platform admin only.
- User flow: Admin opens `/upload-data-map` (no sidebar entry; `SELECTED_KEY_ALIASES` in `navConfig.tsx` highlights Mapped Data when there). Mapped/Unmapped radio switches `isMapped`; grid shows Caboodle System ID, Entity Name, Entity Module (`FileCategory`), Provider; filters by provider (0 = none) and module. Unmapped rows offer "Edit Entity" (`EditMappedData`: pick target entity from matching CRM list) and every row "Remove Entity" (soft delete). Upload asks for file category (Retailer, Distributor, Banner, Region, SubDistributor: `FileCategoryForMappedData`) and optional provider, then posts CSV to `datamappings/import`; sample CSV available. Export downloads filtered list.
- APIs (prefix `/api/v1/datamappings`, all `MustHavePermission(Create, DataUpload, DataUpload)`): `GET /`, `GET /{id}`, `POST /`, `DELETE /`, `POST /import`, `GET /export/sample-file`, `GET /export`, `GET /filter-data`.
- Business rules: entity name required and unique (case-insensitive) on upsert; `EntityID`, when sent, must exist in table for its `FileCategory` (else 404); import rejects names already present ("Already exist in the system.") and entity IDs that do not exist; delete requires at least one id and soft delete (`DapperQueryBuilder.Delete`).
- Gotchas: no import or report reads `DataMappings` today: only writer outside feature, `SharedDataService.SaveBannerSKUsDataFromProvider`, reached only from commented-out `SaveBannerSKUs` calls in `ImportKeHERequest` and `ImportUNFIRecordsRequest`; `GetMappingDataSpecification` no caller. Name resolution for uploads now uses DataHub aliases (2.14). List, filter and import SQL inline values with quote escaping (`GetDataMappingsRequest.GetQuery`). `DeleteDataMappingsRequest` SQL inlines GUIDs and user id (`DapperQueryBuilder.Delete`). No tests found (backend or admin).
