# Module 2.12 — Intelligence (Ask Caboodle) (code-verified)

Source of truth: `docs/feature-context.md` §2.12. Self-sufficient reproduction (condensed to verified facts; full prompt/SQL detail in source).

## Purpose
Natural-language analytics for a brand ("Ask Caboodle"). A user question is screened, classified, routed to one of two query paths (distributor report data from KeHE/UNFI uploads, or internal CRM, Product Specs and Trade Spend data), turned into an LLM-written query plan, compiled to parameterised SQL by the server, executed read-only, and returned as a structured report (table, KPI, chart, insights, actions, follow-up suggestions). Conversations persisted per user and brand, every turn audited with token cost, and two admin-only tools exist (entity index rebuild, evaluation suite). A separate web "AI-Powered Dashboard" prototype uses a placeholder Next.js API route.

## Feature inventory (summary; full detail in source §2.12)

### 2.12.1 Ask Caboodle chat (question to report) [Active]
- Status: Active (module `ask-caboodle`; only in-app link, dashboard ask box, hidden when `NEXT_PUBLIC_APP_ENVIRONMENT` is `Production`, see 2.11.6.1; route stays reachable by URL). Used by Brand organizations (and brokerages on connected brand) with module `ask-caboodle` action View.
- What it does: answers one natural-language question per call with structured report built from brand-scoped data.
- User flow: user opens `/{brandID}/ask-caboodle` (directly or from dashboard ask box with `?prompt=`). Prompt in query string sent once on mount. `ChatContainer` loads session list and shows conversation; `ChatInput` sends `POST intelligencechat/chat` with `{ message, sessionId, explain }` and header `BrandID`. Server pipeline (`PathAwareOrchestrator.ProcessAsync`): (1) get or create session; if already holds `MaxSessionMessages` messages, reply Refuse "This conversation has reached the maximum of N messages" (not persisted). (2) Prompt guard; blocked messages return Refuse with `ValidationFailure`. (3) Intent classification; anything but Queryable stores user message plus fixed clarification reply. (4) Data context classification: DistributorReport goes to path A, InternalData to internal path, anything else (including SyndicatedReport) gets "I can help with distributor report queries (KeHE/UNFI sales data) or internal CRM data." (5) Path runs plan, compile, execute, report build; assistant message stores headline as content and report as `ResponseJson`. (6) Any exception: Refuse "Something went wrong. Please try again." with `TransientFailure` and `ErrorDetail = ex.Message`. Web renders reply with `AIReportRenderer` (blocks `kpi`, `chart`, `table`, `insights`, `actions`; `nextSuggestions` as clickable chips sending new message). "New conversation" resets local state; first reply's `sessionId` stored and reused.
- APIs: `POST /api/v1/intelligencechat/chat` (`RequireModule(ask-caboodle, null, View)`, `BrandIDHeader`) → `ChatResponseDTO` (`SessionId`, `Intent`, `Message`, `TotalRows?`, `FailureType?`, `ErrorDetail?`, `StructuredReport?`); web `ChatRequest`/`ChatResponseDTO`.
- Business rules: brand scope: `ChatRequestHandler` uses `IAccessContext.GetActiveBrandIdAsync`; every compiled query adds `BrandID = @brand` (distributor tables; internal tables in `TablesWithBrandId`). Message limits: guard blocks empty text and more than 100 characters. Session cap: `MaxSessionMessages` counts user and assistant messages (20 in Development and Staging config, so 10 exchanges). Token cost computed only when `PlannerProvider = Claude` (planner plus report tokens times `LlmModelPricings` for `ClaudeModel`); other providers log 0 tokens and 0 cost.
- Gotchas: `DbChatContextStore.GetOrCreateAsync` loads session by id without checking `UserId` or `BrandId`; caller who knows another user's session id can append to it, and that session's history fed into LLM prompts. Get and Delete do check ownership. `ErrorDetail = ex.Message` returned to client on any exception (including "forbidden keyword" safety exception, thrown outside executor's try block). Web thread-full detection looks for word "thread" in reply (`useAskCaboodleChat.ts`); backend says "conversation", so input never locks. Web has no 100-character limit; longer questions refused by server guard. Web types expect `clarificationOptions` and render `ClarificationOptions`; backend never returns that field. Web `FailureType` enum has `ProcessingError = 2` where backend has `PermissionFailure = 2`. Several options read nowhere: `MaxTokens`, `Temperature`, `MaxQueryRows`, `MaxJoins`, `PlannerHistoryMessageCount` (each component uses own constants). `UpdateConstraintsAsync` never called, so session constraints (year, module, entities) always empty. Non-Claude providers record zero tokens and zero cost in audit log.

#### 2.12.1.1 Prompt guard [Active]
- Regex and keyword screen before any LLM call.
- Business rules: blocks: "ignore ... instructions", "reveal/show ... prompt", "show/list ... table|schema|column|database", whole-word SQL verbs `DROP|ALTER|TRUNCATE|DELETE|INSERT|UPDATE|CREATE|GRANT|REVOKE`, `; SELECT` chains, `UNION SELECT`, role-play phrases, and substrings `password`, `secret`, `token`, `apikey`, `api_key`, `connectionstring`, `encryption` (`PromptGuard.cs`).
- Gotchas: ordinary business words blocked (e.g. "update", "delete", "create" as words, or "token"), message "contains a pattern that is not allowed".

#### 2.12.1.2 Intent classification [Active]
- LLM returns one of Queryable, Analysis, Clarification, Ambiguous, Refuse, Unspecified (`ConversationIntentType`) from `IntentClassificationPrompt.txt` with full session history.
- Business rules: only Queryable continues. Replies: Clarification "Could you clarify...", Ambiguous "I'm not sure which data...", Refuse "I can't help with that request.", Analysis "For deeper analysis, please ask a specific data question...", others generic text. Max 64 output tokens, temperature 0.1.

#### 2.12.1.3 Data context classification [Partial]
- `SyndicatedReport` classified but no execution path; falls to unsupported reply in `PathAwareOrchestrator.ProcessAsync`.
- What it does: LLM picks DistributorReport, SyndicatedReport, InternalData or Unspecified (`DataContextClassificationPrompt.txt`). KeHE/UNFI as data source means DistributorReport; KeHE/UNFI as a company means InternalData; "Monthly report" means InternalData.

#### 2.12.1.4 Distributor report path (KeHE / UNFI) [Active]
- LLM produces `DistributorReportPlan` (source KeHE, UNFI or Both; logical fields period, retailer_name, store, city, dc_warehouse, upc, product_description, sales_dollars, quantity; filters, dimensions, measures, year, month range, sort, limit). Compiler maps logical fields to physical columns (`ColumnMapping`), builds parameterised SQL per source against `DataUpload.KeHeRecords`/`DataUpload.UnfiRecords` with `Deleted = FALSE` and `BrandID`, executor runs it with timeout and transient retries, tagging rows with `Source` when both run.
- Code map: `DistributorReportLlmPlanner.cs`, `DistributorReportPlannerPrompt.txt`, `DistributorReportCompiler.cs`, `ColumnMapping.cs`, `DistributorReportExecutor.cs`.
- Business rules: unknown source defaults to Both. Measure aggregations sum, avg, min, max, count (distinct optional). Default limit 100. KeHE `sales_dollars` maps to `CurrentYearCost`.
- Gotchas: `ColumnMapping` passes unknown logical names straight through as quoted identifiers, and measure `Name` from LLM interpolated into `AS "<name>"`; only keyword blocklist (`ValidateSqlSafety`) stands between LLM output and SQL text. `plan.Limit` from LLM not capped. Queries run through normal `IDapperRepository` connection (no read-only role found).

#### 2.12.1.5 Internal data path (CRM, Product Specs, Trade Spend) [Active]
- Extracts entity mentions (LLM, `EntityExtractionPrompt.txt`), resolves against `Intelligence.MasterEntities` (exact or `ILIKE` contains, exact first), passes as session context to planner (`InternalDataBusinessPrompt.txt` plus `CrmSchema.txt`, `ProductSpecsSchema.txt`, `TradeSpendSchema.txt`, `TradeSpendSandboxSchema.txt`), which returns intent and `InternalDataQueryPlan` (dataset, joins, measures incl. `sum_months`, `sum_columns`, `derived`, conditional filter, dimensions, filters, time range, sort, limit, page). `InternalDataSqlCompiler` validates against allow-list of 31 tables, adds `Deleted = FALSE` per alias and `BrandID` for brand-owned tables, caps limit at 1000, maps enum columns back to labels (`InternalDataEnumMapper`).
- Code map: `LlmEntityExtractor.cs`, `MasterEntityResolutionService.cs`, `InternalDataPromptBuilder.cs`, `InternalDataLlmPlanner.cs`, `InternalDataQueryPlan.cs`, `InternalDataSqlCompiler.cs` (`AllowedTables`, `TablesWithBrandId`, `SafeColumnName`, `EnumColumnByTableColumn`), `InternalDataExecutor.cs`, `InternalDataEnumMapper.cs`.
- Business rules: planner intents other than DataQuery return planner's clarification question or message. Brand-owned tables include monthly report, promos, events, banner SKUs, contacts, pipelines, categories, products, price list; global tables (retailers, banners, distributors, regions, stores, DCs) carry no brand filter.
- Gotchas: `MasterEntities` has no brand column, so product/category of another brand can resolve as context (SQL itself still brand-filtered). `IdColumnFilter` drops any column whose name ends with "Id", "ID" or "Guid", also hiding legitimate columns with such endings.

#### 2.12.1.6 Structured report response [Active]
- Always adds table block from rows (page size hint 15); asks LLM (temperature 0.3, up to 12,000 output tokens) for headline, overview, insights, actions, next suggestions, and chart/KPI recommendations, then builds chart and KPI blocks from real rows. Falls back to "Report, N rows returned." when LLM output does not parse.
- Code map: `ReportResponseBuilder.cs`, `StructuredReportPrompt.txt`, `StructuredReportDTOs.cs`; web `AIReportRenderer.tsx`.

#### 2.12.1.7 Session title generation [Active]
- On first data-query turn of new session, provider-specific generator writes short title (`SessionTitleGeneratorSelector`). Sessions whose first turn non-queryable keep null title.

#### 2.12.1.8 Audit log and token cost [Active]
- One `QueryAuditLog` per request with intent, model name (`ActiveModelName`), tokens, cost, timing, rows, failure type and response summary. Cost = tokens / 1000 times per-1K prices from `LlmModelPricings` (cached 30 minutes, `ModelPricingService`); `LlmModelPricingSeeder` (`ICustomSeeder`) seeds `gpt-4o`, `gemini-2.5-flash`, `claude-sonnet-4-6` when missing.
- Gotchas: `GeneratedSql` and `QueryPlanJson` never filled by orchestrator (`SetExecutionResult(null, null, ...)`, `SetPlannerResult(..., null)`), so audit cannot reproduce a query. Staging model `gemini-2.5-flash-lite` has no seeded price.

### 2.12.2 Chat sessions (history sidebar) [Active]
- Lists current user's conversations for active brand, opens one with messages and reports, deletes one.
- User flow: `ChatSidebar` loads `GET sessions` on mount and after new session id appears; web sorts by `lastActivityAt` descending. Clicking session loads `GET sessions/{id}` and maps messages, restoring each `structuredReport`. Delete calls `DELETE sessions/{id}`; 404 treated as already removed (info toast); other errors show server message.
- APIs: `GET /api/v1/intelligencechat/sessions`, `GET /api/v1/intelligencechat/sessions/{sessionId}`, `DELETE /api/v1/intelligencechat/sessions/{sessionId}`.
- Business rules: Get and Delete return 404 ("Chat session not found") unless session belongs to caller and active brand. Delete needs only View.
- Gotchas: list SQL has no `ORDER BY` and no limit, counts only user messages, inner-joins messages, so session with no user message hidden. `ListSessionsForUserSpec` (limit 50) unused by list request. Controller's `NotFound()` branch unreachable because handler throws.

### 2.12.3 LLM provider configuration [Active]
- One switch, `PlannerProvider`, selects OpenAI, Gemini or Claude for every LLM step (intent, data context, entity extraction, both planners, report narrative, title).
- Data: Development and Staging set `PlannerProvider: Claude`, `ClaudeModel: claude-sonnet-4-6`, `OpenAIModel: gpt-4o`, `GeminiModel` `gemini-2.5-flash` (Development) or `gemini-2.5-flash-lite` (Staging), `SessionTtlMinutes: 60`, `MaxJoins` 3 (Development) or 10 (Staging). `appsettings.json` and `appsettings.Production.json` contain no `IntelligenceSettings` section, so production falls back to defaults (OpenAI, empty key) unless environment supplies them.
- Gotchas: `appsettings.Development.json` and `appsettings.Staging.json` tracked in git and hold non-empty `ClaudeApiKey` values (Staging also `GeminiApiKey`); values not reproduced here. Gemini keys travel in request URL (`?key=`), can end up in HTTP logs. Empty key makes `ClaudeApiHelper` return null silently, surfacing as "Could you rephrase" style replies rather than configuration error.

### 2.12.4 Master entity index rebuild (admin tool) [Partial]
- Endpoint only; no caller in admin or web.
- What it does: soft-deletes every `Intelligence.MasterEntities` row, then re-inserts names and ids from `CRM.Retailers` (CorporateName), `CRM.Banners`, `CRM.Distributors`, `ProductSpecs.Categories`, `ProductSpecs.ProductSpecifications` ("Name - UPC"), `DataHub.StoreListEntries` ("Retailer - Banner - Store") and `Brand.Brands`; returns per-type counts.
- API: `POST /api/v1/intelligencechat/master-entities/populate` (`MustHavePermission(Execute, IntelligenceTools, Admin)`) → `PopulateMasterEntitiesResult` (`RetailersInserted` ... `BrandsInserted`, `TotalInserted`).
- Gotchas: soft-deleted rows never purged, so table grows on every run. Cache key it clears (`Intelligence:MasterEntities:All`) not used by any reader. No job keeps index in step with renames; only as fresh as last manual run. Not brand scoped.

### 2.12.5 Evaluation suite (admin tool) [Partial]
- Endpoint only; no caller in admin or web.
- What it does: runs 21 built-in questions in `EvaluationSuite.Cases` through real orchestrator for brand in request's `BrandID` header (or `Guid.Empty`) and compares returned `IntentType` with expected.
- API: `POST /api/v1/intelligencechat/evaluation/run` (`MustHavePermission(Execute, IntelligenceTools, Admin)`) → `EvaluationResultDTO` (`TotalCases`, `Passed`, `Failed`, `Results[]`).
- Business rules: only intent equality scored (`ExpectedSchema`, `ExpectedTable` not checked).
- Gotchas: each case creates real chat sessions, messages and audit rows under admin user and incurs LLM cost; with `Guid.Empty` brand every brand filter matches nothing.

### 2.12.6 AI-Powered Dashboard prototype (`dashboard-ai`) [Partial]
- UI on placeholder logic: `app/api/ai-message/route.ts` keyword-matching stub with sample data; no inbound link to `/{brandID}/dashboard-ai`.
- What it does: two-column page: chat panel left, `DynamicVisualization` (ECharts charts and PrimeReact tables from JSON spec) right. Messages go to Next.js route `POST /api/ai-message`, which answers "hello", "add chart", "add table", "remove/delete", "clear/reset" with canned replies and sample visualisation changes, echoes anything else.
- APIs: `POST /api/ai-message` (Next.js route) (`AIMessageRequest` (`messages`, `currentVisualization`) / `AIMessageResponse` (`reply`, `updatedVisualization`); 400 when no messages).
- Route gated by `BRAND_ROUTE_MODULES["dashboard-ai"] = ask-caboodle`. No external service and no env vars.
