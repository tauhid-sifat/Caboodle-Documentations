# Module 2.9 — Market Overview & APL Reports (code-verified)

Source of truth: `docs/feature-context.md` §2.9. Self-sufficient reproduction (condensed to verified facts; full SQL/handler detail in source).

## Purpose
Broker-facing field intelligence and authorized-product-list (APL) reporting. Brokers log what they saw or presented at retail ("Market Overview" logs: region, retailer, banner, store, SKU, SKU status, presentation date, comment), report on those logs, and maintain or read three different APL views. Brands read the logs their brokers created ("Broker Market Activities") and their own retail item status ("Retail Reports"). The broker landing dashboard (`/dashboard`) is the tile hub linking into these and sibling broker screens.

## Shared data models
- `Broker.MarketOverviews` (`MarketOverview`): `ID`, `RegionID`, `RetailerID`, `BannerID`, `StoreID?`, `DCID?` (optional since migration `20260916105755_MarketOverviewDCIDMadeOptional`), `BrandID`, `BrokerageOrganizationID?`, `SKUID`, `SkuStatus` (int, `SkuStatus` enum 1 Active..7 Commit), `DateTime` (presentation date), `Comment` (HTML), `Training`, `CaseStack`, `LaunchDate?`, audit fields. Indexes on each FK plus `(BrokerageOrganizationID, BrandID)`. A `BEFORE INSERT` trigger `TR_MarketOverviews_StampBrokerageOwner` fills `BrokerageOrganizationID` when null.
- `Broker.DistributorAPLs` (`DistributorAPL`): `DCID`, `DistributorItemCode`, `UPCNumber`, `WholesaleCaseCost`, `WholesaleUnitCost`, soft-delete fields. Global table: no brand or brokerage column; brand reach derived by joining `UPCNumber` to `ProductSpecs.ProductSpecifications`.
- `CRM.BannerSKUs` (owned by CRM, 2.4): source of both Retail APL (broker) and Retail Reports (brand); Market Overview create/update writes into it.
- `DataHub.ExportJobs` (`ExportJob`): Retail APL background export rows (`ModuleType.RetailAplExport = 34`).
- Read-only joins: `CRM.Regions`, `CRM.Retailers`, `CRM.Banners` (`DoorCount` = Number of Stores), `CRM.DistributorDcs` (`Warehouse`), `CRM.RetailerRegions`, `CRM.DistributorBanners`, `CRM.Stores`, `CRM.BannerActivities`, `DataHub.StoreListEntries`, `ProductSpecs.ProductSpecifications`, `ProductSpecs.Categories`, `Brand.Brands`, `Identity.Users`.

The three APL contracts (never interchangeable):
| | Brand Retail Reports ("Brand APL") | Distributor APL | Broker Retail APL ("Brand Retail Item Status") |
|---|---|---|---|
| Route | `POST api/v1/brands/apl` (+ `apl/filter-options`, `apl/export`, `apl-total-count`, `apl-activities*`) | `api/v1/brokers/apl*`, `apl-property-values` | `api/v1/brokers/retail-apl*` |
| Data | `CRM.BannerSKUs` of one brand | `Broker.DistributorAPLs` (DC + UPC + costs) | `CRM.BannerSKUs` of many brands |
| Access | `RequireModule(retail-reports, null, View)`; `BrandID` header required | `RequireModule(null, distributor-apl, ...)`, cross-brand | `RequireModule(null, retail-apl, ...)`, cross-brand |
| Brand scope | Active brand from header | `BrandsInScope(distributor-apl, action)`, rows whose UPC belongs to a product of those brands | `BrandsInScope(retail-apl, action)` intersected with optional `brands` body filter |
| Filter options | One call, all five facets, server self-excludes; no `propertyName` | One call or one facet (`propertyName` optional); self-excludes; adds numeric ranges | `propertyName` required, one facet per call, no self-exclusion (client strips facet's own key) |
| Sort | `sortKey` query (`RetailerName` default, also secondary `BannerName`) | Fixed `Warehouse ASC` | `sortKey` query; empty = `RetailerName`, invalid = `BrandName` |
| Export | Synchronous CSV (`POST apl/export`) | Synchronous CSV (`POST apl/export`), `isSampleFile` | Background job (`export: true` on list body) + status/cancel |
| Row ids | None (display fields only) | `ID`, `DCID`, `BrandID`, `CategoryID` | `BrandID` only |

## Shared services
- `MarketOverviewScope` (`MarketOverview/MarketOverviewScope.cs`): broker writes/reads limited to `BrandsInScope(market-overview, action)` AND `BrokerageOrganizationID = caller's organization` (`Condition` constant); `ResolveRequestedBrands` refuses named out-of-scope brands.
- `MarketOverviewFilterConditionBuilder` + `MarketOverviewFilterRequestBase` (`MarketOverview/MarketOverviewFilterConditionBuilder.cs`): one filter contract (`IMarketOverviewFilter`, 22 fields) shared by list, filters, report and export.
- `AplBrandScope` and `AplFilterConditionBuilder` (`APL/`): Distributor APL brand reach via UPC and shared filter contract `IAplFilter`.
- `ExportJobOwnership.DemandOwnJobAsync` (`Helper/ExportJobOwnership.cs`): another user's job answers 404 (platform admin exempt).
- `ISharedDataService.PushMarketOverviewChangesIntoCRM` / `PushMarketOverviewUpdatesIntoCRM` (`Shared/.../SharedDataService/SharedDataService.cs`): copy logged SKU status into `CRM.BannerSKUs`.
- `FileExportHelper.ConvertToCsvFile` (CSV responses), `PagingHelper.GetDataRange` (`pageSize: -1` = all rows).
- Web: `TableWithHeaderAction`, `TableHeaderActionButtons` (export scope menu), `SearchField`, `SelectFilterGroup` + `FilterComponent` (Retail APL), `useModuleAccess` (`anyBrandCan`), `downloadHelper`, `fetchWithMock` for CSV downloads, `useDebouncedValue`.

## Feature inventory (summary; full detail in source §2.9)

### 2.9.1 Broker Market Overview logs [Active]
- Brokerage's log of retail visits and presentations: one row per (brand, retailer, banner, region, optional store, optional DC, SKU) with SKU status, presentation date, launch date, training and case-stack flags and rich-text comment. `/market-overview` grid lists, filters, sorts, exports, adds, edits and removes brokerage's own rows. Used by Brokerage members with broker module `market-overview` (View, Create, Update, Delete, Export) on at least one connected brand; Brand company refused at policy (`RequireModule(null, market-overview, ...)` has no brand slug).
- User flow: Broker opens Management > Market Overview > Details (`/market-overview`, nav entry in `appNav.helper.ts`, route gated on `market-overview` by `BROKER_ROUTE_MODULES`). Grid loads `POST marketoverviews/list` (default `sortKey: RegionName`, `ASC`, page size `PAGE_SIZE`); search box (`SearchField`) writes `query`; drawer filters write rest; all filter state debounced (`useDebouncedValue`) and resets to page 1. Column headers sort server-side through `SortingOrderTitle` (keys `RegionName`, `RetailerName`, `BannerName`, `StoreName`, `BrandName`, `SKUName`, `SkuStatus`, `DoorCount`, `DC`, `CreatedBy`, `DateTime`). Sort keeps page. Row actions: View comment (only when row has one) and Edit log (when `anyBrandCan(market-overview, update)`). Toolbar: Export (scopes), Add Log, Remove Log (needs selection), Filter. Inverted date, launch-date or store-count range caught client-side (`getMarketOverviewRangeErrors`); list request withheld and reason shown in drawer. After delete that empties last page, grid steps back one page (`isLastPage` uses live page size).
- APIs (prefix `/api/v1/marketoverviews`): `POST /list`, `POST /`, `PUT /`, `DELETE /`, `POST /filters`, `POST /report/export`, `POST /options/search`, `POST /options/stores/search`.
- Business rules: every read/write limited by `MarketOverviewScope.Condition`: `BrandID = ANY(brands in scope for action)` AND `BrokerageOrganizationID = caller's organization`. List `SortKey` must be one of mapped keys or request fails with `SortKey: Invalid Sort Key provided`; empty sorts by brand name; ties broken by `mo.ID`. Validators: `PageSize` -1 or > 0; `FromDate <= ToDate` (`DateTimeRange`), `FromLaunchDate <= ToLaunchDate` (`LaunchDateRange`), `MinNumberOfStores <= MaxNumberOfStores` (`NumberOfStoresRange`); each 400. Text filters (`Query`, `Warehouse`, `Comment`, `Sku`, `UpcNumber`) trimmed and wrapped as `%value%` `ILIKE`; `Query` searches brand, retailer, banner, region, store, DC, SKU name, UPC, comment and creator name. Web gates every toolbar and row control on `anyBrandCan(market-overview, action)`, hidden while access loads.
- Gotchas: delete hard `DELETE` from `Broker.MarketOverviews` although entity has `Deleted` audit fields, and does not revert CRM banner SKU status row wrote. `SortingOrder` interpolated into list SQL without `ValidateSortingOrder` (`GetMarketOverviewsRequest.GetQuery`); other MO handlers validate. `IMarkerOverviewTable`/row mapping reads `item.distributorName`, which DTO does not return. List uses INNER JOIN on region, retailer, banner, brand, user and product (with `p.BrandID = mo.BrandID`); row whose referenced record missing/deleted disappears from grid without error. Web wire-name quirk: `skuIDs` and `dcIDs` must be sent as `skuiDs` and `dciDs` (System.Text.Json camelCase of `SKUIDs`/`DCIDs`); wrong spelling binds nothing and returns unfiltered data (`buildMarketOverviewFilterBody`). Delete returns `No Market overview deleted.` with 200 when nothing matched (out-of-scope ids skipped silently). Mutations invalidate only `QueryKeys.getMarketOverviews`; drawer facet queries and report key not invalidated. No test drives grid's sort or delete flow end to end.

#### 2.9.1.1 Add Log form and location options (CS-1299) [Active]
- Add Log modal creates one log per selected SKU per selected store (or one per SKU with `storeID: null` when no store picked). Region, Retailer, Banner and Store independent pickers fed by two option endpoints; value auto-filled when user's other picks determine it.
- User flow: modal opens; hook fetches `options/search` once with `{ pageSize: -1, currentPage: 1 }` (`LOCATION_OPTIONS_BODY`) and `options/stores/search` for current location picks. User picks any of Region/Retailer/Banner; only picked values narrow other lists (`listLocationChoices`), derived values recomputed (`resolveSelection`), field with exactly one candidate filled. A `null` region (banner not mapped to region) counts as candidate so never auto-replaced. Store multi-select; "Select all" only when Retailer and Banner set; stores not in fresh store result pruned after refetch (`pruneStoreSelection`, gated on `!isPreviousData`). Brand from `useAccessibleBrands`; picking it clears SKU and DC. SKUs from `GET api/v1/banners/skus` with `BrandID` header and `pageSize: -1` (CRM); DCs from `POST api/v1/distributioncenter/distributor/dcs/search` filtered by region (`useGetDistributorDC`). SKU Status, Distribution center (optional), Presentation Date (required), Launch Date, Training, Case Stack, Comment; Submit posts payload array. With "continue" checked, modal stays open, completed SKUs excluded from picker and SKU field clears.
- APIs: `POST /api/v1/marketoverviews/options/search`, `POST /api/v1/marketoverviews/options/stores/search`.
- Business rules: brand scope uses Create action; `ResolveRequestedBrands` throws `BrandIDs: You don't have access to the following brand(s): ...` for named brand outside it; omitted = all brands in scope. Create handler keeps only payload rows whose `BrandID` in Create scope; if none remain throws `Market Overview: We're sorry, but we can't create market overviews ...`; rows for other brands dropped silently when at least one valid. Create stamps `BrokerageOrganizationID`, trims `Comment` (empty string when blank), sets audit fields, bulk-inserts. Web sends `dcid: values.dcid ?? null` explicitly (DC optional since CS-1299).
- Gotchas: store options read `CRM.Stores`, while every Market Overview reader resolves `StoreID` against `DataHub.StoreListEntries` (CS-1693); unless ids coincide, store picked here shows no store name in grid, report and exports. Out-of-scope id in option filters returns empty 200. Backend does not validate `RegionID`, `RetailerID`, `BannerID`, `SKUID` exist or belong together; bad id inserted then hidden by readers' INNER JOINs. `onFinish` writes `launchDate` from `values.dateTime` (presentation date), not Launch Date field. `console.log` calls remain in `onFinish`. Legacy cascade hooks `useGetRetailersByRegions`, `useGetBannerByRetailer`, `useStores` imported but never called by `AddOrEditCategoryReview.tsx`.

#### 2.9.1.3 Remove logs [Active]
- Bulk-deletes selected rows after `DeleteComponent` confirmation.
- Business rules: SQL `DELETE ... WHERE ID = ANY(@IDs) AND <MarketOverviewScope.Condition>` with Delete-action brands; message reports zero, one or many. Validator requires non-empty `IDs`; web clears selection and invalidates list on success and on error.

#### 2.9.1.4 Cascading filter panel [Active]
- Filter drawer (`MarketOverviwesReportFilter`, shared with 2.9.2) shows nine facets (Brands, Retailers, Banners, Stores, Regions, DCs, SKUs, Statuses, Created By) plus text, date, launch-date, store-count and yes/no filters. Each facet own query to `POST marketoverviews/filters` with `propertyName`.
- User flow: opening drawer fires nine facet requests (`useGetMarketOverviewsFilterField`), each narrowed by other selections; value that vanishes from its own facet stays selected and shown with ` (not in current results)` (`mergeSelectedOptions`); Reset clears everything, remounts search box and returns to page 1.
- API: `POST /api/v1/marketoverviews/filters` (`RequireModule(null, market-overview, View, CrossBrand)`) → `MarketOverviewFilterOptionsResult` (Brands, Retailers, Banners, Stores, Regions, Dcs, SKUs (JSON `skUs`), Statuses, CreatedBy, each `List<FilterModel { Label, Value }>`).
- Business rules: server self-excludes: each facet's query drops its own field (`PickListExcludeFields`); client must not strip it again. With `PropertyName` set, only that list filled and rest stay empty; unknown name 400 `PropertyName: Unrecognized filter property.` (web logs with `console.error`). `Statuses` labels are enum names (`NotActive`), values integers as strings; web converts back to numbers (`toNumericOptions`). Same range validators as list.
- Gotchas: `useMarketOverviewFacetOptions` in `hooks/market-overview.ts` has no caller.

#### 2.9.1.5 Market Overview CSV export [Active]
- Downloads brokerage's logs as `Market Overview.csv` from grid (and `Market Overviews Report.csv` from 2.9.2) with three scopes: All data (no filters, `pageSize: -1`), Filtered data (filters, `-1`; disabled when nothing filtered), Current page (filters, grid page size and page).
- APIs: `POST /api/v1/marketoverviews/report/export` (`RequireModule(null, market-overview, Export, CrossBrand)`) → CSV stream (`FileExportDTO`, name `Market Overview Report`, columns from `MarketOverviewExportDTO`: Brand, Retailer, Banner, Region, Store, DC, Number of Stores, SKU, SKU Status, Date, Comment (HTML tags stripped by `regexp_replace`), Training, Case Stack, Launch Date, Created By).
- Business rules: scope comes only from `PageSize` (-1 = all); ordering always brand name ASC; `SortingOrder` accepted and ignored.
- Gotchas: "Current page" exports page N in brand-name order while grid's page N is in grid's sort order (default `RegionName`), so file can hold different rows than screen.

#### 2.9.1.6 CRM banner SKU status sync [Active]
- Creating or editing a log copies logged SKU status (and Active date or Discontinued date) into `CRM.BannerSKUs` for (brand, banner, product), creating banner SKU when missing.
- Code map: `SharedDataService.PushMarketOverviewChangesIntoCRM` (create) and `PushMarketOverviewUpdatesIntoCRM` (update) in `SharedDataService.cs`; `SyncMarketOverviewWithCRM` (bulk resync, called by admin data cleanup).
- Business rules: existing banner SKU that is Active or Discontinued never changed. Otherwise status only moves "forward": Approved not overwritten by Commit or Pending, Commit not by Pending, etc.; Active sets `ActiveDate = DateTime`, Discontinued sets `DiscoDate = DateTime`, other statuses clear both dates.
- Gotchas: create path takes brand, banner, status and date from `marketOverviews[0]` only and applies them to every product in batch, so batch spanning several banners or brands updates only first banner (web form always sends one brand and one banner per submit, so only direct API call hits this). Deleting a log never reverts banner SKU.

No web tests found for this page.

### 2.9.4 Distributor APL [Active]
- Broker-maintained authorized product list per distribution center: which UPC a DC carries, under which distributor item code, at which wholesale case and unit cost. Grid joins each row to product (brand, description, category, case pack, size, UOM) by UPC and to DC's region. Brokerage members with broker module `distributor-apl` (View, Create, Update, Delete, Import, Export) see and change only rows whose UPC belongs to a product of a brand in their scope; Brand company refused at policy.
- User flow: Broker opens Strategy > Distributor APL (`/distributor-apl`, gated on `distributor-apl`); dashboard tile "Distributor APL" links here. Grid loads `POST brokers/apl/list` with debounced body built from drawer (`buildDistributorAplFilterRequest`); no column sort (server orders by warehouse). Filter drawer (`DistributorAPLFilter`) shows five facets (Regions, Brands, Categories, UPCs, DCs) and four Min/Max ranges (case pack, size, wholesale case cost, wholesale unit cost) from one `POST brokers/apl/filter-options` call, plus search box; inverted Min/Max withholds list and filter requests with inline message. Toolbar (each gated on `anyBrandCan(distributor-apl, action)`): Remove (Popconfirm, selection), Export (three scopes), Upload (CSV import modal with sample download), Add, Filter. Row action: Edit. Add/Edit modal (`DistributorAPLAddOrEdit`) loads DCs and caller's products from `GET brokers/apl-property-values`, resolves DC id from picked warehouse + region, posts `POST brokers/apl` (with `id` on edit).
- APIs: `POST /api/v1/brokers/apl/list`, `POST /api/v1/brokers/apl/filter-options`, `GET /api/v1/brokers/apl-property-values`, `POST /api/v1/brokers/apl`, `DELETE /api/v1/brokers/apl`, `POST /api/v1/brokers/apl/import`, `POST /api/v1/brokers/apl/export`.
- Business rules: brand reach: `AplBrandScope.GetBrandIdsAsync` = `BrandsInScope(distributor-apl, action)`; every query adds `b."ID" = ANY(@AssignedBrandIds)` through UPC-to-product join. List ordering fixed to `dc."Warehouse" ASC`; `SortingOrder` normalised but unused. Text filters (`Query`, `Warehouse`, `DistributorItemCode`) `ILIKE %value%`; `Query` searches warehouse, item code, UPC, product name, brand and category. No validator rejects inverted ranges here (returns zero rows), which is why web withholds request. No `BrandID` header on any call. A UPC shared by products of several brands produces one row per matching product. Table has no brand or brokerage column, so rows shared across brokerages: broker whose brand owns UPC can edit/delete row another brokerage also relies on.
- Gotchas: `GET apl-property-values` returns every DC system-wide (not scoped); only product list scoped. Policy attributes on `POST apl` and `POST apl/export` say View; real Create/Update/Export/Import checks in handlers (`DemandModuleAsync`), so reading controller alone understates requirement. Distributor APL web code lives in `report.service.ts`/`hooks/reports.ts`, not `apl.service.ts`/`hooks/apl.ts` (those serve brand Retail Reports). `caboodle.backend/docs/Broker-Retail-APL-FE.md` still says scope "brands linked via BrandBrokers"; code uses access context's `distributor-apl` grants (CS-1770).

#### 2.9.4.1 CSV import [Active]
- Uploads CSV (`[*] Warehouse`, `[*] Distributor Item Code`, `[*] Product` (UPC), `[*] Wholesale Case Cost`, `[*] Wholesale Unit Cost`) inserting new (DC, UPC) rows and updating existing ones; failures come back as downloadable CSV.
- User flow: Upload > modal (`UploadComponent` with `showUploadStatus`, so progress and result box render in modal) > optional "sample" download (`POST apl/export` with `isSampleFile: true`, empty CSV with import headers) > upload to `POST brokers/apl/import` > list and filter options invalidated.
- API: `POST /api/v1/brokers/apl/import`, multipart `file` / `FileUploadResponseMetaDTO` (`Success`, `Message`, `File` failed-records CSV "Distributor APL Failed Records", rows `APLFailedRecordDTO` with `[Row = n] message`).
- Business rules (per row, `ImportDistributorAPLRequestHandler`): warehouse required and matched case-insensitively to `CRM.DistributorDcs.Warehouse`; UPC required, leading zeros and hyphens stripped for lookup, must belong to product of brand in Import scope ("Product not found with given UPC"); item code required; costs required, `$` and `,` stripped, must parse and be > 0. Existing (DC, UPC) row updated, otherwise inserted; later duplicate in same file replaces earlier one. Bulk insert and bulk update at end.
- Errors: `Success` false when any row failed; valid rows still saved.
- Gotchas: stored UPC and existing-row match use raw cell text, while scope check uses normalised UPC, so `0012345` and `12345` can create two rows for one product. Handler loads whole `DistributorAPLs` table into memory.

#### 2.9.4.2 Add, edit and remove rows [Active]
- Single-row upsert from modal and bulk soft-delete from toolbar.
- APIs: `POST /api/v1/brokers/apl` (View on attribute; Create (no `ID`) or Update (`ID`) demanded in handler), `DELETE /api/v1/brokers/apl` (`RequireModule(null, distributor-apl, Delete, CrossBrand)`).
- Business rules: upsert validates DC and UPC exist (`GetDistributionCenterAsync`, `GetProductByUPCAsync`) and UPC belongs to brand in scope (404 "Product not found with the given UPC" otherwise); edit of row whose current UPC outside scope 404. Delete soft delete (`Deleted`, `DeletedBy`, `DeletedOn`) limited to rows whose UPC belongs to caller's Delete-scope brands; other ids skipped and message says how many removed.
- Gotchas: no uniqueness check on (DC, UPC) in upsert path; import path only one that de-duplicates.

#### 2.9.4.3 Filter options and CSV export [Active]
- One call returns every facet and range narrowed by other filters; export downloads `Distributor APL.csv` with three scopes (All data = no filters and `pageSize: -1`; Filtered data = filters and `-1`, disabled when nothing filtered; Current page = filters with grid page).
- APIs: `POST /api/v1/brokers/apl/filter-options` (`RequireModule(null, distributor-apl, View, CrossBrand)`) → `AplFilterOptionsResult` (Brands, Categories, DCs, Regions, UPCs: `FilterModel[]`; CasePack, Size, WholesaleCaseCost, WholesaleUnitCost: {Min, Max}). `POST /api/v1/brokers/apl/export` (View on attribute; Export (or Import when `IsSampleFile`) in handler) → CSV (`ExportAPLDTO` columns: Distribution Center Name, Distributor Item Code, Region Name, Unit UPC, Brand Name, Product Description, Category, Case Pack, Size, UOM, Wholesale Case Cost, Wholesale Unit Cost).
- Business rules: facets self-exclude (`PickListExcludeFields`, `RangeExcludeFields`); unknown `PropertyName` 400; `UPCs` facet value is UPC and label product name. Export pins `pageSize: -1` for unpaged scopes (`EXPORT_ALL_ROWS_PAGE_SIZE`); `isSampleFile` must travel in body.
- Errors: export reads JSON error bodies and shows server message (`saveExportResponse` in `DistributorAPLTable.tsx`); export button disabled when `totalCount === 0` or range invalid.

#### 2.9.4.4 Legacy APL filter endpoints [Deprecated]
- Gated to platform-admin `UnusedEndpoints` permission; web `ReportService.getDistributorAPLFilter`/`useGetDistributorAPLFilter` no caller. Six GET endpoints (`apl-filter`, `apl-filter-brand`, `apl-filter-category`, `apl-filter-dc`, `apl-filter-region`, `apl-filter-upc`).
- Gotchas: superseded by `POST apl/filter-options`; candidates for removal together with web dead code and `mockApi.ts` stub.

### 2.9.5 Broker Retail APL ("Brand Retail Item Status") [Active]

Searchable, filterable by brand, retailer, banner, product, category and status, sortable on seven columns, exportable as background CSV job. Display name "Brand Retail Item Status"; every route, module slug, endpoint and code identifier stays `retail-apl`. Used by Brokerage members with broker module `retail-apl` (View, Export); Brand company refused at policy.
- User flow: Broker opens Strategy > Brand Retail Item Status (`/retail-apl`, gated on `retail-apl`) or dashboard tile. Grid loads `POST brokers/retail-apl` with filter body (every key always sent, `[]` when unselected, `buildRetailAplFilterBody`) and paging/sort in query (default `RetailerName` ASC). `SearchField` (placeholder "Search brand retail items") sets `searchKeyword`; drawer `SelectFilterGroup` loads one facet per `POST brokers/retail-apl/filter-options` call with `propertyName` (Brand, Retailer, Banner, Product, Category, Status); `FilterComponent` strips requested facet's own key from body. Headers sort through `SortingOrderTitle` (`BrandName`, `RetailerName`, `BannerName`, `UPCNumber`, `CategoryName`, `ProductName`, `Status`); page size via footer. Export (green, gated on `anyBrandCan(retail-apl, export)`) offers All data/Filtered data/Current page; starts job, polls status every 2500 ms, shows progress in `ExportStatusUI`, offers Cancel, links S3 download when done (2.9.5.1).

- Business rules: brands = `BrandsInScope(retail-apl, View or Export)` intersected with requested `Brands` (empty = all in scope; `Guid.Empty` ignored). No accessible brand returns empty page (and for export `Message: "No accessible Retail APL records to export."` with null `JobId`). `sortKey` empty becomes `RetailerName` in controller; non-empty unknown falls back to `BrandName` (`ValidateSortKey` returns first column); `RetailerName` also sorts by `BannerName` second. `SearchKeyword` (trimmed, `%..%` `ILIKE`) searches product, retailer, banner, UPC, category and brand names. No `BrandID` header sent or read. Rows carry no unique id, so web builds composite display identity and disambiguates repeats with `row-N` keys (`buildRetailAplRowIdentity`, `buildRetailAplRowKeys`); duplicate keys previously left stale rows mounted.
- Gotchas: `caboodle.backend/docs/Broker-Retail-APL-FE.md` still says scope "brands linked via BrandBrokers"; code uses access context's `retail-apl` grants (CS-1770). Module slug `retail-apl` introduced by CS-1770 (commit `bae3ef25`); before that screen borrowed `distributor-apl` (comment in `appNav.helper.ts`).

#### 2.9.5.1 Background CSV export job [Active]
- `export: true` on list body queues Hangfire job writing CSV to S3; client polls status and downloads from signed URL.
- User flow: Pick scope > `POST retail-apl` with `export: true` (All data drops filters, both unpaged scopes send `pageSize: -1`, Current page sends grid page and sort; `buildRetailAplExportBody`, `buildRetailAplExportParams`) > response carries `jobId` and `moduleType: 34` > poll `GET .../status` every 2500 ms > Done shows download link; Done with no URL means zero rows; Cancel posts `.../cancel` then re-polls.
- Data: `DataHub.ExportJobs` row with `BrandID = Guid.Empty`, `ModuleType = RetailAplExport (34)`, `RequestJson` = `RetailAplExportFilterDto` (resolved `BrandIds`, filters, `PageSize` default -1, `CurrentPage`, validated `SortKey`/`SortingOrder`), `Status` Pending > Running > Done/Failed/Cancelled, `TotalRows`, `RowsExported`, `S3Key`, `FileName`, `FileSize`.
- APIs: `GET /api/v1/brokers/retail-apl/export/{jobId}/status`, `POST /api/v1/brokers/retail-apl/export/{jobId}/cancel`.
- Business rules: status and cancel answer 404 for unknown job, deleted job, job of another module type, or another user's job (`ExportJobOwnership.DemandOwnJobAsync`; platform admin exempt). Cancel only changes Pending or Running jobs.
- Errors: any exception marks job Failed with message. Web treats 403 and 404 on status as terminal.
- Gotchas: cancel only flips database status; running job never re-reads it, so keeps exporting and `Complete()` overwrites `Cancelled` with `Done`. Whole CSV built in `MemoryStream` before upload. Web copy for 403 ("limited to whoever started it") never shows because backend answers 404 for someone else's job.

#### 2.9.5.2 Filter options [Active]
