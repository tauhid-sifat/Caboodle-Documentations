# Module 2.13 — File Repository (code-verified)

Source of truth: `docs/feature-context.md` §2.13. Self-sufficient reproduction (condensed to verified facts; full SQL/handler detail in source).

## Purpose
Stores and organizes documents in S3 behind a folder tree. Two separate areas: a brand's Files (brand page `/{brandID}/file-upload`, used by brand company and connected brokerages) and a brokerage's own File Repository (`/file-repository`, no brand). Owns folders, files, chunked uploads, presigned downloads, move/rename/delete, search, opaque share links with public redirect endpoint, and in-app preview.

## Shared data models
- `FileRepository.FileDirectories` (`FileDirectory`): `ID`, `BrandID?`, `Name`, `DirectoryType` (1 Root, 2 Subdirectory; every row created here is 2), `ParentDirectoryId?`, `UserId`, `PrivacyType` (1 Public, 2 Private), audit columns incl. `Deleted`/`DeletedOn`.
- `FileRepository.UserFiles` (`UserFile`): `ID` (also S3 file name), `UserId`, `BrandID?`, `DirectoryId?`, `Name`, `Size` (bytes, long), `Extension`, `Url` (legacy unsigned S3 URL), `Key?` (canonical S3 object key, added by migration `20260916102725_FileShareLinksAndUserFileKeyAdded`), `PrivacyType`.
- `FileRepository.FileShareLinks` (`FileShareLink`): `UserFileID` (no FK), `Token` (unique index `IX_FileShareLinks_Token`), `ExpiresOn?`, `RevokedOn?`, `RevokedBy?`, `AccessCount`, `LastAccessedOn?`.
- Ownership rule (`FileRepositoryArea`): brand rows carry `BrandID = brand` and `UserId = creator`; brokerage rows carry `BrandID = null` and `UserId = brokerage OrganizationId`.

## Shared services
- `FileRepositoryArea` (`Helper/FileRepositoryArea.cs`): resolves area from route (brand route uses active brand, `broker/*` routes use caller's brokerage), privacy rights, ownership checks, S3 prefix (`CaboodleFiles/{brandId}/` or `CaboodleFiles/Broker/{organizationId}/`).
- `IDirectoryService.GetCurrentDirectoryRelativePath` (`DirectoryService.cs`): builds `Parent/Child/` from folder NAMES by walking `ParentDirectoryId`.
- `IFileStorageService` / `AwsS3StorageService`: upload, multipart chunks, copy, move prefix, delete prefix, presigned URLs.
- `IFileUploadGuard` / `FileUploadGuard`, `FileUploadRules`, `FileStorageQuota`, `FileStorageCounter` (`IQuotaCounter`): module-setting limits and storage quota.
- `FileShareLinkRules`, `ShareTokenGenerator`, `UserFileKeyResolver`, `FileContentTypeResolver`.
- Web: `useFilesActions` (gating), `useCopyShareLink`, `explorer.helpers.ts`, `shareLink.helpers.ts`, `copyFileUrl.ts`.

## Cross-module dependencies
- 2.2 Organizations & Access Control: `IAccessContext` (organization, brands, company modules, `files.private` org permission) decides area and privacy.
- 2.2 module catalog and settings: module slug `files` gates every endpoint; Files module settings (`max-upload-size-mb`, `allowed-file-types`, `storage-quota-gb`, `allow-never-expiring-links`, `default-share-link-expiry`, `share-link-max-expiry-days`) via `IModuleSettings`; quota lock via `IQuotaGuard`.

## Feature inventory (summary; full detail in source §2.13)

### 2.13.1 Repository areas and access rules [Active]
- Every handler resolves a `FileRepositoryArea` before touching data. Brand routes act on brand in `BrandID` header; `broker/*` routes act on caller's own brokerage; "shared" read routes (`GET directory`, `directory/tree`, `directory/parent`, `directory/search`) take area from record or request. Used by Brand companies (own brand), brokerages on connected brand route, brokerages on own repository (module slug `files`).
- User flow: web route gate: `/file-upload` maps to slug `files` in `BRAND_ROUTE_MODULES`; `/file-repository` maps to `files` in `BROKER_ROUTE_MODULES` and `BROKER_COMPANY_LEVEL_ROUTES`. Header shortcut "Files" points at `/{brandId}/file-upload` or `/file-repository`. Controls appear only when `useFilesActions` reports action (`can(files, action)` on brand pages, `hasCompanyModule(files, action)` on broker repository); all false while `/me/access` loads. Server: `RequireModule` policy, then `FileRepositoryArea.ResolveAsync`/`ForSharedRequest`/`ForRecord`, then `area.CanSee(record)` on every loaded row (404 when not visible).
- APIs: access rule per endpoint listed under each feature. Policy string format `module:{brandSlug}|{brokerSlug}|{action}|{crossBrand}|{organizationLevel}`.
- Business rules: Brand area: `CanUsePrivate = access.OrganizationId == brandId && files.private` (only brand company itself, never connected brokerage). Brokerage area: refused 403 "This module is not available to your organization." unless caller's org is Brokerage. `ForRecord`: record with `BrandID` visible when caller holds `files` View on that brand; record without `BrandID` only to Brokerage (then `Owns` checks `UserId == organization`). `OrganizationLevel = true` routes check company's own module grant (`HasOrganizationModule`); Brand company checked on own brand. `area.DemandPrivacy(Private)` without right: 403 "You don't have access to the private repository." Invalid `BrandID` header 400 "Invalid BrandID."; foreign brand 403; record outside area returns 404 (not 403).
- Gotchas: shared read routes are `OrganizationLevel = true`, while `GET directory/root` is not. A brokerage on a brand route therefore needs company-level `files` View to open a subfolder (`GET directory`, `tree`, `parent`, `search`) in addition to brand grant that `ForRecord` checks; root listing needs only brand grant.

#### 2.13.1.1 Private repository (Brand company) [Active]
- Second, private tree for brand company. Brand page shows Public/Private tabs only when `isBrandOrg && hasPermission(files.private)`; each tab mounts `FileExplorer` with `privacyType` 1 or 2.
- Business rules: privacy fixed per container: folder's children created with folder's privacy (`GetFileDirectorySpec(id, privacyType)` on create/upload); file cannot move into folder of another privacy (`FileMoveRequestHandler`). Private files cannot be shared (2.13.7). Privacy not part of S3 key, so public and private root folder with same name would share prefix; same-name check spans both privacies (`ChildDirectoriesSpecification` no privacy filter).
- Gotchas: tab `onChange` pushes `/{brandID}/file-upload`, dropping any `directoryID`.

#### 2.13.1.2 Brokerage private repository [Partial]
- Backend supports `PrivacyType = 2` for brokerage area with `files.private`; web broker page always mounts `FileExplorer privacyType={1}` (`file-repository/page.tsx`).
- Business rules: `ForBrokerage` sets `CanUsePrivate = HasOrgPermission(files.private)`.

### 2.13.2 Browsing and navigation [Active]
- Lists root folders and files, folder's direct children, one level of sidebar tree, and breadcrumb path. Used by every user with `files` View in area.
- User flow: no `directoryID` in URL: `GET directory/root` (brand, `BrandID` header) or `GET directory/broker/root`. `?directoryID=` in URL: `GET directory?directoryID=` (both areas) and `GET directory/parent` for breadcrumbs. Sidebar tree (`SubFileTree`) expands lazily: `GET directory/tree?directoryID=` per node (root uses `root`/`broker/root`). Opening folder pushes `{rootPath}?directoryID={id}`; breadcrumbs collapse beyond 3 segments (`collapseBreadcrumbSegments`).
- APIs: `GET /api/v1/directory`, `GET /api/v1/directory/tree`, `GET /api/v1/directory/parent`, `GET /api/v1/directory/root`, `GET /api/v1/directory/broker/root`.
- Business rules: shared routes resolve area from loaded directory (`FileRepositoryArea.CanRead`). Lists ordered by `Name ASC` in SQL; web re-sorts client-side (`buildExplorerRows`, folders always first, sort by name or last modified).
- Gotchas: `sortingOrder` cannot produce DESC: handlers replace any value not equal to `Constants.SORTINGORDER` (`"ASC"`) with `"ASC"`; `GetDirectoryRequest` ignores it entirely. `DirectoryService.ResolveSubdirectories` interpolates parent GUID and sorting order into SQL and returns one level only, despite "tree" name; does not filter `Deleted` (rows hard-deleted, so no practical effect). `GetDirectoryRequest` lists child folders and files without privacy filter; children inherit privacy at creation, so relies on that invariant. DTO `Url` is stored unsigned S3 URL (bucket and tenant path), returned in listings although web never uses it for downloads.

#### 2.13.2.1 List and tile views [Active]
- One antd `Table` (list) or card tiles, both built from same grouped rows (`groupExplorerRows`, `withExplorerSections`), with "Folders"/"Files" section headings and client sorting by name or last modified.
- Code map: `ExplorerTableRow.tsx` (row drag/drop), `FileRowActions.tsx`, `FolderRowActions.tsx`, `DraggableFile.tsx`, `DraggableAndDroppableFolder.tsx`.
- Gotchas: recorded conventions (breadcrumb ellipsis, `.fx-*` CSS, empty-state padding) live in `caboodle.web/CLAUDE.md` and `src/app/globals.css`.

### 2.13.3 Folder management [Active]
- Create, rename, move (drag a folder onto a folder or tree root) and delete folders, in both areas. Requires `files` Create, Update or Delete respectively.
- User flow: "New folder" opens `AddOrEditFolder`; client blocks name already on screen; server re-checks. Rename uses same modal and sends `{directoryID, parentDirectoryID: currentDirectoryID, directioryName}`. Drag folder onto another folder row, tile or tree node, confirm in "Move folder" modal, then `PUT directory` with new `parentDirectoryID` (null for root). Delete from row menu, confirm, `DELETE directory?directoryId=`.
- APIs: `POST /api/v1/directory`, `POST /api/v1/directory/broker`, `PUT /api/v1/directory`, `PUT /api/v1/directory/broker`, `DELETE /api/v1/directory`, `DELETE /api/v1/directory/broker`.
- Business rules: name required (validators). Same-name check exact-case (`x.Name == name`) among destination parent's children, privacy ignored. Rename/move: parent must exist, be visible, have same privacy; moving folder into itself or descendant refused ("A directory can't be moved into itself.", prefix comparison of relative paths). `PUT` always sets `ParentDirectoryId = request.ParentDirectoryID`, so null parent moves folder to root. After S3 move, one SQL `UPDATE` rewrites `Key` of every non-deleted file whose `Key` (or legacy `Url`) contains old prefix (`RewriteFileKeysAsync`). `Url` not updated. Delete: S3 prefix deleted first, then recursive CTE hard-deletes all descendant folders and their files.
- Gotchas: `ProducesResponseType(typeof(DirectoryInfoDTO))` on `POST directory` and `POST directory/broker` wrong; handler returns `ResponseMetaDTO`. S3 listing not paginated (`ListObjectsV2` in `MoveFolderObjectAsync`, `ListObjects` in `GetObjectsWithPrefix`, single `DeleteObjects` call): folders with more than 1000 objects partly moved or partly deleted, while SQL key rewrite or row delete covers every row. Move and delete not transactional across S3 and database. Folder names become S3 path segments; no validation rejects `/` in name. Web rename sends `parentDirectoryID = currentDirectoryID` (`AddOrEditFolder.tsx`); rename started from search results inside another folder may move folder. CS-1795 on master (`f2637cb9`) solves same key-sync problem differently: `MoveFolderObjectAsync` returns `IList<FileUploadResult>` and `DirectoryUpdateRequest` bulk-updates `Key` and `Url` per moved object (`GetFilesByIDsSpec`), with new tests `DirectoryMove/DirectoryUpdateRequestTests.cs`. Working branch rewrites `Key` with one SQL statement and leaves `Url` stale; interface signature conflicts on merge.

#### 2.13.3.1 Folder upload [Active]
- Dropping folder into upload dialog creates whole folder tree in one call, then uploads each file by chunks into created folder IDs.
- User flow: `DraggerFile.onDrop` walks `webkitGetAsEntry` entries (`traverseFileTree`), building `FolderTree` nodes with `meta = {tempId, type}`. `POST directory/tree` (or `broker/tree`) with `currentDirectoryId` = URL `directoryID`. Response echoes `meta`; files mapped to created folder IDs by `parentTempId` and uploaded sequentially (2.13.4.1).
- APIs: `POST /api/v1/directory/tree` (`RequireModule(files, files, Create)` + `BrandIDHeader`), `POST /api/v1/directory/broker/tree` (`RequireModule(null, files, Create, OrganizationLevel)`). Request `DirectoryTreeCreationRequest` {`currentDirectoryID?`, `privacyType`, `name`, `meta`, `subDirectories[]`} / `DirectoryTreeDTO`.
- Business rules: all folders get root's area and privacy; inserted with `IBulkRepository.BulkInsertAsync`.
- Gotchas: no same-name check (unlike `DirectoryCreationRequest`): uploading folder whose name matches existing sibling creates two folders sharing one S3 prefix, and deleting either deletes other's objects. `DraggerFile.tsx` keeps several `console.log` calls.

#### 2.13.3.2 Folder download as zip [Partial]
- Backend only: no web or admin caller of `directory/download` or `directory/broker/download`.
- What it does: downloads every object under folder prefix, rebuilds tree on API server's disk, zips it and streams `application/zip`.
- APIs: `GET /api/v1/directory/download` (`RequireModule(files, files, View)` + `BrandIDHeader`), `GET /api/v1/directory/broker/download` (`RequireModule(null, files, View, OrganizationLevel)`). Query `directoryID` / file stream `{name}.zip`.
- Gotchas: uses fixed working folder `AppDomain.BaseDirectory/FolderDownload` deleted in `finally`, so concurrent downloads interfere; zip read fully into memory; S3 listing capped at 1000 objects; `CreateSubdirectories` interpolates GUID into SQL; any object without matching `UserFiles` row raises null reference reported as 400 "Folder download".

### 2.13.4 File upload [Active]
- Uploads files into current folder of either area. Web always uses chunked multipart route; base64 single-request route also exists.
- User flow: "Upload" opens `DraggerFile` (antd `Dragger`, multiple files); files without `.` in name dropped client-side. Files upload one after another in 6 MB chunks (`chunkSize = 1048576 * 6`); progress per file. On last chunk server completes multipart upload, checks rules and quota, saves row, returns `id`.
- APIs: `POST /api/v1/files/upload/chunk`, `POST /api/v1/files/broker/upload/chunk`, `POST /api/v1/files/upload`, `POST /api/v1/files/broker/upload`.
- Business rules: name = text before first `.`, extension = text after last `.` (`FileExportHelper.ExtractPartFromFileName`). Continued chunk's `key` must start with destination path and end in `{guid}.{ext}` (`IsKeyOf`), else 400 "The upload key doesn't belong to this upload." Chunk route validation runs in handler (request built from query string): negative `fileSize` refused; type checked on every chunk; size and quota checked on chunk 1 when `fileSize` sent; each chunk larger than max file size refused.
- Gotchas: file named `Q1.Report.v2.pdf` stored as name `Q1`, extension `pdf`. ETags travel as comma string `part,etag,part,etag` in query (`prevETags`). "File must have an extension." (validator, not run on chunk route). S3 or chunk errors rethrown as plain `Exception` "Chunk File Upload failed: ..." and reach client as generic 500; abandoned multipart upload never aborted. `FileExplorerService` has no caller of `files/upload` or `files/broker/upload` (single base64 upload Partial).

#### 2.13.4.1 Chunked multipart upload [Active]
- See parent. Client sends `fileSize` only with chunk 1 and stops at first error (`showErrorNotification`, row marked failed).

#### 2.13.4.2 Single base64 upload [Partial]
- Backend only: `FileExplorerService` no caller of `files/upload` or `files/broker/upload`.
- Business rules: size estimated from base64 length before upload (`FileUploadRules.DecodedSize`); real size re-checked in `SaveAsync`.

#### 2.13.4.3 Upload rules and storage quota [Active]
- Applies area organization's Files module settings: allowed file types (`jpeg` aliased to `jpg`), maximum file size in MB, storage quota in GB per area. No-ops until an organization has values ("With no values every file is allowed, as before", `FileUploadRules.cs`).
- Business rules: settings read for `area.OwnerId` (brand or brokerage), so brokers uploading to a brand count against brand's quota. `EnsureAllowedAsync` checks type, size and quota without lock before S3; `SaveAsync` re-checks size and runs insert under `IQuotaGuard.RunAsync` (advisory lock); on refusal S3 object removed. Usage = `SUM(Size)` of non-deleted `UserFiles` where `BrandID = org` or (`BrandID IS NULL AND UserId = org`) (`FileStorageCounter.AreaSql`).
- Errors: "Only these file types can be uploaded: PDF, CSV." (400); "Each file can be up to N MB." (400); quota: `AppLimitReachedException` (409) "There isn't enough storage space left for this file. ..."
- Tests: `FileUploadGuardTests.cs`, `FileUploadRulesTests.cs`, `FileStorageQuotaTests.cs`, `RecordingQuotaGuard.cs`, `FilesSettings.cs`.

### 2.13.5 File operations (download, rename, move, delete) [Active]
- Opens or downloads file through 6-hour presigned URL, renames it (extension locked), moves it between folders by drag and drop, deletes it. Requires `files` View, Update or Delete.
- User flow: click file name: `GET files/download` returns URL, opens preview modal (2.13.8). "Download" in menu fetches same URL and clicks temporary anchor. Rename: modal shows base name; extension re-appended; `PUT files/rename`. Move: drag file onto folder row, tile or tree node; confirm; `PUT files/move` {`directoryID`, `fileId`}. Delete: menu, confirm, `DELETE files/{id}`.
- APIs: `GET /api/v1/files/download`, `GET /api/v1/files/broker/download`, `PUT /api/v1/files/rename`, `PUT /api/v1/files/broker/rename`, `PUT /api/v1/files/move`, `PUT /api/v1/files/broker/move`, `DELETE /api/v1/files/{id:guid}`, `DELETE /api/v1/files/broker/{id:guid}`.
- Business rules: download URL: `attachment` disposition, file name `name.ext`, content type from extension, lifetime 6 hours (`DefaultDownloadUrlLifetime`). Rename refuses changed extension ("You can't update file extension"); S3 key does not change (it is file ID). Move target must exist, be visible, not deleted, and have file's privacy; `DirectoryID = null` moves to root. Delete removes S3 object at path computed from current folder chain, and only then deletes row; `responseValue != 1` gives 400.
- Gotchas: delete hard SQL delete; `UserFiles` rows never become soft-deleted by this module. Delete derives S3 path from folder names rather than stored `Key`; if they diverge (2.13.3 pagination gap), object stays in S3. CS-1795 on master sets `existingFile.Key = fileUploadresult.Key` in `FileMoveRequest`; working branch sets `existingFile.Key = destinationPath` (same value). Web `downloadRow` calls `window.URL.revokeObjectURL` on an https URL (no effect).

### 2.13.6 Search [Active]
- Name search (case-insensitive `ILIKE`, `%` and `_` escaped) over folders and files of current area and privacy, optionally limited to subtree of folder being viewed (CS-1494).
- User flow: search box submits; URL gets `searchString` (and keeps `directoryID`). `GET directory/search?name=&privacyType=&directoryID=` with `BrandID` header on brand pages, none on broker page. Results show "Location" column linking to parent folder ("My Drive" for root).
- API: `GET /api/v1/directory/search` (`RequireModule(files, files, View, OrganizationLevel)`) → `SearchResponseDTO` {`directories: DirectorySummeryDTO[]` (ID, Name, ParentDirectoryID, ParentDirectoryName, dates), `files: FileSummeryDTO[]` (ID, `name.ext`, Size string, Url, DirectoryID, DirectoryName)}.
- Business rules: area from `FileRepositoryArea.ForSharedRequest`: active brand, else Brand company's own brand, else brokerage. With `directoryID`, recursive CTE scoped by same ownership predicate limits results; anchor folder itself excluded from folder results, files directly inside included. Stale or foreign `directoryID` returns 200 with empty lists.
- Errors: empty search text 400 "Search field cannot be empty. Please provide a value."
- Gotchas: `brandID` query parameter bound but unused (web comment in `directory.service.ts` confirms). `FileSummeryModel.Size` is `int` while `UserFile.Size` is `long`. React Query key reuses `QueryKeys.getFilesAndFolders` with different parameters.

### 2.13.7 Share links [Active]
- "Copy URL" mints opaque, revocable token link (`{ApiBaseUrl}/share/{token}`) instead of exposing presigned S3 URL; anyone holding link redirected to 15-minute presigned URL. Requires `files` Export (brand) or company-level `files` Export (brokerage). Public files only.
- User flow: Copy URL in row menu, tile menu, or preview modal (shown only when `canCopyShareLink(privacyType) && canExport`). `POST files/share` (or `files/broker/share`) with `{fileID}` only (no expiry from UI). `response.data.url` to clipboard (`copyFileUrlToClipboard`), toast "Copied".
- APIs: `POST /api/v1/files/share`, `POST /api/v1/files/broker/share`, `DELETE /api/v1/files/share/{token}`, `DELETE /api/v1/files/broker/share/{token}`, `GET /share/{token}` (no `api/v1` prefix).
- Business rules: see sub-features.
- Gotchas: no endpoint lists a file's links. Share links have no FK to `UserFiles` and not removed when file or folder hard-deleted; they resolve to 404.

#### 2.13.7.1 Create share link (Copy URL) [Active]
- Business rules: request without expiry reuses file's active never-expiring link (`GetActiveFileShareLinkSpec`); dated link always new. Web never sends `expiresInDays` (`buildCreateShareLinkRequest` omits invalid values). No success toast from mutation; clipboard helper reports outcome.

#### 2.13.7.2 Revoke share link [Partial]
- Backend and hooks only: `useRevokeShareLink`/`useRevokeBrokerShareLink` in `hooks/directory.ts` no component caller.
- Business rules: caller must be able to see linked file in area (else 404 "Share link not found!"); already revoked link returns 200 "Share link was already revoked."; sets `RevokedOn`, `RevokedBy`.
- Gotchas: web comment on `describeRevokeShareLinkResult` says unknown token answers 200; handler throws 404 for unknown token.

#### 2.13.7.3 Public share resolution [Active]
- Business rules: Unknown, revoked, expired, deleted-file and now-private cases all 404 "This link is no longer available."; each resolve increments `AccessCount` and sets `LastAccessedOn`; disposition `inline` unless `?download=true`; presigned lifetime 15 minutes. Controller outside versioned prefix so links stay valid across API versions.

#### 2.13.7.4 Share link expiry settings [Active]
- Business rules: settings of area organization: `allow-never-expiring-links` (default true), `default-share-link-expiry` ("never" or days), `share-link-max-expiry-days` (default 3650). Requested expiry above maximum: 400; no request and default: `min(default, max)`; no default and never-expiring not allowed: maximum.

### 2.13.8 File preview [Active]
- Clicking a file opens 900px modal with `DocsViewer`: office documents, PDF, CSV and text through Google Docs viewer iframe; images, video and audio rendered directly; anything else "File not viewable". Download button and (when allowed) Copy URL in modal.
- Code map: `DocsViewer.tsx` (also used by `Activities.tsx` and `AddActivityModal.tsx`); modal in `FileExplorer.tsx`.
- Business rules: extension parsed from URL path; doc types `doc docx xls xlsx ppt pptx pdf odt ods odp rtf csv txt`; images `tiff bmp jpg jpeg png gif svg`; video `avi mov mp4 wmv`; audio `ogg mp3 wav`.
- Gotchas: viewer URL built as `https://docs.google.com/viewer?url=` + presigned URL without encoding, so signed query string split across Google's parameters, and presigned URL disclosed to third party. No tests for `DocsViewer`.

### 2.13.9 S3 storage layout and object keys [Active]
- Defines where objects live and how row points at its object. New rows store `Key`; legacy rows only have `Url` and resolved by decoding URL path (`S3KeyHelper.ExtractKeyFromUrl`) until admin backfill (2.15.5) runs.
- Code map: `AwsS3StorageService.cs`, `AwsS3Provider.cs`, `S3KeyHelper.cs`, `UserFileKeyResolver.cs`, `FileContentTypeResolver.cs`.
- Data: key layout `CaboodleFiles/{brandId}/{FolderA}/{FolderB}/{fileId}.{ext}` and `CaboodleFiles/Broker/{organizationId}/...` (`Constants.CABOODLEFILES`, `CABOODLEBROKERFILES`).
- Business rules: `Url` produced by `GetFileUrl(key, client)`: 20-year presign with query string stripped, i.e. unsigned object URL. Presigned download URLs use HTTPS and `ResponseHeaderOverrides` for disposition and content type.
- Gotchas: folder names part of every key, so renaming/moving folder rewrites all keys under it (2.13.3). `LocalFileStorageService` exists but does not implement `IFileStorageService`. Static file middleware in `FileStorage/Startup.cs` serves local `Files` folder, unrelated to S3. `AwsS3Provider` hard-codes `RegionEndpoint.APNortheast1`.
