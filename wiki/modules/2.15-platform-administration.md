# Module 2.15 — Platform Administration (code-verified)

Source of truth: `docs/feature-context.md` §2.15. Self-sufficient reproduction (condensed to verified facts; full SQL/handler detail in source).

## Purpose
Platform-admin operations that keep the system healthy and observable: admin app's landing dashboard, sent-email log with resend, AWS SES delivery events via SNS webhook, nightly soft delete purge, one-off file key backfill, connectivity probes for a client SQL Server database (Bubbies), and two data repair jobs. Callers are platform admins (role permissions checked by `MustHavePermission`), except anonymous SNS webhook.

## Shared data models
- `Email.EmailLoggers` (`EmailLogger`): `Subject`, `Body` (secrets masked with `••••••`), `From`, `TO`, `CC`, `BCC` (comma-joined), `TotalEmailSent`, `ErrorMessage`, `Status` (`EmailSentStatus` 1 Success, 2 Failed, 3 Pending), `ResendCount` (starts at 1). Written by `SmtpMailService` for every email platform sends.
- `Email.SnsEventLogs` (`SnsEventLog`): failed or rejected SNS/SES events: `RawBody`, `ErrorType`, `ErrorMessage`, `SnsMessageId`, `SnsTopicArn`, `SnsType`, `MessageText`, `EmailLoggerId?`.
- `DataLifecycle` schema: `SoftDeletePurgeSettings` (single row), `SoftDeletePurgeSchemaRetentions`, `SoftDeletePurgeTableRegistries`, `SoftDeletePurgeRuns`, `SoftDeletePurgeRunDetails` (FK to runs, cascade delete), `UserFileKeyBackfillRuns` (migrations `20260802062719_SoftDeletePurgeDataLifecycleTables`, `20260916102725_FileShareLinksAndUserFileKeyAdded`).

## Feature inventory (summary; full detail in source §2.15)

### 2.15.1 Admin dashboard [Active]
- Landing screen of admin app ("Overview"): greeting with "Create organization" and "Invite member" actions, four counters (organizations with brand/brokerage split, members, pending access requests, pending invitations), latest 10 audit events, quick links into main admin areas. Used by platform admins.
- User flow: `/` checks server session and redirects to `/dashboard`, or `/login` when no session or session carries `RefreshAccessTokenError`. `(mainApp)/layout.tsx` repeats session check and wraps pages in `AdminLayout`. `AdminOverview` issues `pageSize: 1` list reads and shows `meta.totalCount` (no stats endpoint). Quick links from `QUICK_LINK_HREFS` resolved against `flattenNav` (`navConfig.tsx`).
- APIs: no endpoint of its own. Reads via hooks `useGetOrganizations`, `useGetMembers`, `useGetAccessRequests`, `useGetInvitations`, `useGetAuditEvents` (calling `GET api/v1/organizations`, `api/v1/members`, `api/v1/accessrequests`, `api/v1/invitations`, `api/v1/auditevents`).
- Business rules: event colour by action suffix (`eventTone`: `_failed`/`.locked` danger, removed/deleted/cancelled/rejected/logout warning, created/added/accepted/approved/succeeded/resent/sent success). Today's date renders after mount to avoid hydration mismatch.
- Gotchas: five count queries on every visit, each a full list read with `pageSize: 1`. No tests (admin repo has no test files).

### 2.15.2 Email logs (Sent Emails) [Active]
- Admin screen "Sent Emails" (`/email-loggers`) to search all logged outbound emails, open one with HTML body, resend one or many. Permissions: `Permissions.Admin.EmailLoggers.View` (list, detail, suggestions) and `.Execute` (resend).
- User flow: table loads `POST admin/email-loggers` with `query`, `status`, `pageSize`, `currentPage`, `sortingOrder` (default DESC in UI). Free-text search (to, from, subject, body), status filter, From/To autocompletes feeding same `query`. Row click opens `EmailLogDetailModal` (`GET admin/email-loggers/{id}`), body shown in sandboxed `<iframe srcDoc>`. Resend from row, modal, or "Resend Selected"; success toast shows backend message and list refetches.
- APIs: `POST /api/v1/admin/email-loggers`, `GET /api/v1/admin/email-loggers/{id}`, `GET /api/v1/admin/email-loggers/address-suggestions`, `POST /api/v1/admin/email-loggers/resend`.
- Business rules: search excludes `Deleted` rows; status filter optional; `ILIKE '%query%'` over `TO`, `From`, `Subject`, `Body`; list query does not select `Body`. Resend: empty id list returns 200 "No email IDs provided."; unknown ids 200 "No email logs found with the provided IDs."; otherwise 200 "Resend task has been initiated for N email(s)...". Job per log: body containing masked marker `••••••` not resent (status Failed, "Not resent: this email contained a one-time code or link..."); otherwise status Pending, send via SMTP with configured `From`, headers `X-Caboodle-EmailLogId`, `X-Caboodle-Environment`, `X-SES-CONFIGURATION-SET`; success sets Success, `ResendCount++`, clears error; failure sets Failed with exception message. Original recipients (TO, CC, BCC) reused.
- Gotchas: sort order always oldest first: handler replaces any value other than `Constants.SORTINGORDER` (`"ASC"`) with `"ASC"`, so UI default `DESC` ignored (test `GetQueryDefaultSortingIsAscending` only covers default). `%` and `_` in search text not escaped. Suggestions return whole distinct `TO` strings, which can be comma-joined lists, not single addresses. Admin hook's `onError` comment expects empty-id cases as errors; backend returns them as 200. Resend uses current `MailSettings.From`, not stored `From`.

#### 2.15.2.1 Search and detail [Active]
- See parent: paged search with status and text filters; detail adds `Body`.

#### 2.15.2.2 Address suggestions [Active]
- From/To type-ahead (`SELECT DISTINCT` on `From` or `TO`, `ILIKE`, ordered ascending, no limit); a pick becomes free-text `query`.

#### 2.15.2.3 Resend [Active]
- Single, from-modal or bulk resend, executed asynchronously by `EmailResendJob`.

### 2.15.3 SES/SNS email event webhook [Active]
- Receives SNS notifications carrying SES events and turns bounces, complaints, rejects and rendering failures into `Failed` email logs with reason. Confirms SNS subscriptions automatically. Anonymous.
- User flow: SNS posts JSON to `POST /api/v1/webhooks/sns-email-events`; controller reads raw body. `ProcessSnsEmailEventRequestHandler` parses it (`Amazon.SimpleNotificationService.Util.Message`), validates signature and that `SigningCertURL` host ends with `.amazonaws.com`. `SubscriptionConfirmation`: GET `SubscribeURL`; `UnsubscribeConfirmation`: logged; `Notification`: `SesEmailEventProcessor.ProcessEventAsync`. Processor checks `eventType`, environment header, configuration set, sending account id, then loads `EmailLogger` from header `X-Caboodle-EmailLogId` and applies event.
- APIs: `POST /api/v1/webhooks/sns-email-events` (`AllowAnonymous`) → `ResponseMetaDTO` {message}.
- Business rules: event effects: `Bounce` "Bounce: type/subtype - diagnostic", `Complaint` "Complaint registered by recipient", `Reject` "Rejected by SES: reason", `RenderingFailure` "Rendering failure - Template: ..., Error: ..." all set `Failed`; `Delivery`, `Send`, `DeliveryDelay` only logged. Event for another environment (`X-Caboodle-Environment` mismatch): skipped silently. Configuration set or sending account mismatch, missing log id, unknown log, unknown event type: skipped and recorded in `SnsEventLogs` with `ErrorType` (`ConfigSetMismatch`, `SendingAccountIdMismatch`, `MissingEmailLoggerId`, `EmailLoggerNotFound`, `UnknownSesEventType`, `JsonParseError`, `MissingEventType`).
- Gotchas: `SnsSettings.TopicArn` empty in every appsettings file and never compared with message's `TopicArn`, so any AWS-signed topic accepted and auto-confirmed. Successful delivery never changes status (Success set at SMTP send time). Unparseable body 400 (`InvalidSnsMessage`); bad signature 403 (`BadSignature`); untrusted cert domain 403; unknown SNS type 400; processor exception rethrown (500) after logging `SesProcessingError`, making SNS retry. Envelope failures de-duplicated by `SnsMessageId`. No tests found for webhook, `ProcessSnsEmailEventRequest` or `SesEmailEventProcessor`. Whether AWS SNS subscribed to this URL in each environment cannot be verified from code.

### 2.15.4 Soft delete purge [Partial]
- Status: Partial (backend complete; no admin app screen calls `api/v1/admin/soft-delete-purge`, verified by grep of `caboodle.admin/src`).
- What it does: permanently deletes rows soft-deleted (`Deleted = TRUE`) longer than per-schema retention, across every table with `ID`, `Deleted` and `DeletedOn` columns, in foreign-key-safe order, then emails report. Runs daily via Hangfire when enabled, or on demand. Permissions `View`/`Update`/`Execute` on `SoftDeletePurge` (Admin module).
- User flow: `POST seed` creates settings row (disabled, 02:00 UTC) and syncs schemas/tables from live database. `GET settings` returns settings, schema retentions, tables grouped by schema with on/off flags. `PUT settings` saves schedule, enablement, retention, notification options and table toggles, then re-registers recurring job. Daily job or `POST runs/trigger` executes run; `POST runs`, `GET runs/{runId}`, `POST runs/details` show history.
- APIs: 7 endpoints listed in source §2.15.4 table (settings GET/PUT, runs search, run GET, run details search, seed, trigger).
- Business rules: see sub-features 2.15.4.1-2.15.4.5.
- Gotchas: rows with `Deleted = TRUE` and `DeletedOn IS NULL` purged on first run regardless of retention. New tables found by sync added enabled with default 30-day schema retention, so purged without anyone opting in. Seeder hard-codes `NotificationEmails = "ktt.ornov@asthait.com"`. When run throws after run row created, outer `catch` marks settings `Failed` but leaves run row at `Running`; executor also refuses to start while settings say Running and started less than 24 hours ago (`OverlapGuardHours`). `Hangfire` schema excluded as `"hangfire"` (case-insensitive set) and `public`, `DataLifecycle`, `information_schema`, `pg_catalog`, `pg_toast`, plus table `Email.EmailTemplates`; everything else with three columns eligible, including `FileRepository` and `Email.EmailLoggers`. `Startup.cs` of Admin module declares namespace `Caboodle.Modules.Brands.Application`.

#### 2.15.4.1 Settings and table registry [Partial]
- Business rules: history retention within stored min/max; schema retention within min/max; `applyRetentionToAll` requires `retentionDaysForAll > 0`; tables in `tables`, `includedTables`, `excludedTables` must exist in registry; table in both include and exclude lists 400; `excludedTables` override `includedTables`, which override `tables`. `NotificationEmails` trimmed but not format-validated. `ExcludedTables`/`IncludedTables` always returned empty by `GET settings`.

#### 2.15.4.2 Seed and registry sync [Partial]
- Business rules: idempotent: settings created only when none exist; schema retentions added for new schemas (30 days); registry rows removed for tables no longer eligible and added (enabled, next display order) for new ones. Same sync runs at start of every purge run.

#### 2.15.4.3 Scheduled and manual runs [Feature-flagged]
- Status: Feature-flagged (`SoftDeletePurgeSetting.IsEnabled`, seeded false; executor returns immediately when disabled).
- Business rules: run creates one detail per enabled table (`Pending`), purges each table in manifest order (children before parents; self-referencing tables loop until batch deletes 0 rows), records success or failure per table without stopping, then deletes run history older than `HistoryRetentionDays` (details by cascade) and sets `Completed` or `CompletedWithErrors`. `[DisableConcurrentExecution(86400)]`.

#### 2.15.4.4 Run history [Partial]
- Business rules: run search filters by start date range and status; details search adds schema/table `ILIKE`, detail status, minimum rows; both validate `sortingOrder` as ASC or DESC (default DESC).

#### 2.15.4.5 Purge report email [Partial]
- Business rules: sent when (`!NotifyOnlyOnErrors` or failures > 0) and (`NotifyOnZeroDeletions` or rows deleted > 0 or failures > 0), to parsed `NotificationEmails`; includes failed tables with errors. Missing template throws 404 inside job, after run row already Completed.
- Gotchas: sending code exists; no migration seeding `EmailTemplates` row for module 12 found.

### 2.15.5 File key backfill [Partial]
- Status: Partial (backend only; no admin app screen calls `api/v1/admin/file-key-backfill`; FE guide exists at `caboodle.backend/docs/Admin-File-Key-Backfill-FE.md`).
- What it does: one-off, re-runnable job filling `FileRepository.UserFiles.Key` for rows created before column existed, decoding object key from stored `Url`. Permissions `View`/`Execute` on `UserFileKeyBackfill`.
- User flow: `GET status` shows totals (files, with key, pending) and latest or given run. `POST run` creates `Running` run row and enqueues job; returns run id. Poll `GET status?runID=` for progress (`ProgressPercentage`).
- APIs: `GET /api/v1/admin/file-key-backfill/status`, `POST /api/v1/admin/file-key-backfill/run`.
- Business rules: second trigger refused (400 "A backfill is already running...") while Running run started within 6 hours; older Running runs superseded. Job walks rows with `Key IS NULL` and non-empty `Url` by ID cursor in batches of 2000, updates resolvable keys with one `UPDATE ... FROM unnest(...)`, counts unresolvable rows as skipped, persists progress after each batch, marks Completed or Failed with exception message.
- Gotchas: batch select does not filter `Deleted` while status summary does, so counts can differ. Rows keyed before CS-1795 folder renames may hold stale keys; backfill only touches `Key IS NULL`.

### 2.15.6 Client database (Bubbies) probes [Partial]
- Status: Partial (backend only; no admin or web caller of `admin/bubbies-db/*`).
- What it does: diagnoses access to client-provided SQL Server database configured in `BubbiesDatabaseSettings`. Permission `View` on `ClientDatabase`.
- User flow: `GET bubbies-db/connectivity` opens connection and runs `SELECT TOP 1 1 FROM [dbo].[ForecastData] WITH (NOLOCK)`. `GET bubbies-db/tables` lists all base tables and columns, probes read access per table, and for `dbo.ForecastData` probes write access.
- APIs: `GET /api/v1/admin/bubbies-db/connectivity`, `GET /api/v1/admin/bubbies-db/tables`.
- Business rules: missing config returns `CanRead = false` / `Success = false` with fixed message and logged error; SQL errors returned in body with `[LogID: ...]` reference (always HTTP 200).
- Gotchas: `GET tables` endpoint writes to client database on every call: deletes and re-inserts fixed probe row (`Id 56e9452d-...`, codes `CABOODLE_WRITE_PROBE`) in `dbo.ForecastData` and leaves it there. Connections use `Encrypt = false`, `TrustServerCertificate = true`. `appsettings.Production.json` carries non-empty `BubbiesDatabaseSettings.Password` in repository. No tests for handlers; policy covered in `EndpointAuthorizationCoverageTests.cs`.

#### 2.15.6.1 Connectivity check [Partial]
- Single read probe on `dbo.ForecastData`.

#### 2.15.6.2 Tables report with write probe [Partial]
- Full table and column inventory with read status per table and `ForecastData` write probe (delete outcome reported in `DeleteErrorMessage`, write access decided by insert alone).

### 2.15.7 Data cleanup tools [Partial]
- Status: Partial (backend only; no admin or web caller of `admin/data-cleanup/*`; admin "Brand Data Cleanup" screen is different DataHub feature).
- What it does: two synchronous repair endpoints recompute data across all tenants. Permission `Clean` on `DataCleanup`.
- User flow: admin calls endpoint directly (Swagger or HTTP client); request runs to completion inside HTTP call.
- APIs: `POST /api/v1/admin/data-cleanup/bannersku`, `POST /api/v1/admin/data-cleanup/sync-per-unit-price`.
- Gotchas: both load whole tables into memory with `ListAsync()` and filter in C#. Long-running requests can time out at HTTP layer; no job, no progress record. No handler tests; policy only.

#### 2.15.7.1 Banner SKU sync from Market Overview [Partial]
- Business rules: walks non-deleted Market Overview logs in `LastModifiedOn` order, matches Banner SKU by brand, banner and product, sets status-dependent `ActiveDate`/`DiscoDate` (Active, Approved, Commit, Pending, Discontinued handling in `SyncMarketOverviewWithCRM`).

#### 2.15.7.2 Sync per-unit price of promotional events [Partial]
- Business rules: for each non-deleted Brand Approved and sandbox event, picks latest price list row (by `ValidFrom`) for brand, product and distributor valid at event start; sandbox events get distributor from brand-banner distributor mapping; changed prices bulk-updated. Events with empty distributor or no price skipped.
