# Cross-cutting concerns (code-verified)

Source of truth: `docs/feature-context.md` §3. Self-sufficient reproduction (condensed to verified facts; full detail in source).

## 3.1 Auth and permissions (pipeline only)
Backend request pipeline, in order (`Startup.cs` `UseInfrastructure`, then `MapEndpoints`):
1. `UseRequestLocalization` (+ `LocalizationMiddleware` when `MiddlewareSettings:EnableLocalization`) — default culture `en-US`.
2. `UseStaticFiles`, `UseSecurityHeaders`, `UseFileStorage` (`/Files` from `Files` folder).
3. `ExceptionMiddleware` — maps exceptions to status + error envelope (3.2).
4. `UseRouting`, `UseCors("CorsPolicy")` — any origin, header, method.
5. `UseAuthentication` — JWT bearer (`SecuritySettings:Provider` = `Jwt` in all env files) or Azure AD when `Provider` = `AzureAd`. JWT: symmetric key, issuer/audience not validated, `ClockSkew` zero, `OnChallenge` throws 401 envelope, token read from `?access_token=` only for `/notifications`.
6. `CurrentUserMiddleware` — loads principal; parses `BrandID` header (invalid GUID flagged, not rejected here) and `OrganizationID` header.
7. `UseAuthorization` — policies from `PermissionPolicyProvider`; runs `[MustHavePermission]`, `[RequireOrgPermission]`, `[RequireModule]`. Refusal rendered by `AccessForbiddenResultHandler` as 403 `PermissionDeniedException` under key `Access`, or 400 `ValidatorException` when refusal is a bad request (missing/unparsable `BrandID`).
8. `RequestLoggingMiddleware` (when `MiddlewareSettings:EnableHttpsLogging`).
9. `BrandValidationMiddleware` — for authenticated request with `BrandID` header: invalid GUID writes 400 `Invalid BrandID.`; `ADMIN` passes; otherwise brand must be in legacy role lists (BrandBrokers / Brands.UserID / BrandSubUsers) OR in caller's organization access (`IAccessContext`), else 403 `PermisionDeniedException`.
10. Hangfire dashboard, Swagger UI.
11. `MapControllers().RequireAuthorization()` — every controller action needs authenticated user unless `[AllowAnonymous]`.

Front ends: Web NextAuth session (`app/api/auth/[...nextauth]/options.ts`); token copied into `sessionToken.ts` by `SessionTokenSync` and by `AxiosInterceptor({session})` in layouts. Server layouts call `serverSessionCheck`. No `middleware.ts`. Route gating client side: `AccessRedirectGuard` (no company to `/onboarding`, platform admin to `/use-admin-app`) and `ModuleRouteGuard` (silent redirect to landing route) mounted in `AppContainer.tsx`. Admin: `getServerSession` in `(mainApp)/layout.tsx` redirects to `/` when no session or `RefreshAccessTokenError`; `AuthSessionWatcher` keeps in-memory token and schedules refresh.

## 3.2 Error handling
Backend exception to status mapping (`ExceptionMiddleware.cs`): `AppValidationException`/`BadHttpRequestException` → 400; `AppEntityNotFoundException`/`KeyNotFoundException` → 404; `AppUnauthorizeException`/`UnauthorizedAccessException` → 401; `AppForbiddenException` → 403; `AppConflictException`/`AppLimitReachedException` → 409; `CustomException` subclasses → their `StatusCode`; anything else → 500 generic. `App*` exceptions thrown through `ErrorHelper` (`ThrowValidatorException`, `Throw404Exception`, `Throw401Exception`, `ThrowForbiddenException`, `ThrowAccessDeniedException`, `ThrowConflictException`, `ThrowLimitReachedException`). Envelope (`ErrorDTO.cs`): `{ error: { logID, statusCode, type, messages: { <Key>: <text> } } }`. Default key `Generic`. Model validation: controllers use `AddFluentValidation()` with `InvalidModelStateResponseFactory = ValidationErrorHelper.ValidationResponse`; FluentValidation failures become 400 `ValidatorException` with one message per field, multiple messages joined by `, `. Validators registered per module with `AddValidatorsFromAssembly`. No MediatR pipeline behavior (no `IPipelineBehavior` in solution): validators run at model binding, not inside `Mediator.Send`. `ErrorMessageHelper.ExtractPlainMessage` turns serialized envelope back into plain text.

Web (`caboodle.web`): `AxiosInterceptor.tsx` rejects with `error.response` (not AxiosError), so callers read `error.data.error.messages`. 401 gets one single-flight refresh through `getSession()` and one retry, then `signOut`; 403 never signs out. `apiError.helper.ts`: `readApiError`, `apiMessageEntries`, `firstApiMessage`, `apiMessageFor`, `hasApiMessage`, predicates `isUnauthorized`, `isAccessDenied`, `isOrganizationSelectionRequired`, `isStaleOrganization`, `isNoOrganization`, `isLimitReached`, `isNotFound`, and `readFetchErrorMessage` for raw-fetch exports. `helper.ts` `showErrorNotification`: one toast per message key; 409 limit becomes "Limit reached" warning; no messages gives `GENERIC_ERROR_TEXT`. `notification.helper.ts` `openNotification`: antd notification, `topRight`, top offset `TOAST_TOP` 76, `maxCount` 5, durations success 4s, info 5s, warning 7s, error 10s; title equal to type name replaced by message. `useApiErrorHandler.ts` routes stale company to `/me/access` refetch and "no company" to `/onboarding`.

Admin (`caboodle.admin`): `authErrorInterceptor.ts`: 401 triggers one single-flight refresh via `AuthClientService.triggerRefresh`, then replays; skips `/api/v1/admin/login`, `/api/v1/auth/refresh-token`, `/api/v1/auth/logout`, `/api/auth/*`; terminal failure calls `AuthSessionService.logout`. `helper.ts` `showErrorNotification`, `getForbiddenReason`; `notification.ts` `openNotification`.

## 3.3 Logging
Bootstrap logger: `StaticLogger.EnsureInitialized` writes to Console until configuration loads. Host logger: `builder.Host.UseSerilog(... WriteTo.Console().ReadFrom.Configuration(...))`. Sinks from `Serilog:WriteTo`: Development has `File` (JSON formatter, daily roll under `Logs/`, 5 files kept) and `Seq`; Staging and Production have `Seq` only. Console always added in code. Enrichers: `FromLogContext`, `WithMachineName`, `WithProcessId`, `WithThreadId`, `WithHangfireContext`. Level filters (`Serilog:MinimumLevel`): Default `Information`; overrides `Microsoft` `Error`, `Microsoft.Hosting.Lifetime` `Information`, `System` `Information`, and `Hangfire` `Warning` (Development and Staging only; Production has no Hangfire override). Packages referenced but not configured: `Serilog.Sinks.Elasticsearch`, `Serilog.Sinks.MSSqlServer`, `Serilog.Sinks.Async`. Error logging: `ExceptionMiddleware` and `ValidationErrorHelper` call `LoggerHelper.SaveLog` with user id, `logID` and stack trace; `logID` in response matches log line. Request logging (`RequestLoggingMiddleware`, on in all environments via `MiddlewareSettings:EnableHttpsLogging`): logs user id, path, method, query and headers. Headers `Authorization`, `Proxy-Authorization`, `Cookie` and query keys `access_token`, `token`, `refreshToken`, `code` replaced with `[Redacted]`. JSON body buffered and read, but not written to log (`requestBody` never added to `RequestLogDTO`). `ResponseLoggingMiddleware` exists but registration commented out. Hangfire: `LogJobFilter` logs job creation, start, completion, state changes and failures through Hangfire's `LogProvider`; `UseConsole()` enables Hangfire.Console output. EF Core: `BaseDbContext.OnConfiguring` calls `EnableSensitiveDataLogging()` unconditionally (TODO comment says development only). Email audit: every outbound mail stored in `Email.EmailLoggers`; one-time codes and links masked in stored copy (`SmtpMailService` `MaskSecrets`), and `EmailResendJob` refuses to resend a masked log.

## 3.5 Internationalization
Backend: `JsonStringLocalizerFactory` reads `Localization/{culture}.json` from working directory (`JsonStringLocalizer.cs`); 21 culture files ship in `Hosts/API/Localization`. ## 3.7 Background jobs
Setup (`BackgroundJobs/Startup.cs`): `AddHangfireServer` bound to `HangfireSettings:Server` (queues `default` and `notdefault`, `WorkerCount` 1 in all env files). No job uses `[Queue]`, so everything runs on `default` with one worker per API process. Storage PostgreSQL via `UsePostgreSqlStorage` with `HangfireSettings:Storage:Options`; startup throws if provider or connection string empty. `CaboodleJobActivator` creates DI scope per job and restores current user id from job parameter `QueryStringKeys.UserId` when present. `CaboodleJobFilter` (which would stamp that parameter) commented out of registration, so jobs run without current user unless payload carries one. Global filter `LogJobFilter`; `UseConsole()`. Dashboard at `HangfireSettings:Route` (`/jobs` in all env files) protected by `HangfireCustomBasicAuthenticationFilter` with `HangfireSettings:Credentials`.

Enqueue abstractions: `IJobService` (`IJobService.cs`, `ITransientService`) implemented by `HangfireService` (`HangfireService.cs`): `Enqueue`, `Schedule`, `Delete`, `Requeue` wrappers over `BackgroundJob`. `IBackgroundJobDispatcher` (`IBackgroundJobDispatcher.cs`) implemented by `BackgroundJobDispatcher` (`BackgroundJobDispatcher.cs`): one method, `CreateBannerSkus`, enqueues `ISharedDataService.CreateBannerSkusAsync`; used by `UpsertProductSpecRequest` and `ImportProductsRequest`. `EmailResendJob` (`EmailResendJob.cs`) enqueued by `ResendEmailsRequest` (Admin).

Recurring jobs (complete list): `soft-delete-purge-daily` (cron from `SoftDeletePurgeSetting.ScheduleTimeUtc`, default 02:00; `ISoftDeletePurgeJobExecutor.ExecuteAsync`; registered by `SoftDeletePurgeJobRegistrar` via hosted service `SoftDeletePurgeRecurringJobInitializer`, and again when settings change); `unverified-account-cleanup-daily` (cron `30 2 * * *`; `IUnverifiedAccountCleanupJobExecutor.ExecuteAsync`; registered by `UnverifiedAccountCleanupJobRegistrar` itself an `IHostedService` on `ApplicationStarted`); `store-cleanup-nightly-relink` (cron `StoreCleanup:NightlyRelinkCron` `0 7 * * *`; `IStoreCleanupNightlyRelinkJob.RunAsync` with `[AutomaticRetry(Attempts = 0)]`; registered by `StoreCleanupNightlyRelinkJobRegistrar` via `StoreCleanupNightlyRelinkJobInitializer`; removed when `NightlyRelinkEnabled` false, which it is in all three env files — Feature-flagged, off); `store-cleanup-nightly-scan` (cron `30 7 * * *`; `IStoreCleanupNightlyScanJob.RunAsync`; same registrar; removed when `NightlyScanEnabled` false — off in all env files, Feature-flagged).

Fire-and-forget enqueue call sites (47, all through `IJobService` or `BackgroundJob`), grouped by owning module (owner sections document behavior): Admin (`EmailLoggers/ResendEmailsRequest.cs`, `FileKeyBackfill/TriggerUserFileKeyBackfillRequest.cs`, `SoftDeletePurge/Runs/TriggerSoftDeletePurgeRunRequest.cs`); Broker (CategoryReview BrandReport notify/resend, calendar assign/send, file import, PromoManagement export, RetailApl); CRM (Banners, Region, Retailers upsert); DataHub (brand data cleanup, entity resolution alias, rename propagation, exports, retailer matching backfill, store cleanup, store list issues recheck, merge, store list update/import, duplicate cleanup, entry-id backfill, store matching backfill, sync); DataUpload (DSR import, KeHE/UNFI/SPINS/MonthlyReport chunk uploads); Organization (backfill trigger); ProductSpec (UpsertProductSpec, 2); Shared (`BackgroundJobDispatcher.cs`); TradeSpend (PromosAtAGlance export).

Hosted services (non-Hangfire): `ApplicationLifetimeEventsHostedService` (host), plus the three job registrars above. No `BackgroundService` loops.

## 3.10 API conventions
Routes: controllers derive from `VersionedApiController` with `[Route("api/v{version:apiVersion}/[controller]")]` (`VersionedApiController.cs`); `AddRouting(LowercaseUrls = true)`; API versioning default 1.0, assumed when unspecified, versions reported (`Startup.cs` `AddApiVersioning`). Many controllers override `[Route]` (e.g. `webhooks/sns-email-events`). Handlers invoked through `Mediator.Send` (`BaseApiController.Mediator`). JSON: System.Text.Json camelCase for responses; no `JsonStringEnumConverter`, so enums travel as integers. String enums appear only where DTO declares string fields (web notes `/me/access` payload as exception). Enum numbering: newer enums use spaced values 5/10/15 (e.g. `BrandReportStatusColumnType`, `ImportJobStatus` 5/7/10/15/17/20/25, `ImportOutcome` 5/10/15, `OrganizationBackfillMode` 5/10/15); older enums sequential (`SkuStatus` 1 to 7, `ModuleType` 1 to 35+, `EmailModule` 1 to 15). `ModuleActions` bit flag set (View 1, Create 2, Update 4, Delete 8, Import 16, Export 32). Paging: response `PagedData<T> { data, meta }` with `PagedMeta { totalCount, pageSize, currentPage, totalPage, hasPreviousPage, hasNextPage }`; `Paging` sets `totalPage` to 1 when `pageSize == -1` (all-rows sentinel). Requests carry `pageSize`, `currentPage`, `sortingOrder`, `sortKey` by convention. Write responses: `ResponseMetaDTO { message }`, `ResponseMessageDTO { id, message }`, `ResponseIdsDTO { message, ids }`, `FileUploadResponseMetaDTO { success, message, file }`. Swagger/OpenAPI: NSwag (`AddOpenApiDocument`, `UseOpenApi`, `UseSwaggerUi3`) when `SwaggerSettings:Enable` (true in Development, Staging and Production); bearer security scheme (or OAuth2 PKCE for Azure AD); FluentValidation rules feed schema (`ZymLabs.NSwag.FluentValidation`); `SwaggerHeaderAttribute`/`BrandIdHeaderAttribute` add header parameters. NSwag default paths `/swagger` and `/swagger/v1/swagger.json`. CORS: one policy `CorsPolicy`, `AllowAnyOrigin().AllowAnyHeader().AllowAnyMethod()`; `WithOrigins(...)` and `AllowCredentials()` commented out, so `CorsSettings` origins parsed and ignored. Health: `GET /api/health`, anonymous, no checks registered (always healthy while process answers). Headers: `BrandID` (single-brand routes), `OrganizationID` (selected company), `Authorization`.
